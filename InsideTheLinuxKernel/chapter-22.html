Networking is one of the largest subsystems in the kernel tree: net/ alone holds about 1.3 million lines of C, and the network drivers under drivers/net/ add more than five million more. The rest of this book meets it only at the edges: the NET_RX_SOFTIRQ entry in the softirq table (Chapter 4), the sockfs pseudo filesystem (Chapter 12), Unix-domain sockets (Chapter 19), and, building on this chapter, XDP programs (Chapter 23), io_uring's zero-copy receive (Chapter 24) and network namespaces (Chapter 25). This chapter fills the gap. It follows a packet from the network card to a recvmsg() call and back again from sendmsg() to the wire, and it names the data structures that carry the packet and the operation tables that dispatch it at every layer.

The chapter concentrates on the core packet path, because everything else — tunnels, bridges, wireless, Bluetooth, SCTP, MPTCP, IPsec — is built from the same pieces. Those pieces are the struct socket/struct sock pair and their method tables (§2); the struct sk_buff that holds every packet (§3); struct net_device and its queues (§4); the NAPI receive engine with GRO and receive steering (§5); the IP layer with its FIB lookup and neighbour table (§6); the qdisc layer, Byte Queue Limits and segmentation offload on transmit (§7); TCP and UDP (§8); netfilter and the netlink control plane (§9); and the newer zero-copy data paths built on page_pool, together with the kernel TLS and PSP encryption offloads (§10). Almost all of it is architecture-neutral C. Where x86_64 and ARM64 differ — checksum helpers, DMA coherence, interrupt routing — the text says so.

The Networking Stack in One Picture

The Linux network stack is a pile of layers. Each layer talks to the one below it through an operation table chosen when an object is created: a socket gets a proto_ops and a proto, a route gets input and output functions, and a device gets a net_device_ops. Packets move between the layers inside one container type, struct sk_buff. Understanding the stack is mostly a matter of knowing which table is consulted at each step and which execution context does the work.

The stack also has two halves that are built differently. The data plane moves packets. It runs mostly in softirq context, reads shared tables such as routes, neighbours and socket hashes under RCU without taking locks, and keeps its working state per CPU. The control plane creates and changes the objects the data plane reads — sockets, devices, addresses, routes, filter rules. It runs in process context, is driven from user space mostly through netlink, and is serialized largely by the RTNL mutex (§4.2, §9.4). A configuration change therefore does not stop packets in flight: the writer builds a new object, publishes it with an RCU pointer update, and frees the old one only after a grace period, while readers on other CPUs keep using whichever version they found.

Layers and their interfaces

Four layers do the work, and Table 22-1 lists them with their central objects. At the top, the socket layer (net/socket.c) turns system calls into calls through a per-family struct proto_ops. Below it, the protocol layer — net/ipv4/, net/ipv6/, and the transports inside them — implements TCP, UDP and IP. It reaches the transport through a per-protocol struct proto and the next hop through a routing entry (struct dst_entry). The core device layer (net/core/dev.c) is protocol-agnostic. It receives frames from drivers, steers them to CPUs, hands them to protocol handlers, and on the way out queues them in a queueing discipline (qdisc) before passing them to a driver. At the bottom, device drivers implement struct net_device_ops and move descriptors in and out of hardware rings.

Two rules keep the layers decoupled. First, a lower layer never knows which upper layer will consume a packet. The core layer delivers to whoever registered a packet_type for that EtherType, and IP delivers to whoever registered a net_protocol for that protocol number. Second, a packet is not copied between layers. Each layer moves a few offsets and pointers inside the same sk_buff, adding or stripping its header in place (§3.1). A received TCP segment is normally copied exactly once, from the sk_buff's pages into the user buffer during recvmsg(). The zero-copy paths in §8.2 and §10 remove even that copy.

The dispatch tables are filled by registration, at boot or when a module loads, so the layers meet only through these calls. An address family registers a struct net_proto_family with sock_register() (§2.1). Inside IPv4, proto_register() creates the slab cache for a protocol’s sockets, inet_register_protosw() maps a socket type and protocol number to that protocol’s proto and proto_ops, and inet_add_protocol() installs the handler that IP calls for the protocol number on receive. Below IP, dev_add_pack() registers a packet_type for an EtherType, and devices, qdiscs, congestion-control algorithms and netfilter hooks each have their own register_*() call. A parallel set of offload tables — struct packet_offload registered with dev_add_offload() and struct net_offload with inet_add_offload() — holds each protocol’s GRO and GSO callbacks, so coalescing and segmentation follow the same layering as ordinary receive (§5.3, §7.4). The entries used for almost every packet, the TCP and UDP protocol handlers and the IP, TCP and UDP offload entries, are not separate globals. Since Linux 6.9 they live in net_hotdata (include/net/hotdata.h) together with the hottest tunables such as netdev_budget, so the fast path touches a few adjacent cache lines instead of variables scattered across the kernel image.

Between the drivers and the protocol layer sits a thin link layer. For Ethernet, the driver calls eth_type_trans() (net/ethernet/eth.c) on every received frame. It pulls the 14-byte Ethernet header, classifies the frame in skb->pkt_type as addressed to this host, broadcast, multicast or another host, and returns the EtherType that the driver stores in skb->protocol for dispatch. On transmit, the device’s header_ops build the link-layer header, which the neighbour layer caches per next hop (§6.3). Finally, every object in Table 22-1 belongs to one network namespace, a struct net reached with sock_net() from a socket or dev_net() from a device. Nearly every lookup table is per namespace, which is what lets containers have private interfaces, routes and firewalls (§4.2, Chapter 25).

The life of a packet

Figure 22-1 shows the two directions side by side. On receive, the NIC writes a frame into a buffer the driver posted earlier on its RX ring and raises an interrupt, usually through an MSI-X vector dedicated to that queue (Chapter 4). The driver’s interrupt handler does almost nothing except mask the queue’s interrupt and schedule NAPI. The real work happens in net_rx_action(), the NET_RX_SOFTIRQ handler, which calls the driver’s poll function. If an XDP program is attached, the driver runs it on the raw buffer first. The program can drop the frame, send it back out of the same port, or redirect it to another device, another CPU or an AF_XDP socket before any sk_buff exists (Chapter 23, §10.3). Otherwise the driver wraps the frame in an sk_buff, sets its protocol with eth_type_trans(), and passes it to GRO, which coalesces segments of the same flow. If RPS is configured, the packet may now be queued to another CPU’s backlog and continue there (§5.3). __netif_receive_skb_core() delivers copies to packet taps, runs the tc and netfilter ingress hooks, and hands the packet to ip_rcv(). After the PRE_ROUTING hook, early demux or a route lookup attaches a dst_entry, and the route’s input method sends the packet to ip_local_deliver(). After the LOCAL_IN hook, tcp_v4_rcv() or udp_rcv() looks up the owning socket, appends the packet to its receive queue, and calls sk_data_ready(). Only then does a sleeping reader wake up and copy the data out, in its own process context.

A packet addressed to another host takes a third path that never reaches a socket. Its route’s input method is ip_forward(), which decrements the TTL, checks the packet against the outgoing MTU and runs the FORWARD hook. From ip_output() on it continues like a locally generated packet, through POST_ROUTING, the neighbour layer and the qdisc of the output device. The whole trip runs in the receiving CPU’s NET_RX_SOFTIRQ. A packet that GRO merged on the way in is split again on the way out, by GSO in software or by the output NIC’s TSO (§7.4).

On transmit, the order reverses, and the work starts in the sender's process context. sendmsg() reaches tcp_sendmsg(), which copies (or pins) user data into sk_buffs on the socket's write queue. tcp_write_xmit() then decides how much the congestion and receive windows allow and passes segments to ip_queue_xmit(). The IP layer adds its header, runs the output hooks, and resolves the next hop's link-layer address via the neighbour cache. __dev_queue_xmit() picks a transmit queue and enqueues the packet in that queue’s qdisc, or, when the qdisc is empty and allows it, bypasses the queue and sends the packet at once. Whichever CPU wins the qdisc’s run lock dequeues packets and calls the driver’s ndo_start_xmit(), which posts descriptors on the TX ring and rings the NIC’s doorbell. When the NIC later reports that it has finished sending, the driver reclaims the descriptors in its NAPI poll function, reports the completed bytes to BQL, and frees the buffers with napi_consume_skb(). Freeing the skb releases its charge against the socket’s send buffer, and for TCP that is the event that lets TCP Small Queues release the next burst (§7.3, §8.2). UDP takes a shorter path: udp_sendmsg() normally builds each datagram as one complete skb with ip_make_skb() and sends it at once, without a write queue.

A packet can be dropped at every stage of either path, and each layer counts its losses in a different place. The driver keeps ring and hardware counters (ethtool -S), and the device counters (ip -s link) include the core layer’s rx_dropped. Backlog overflows appear per CPU in /proc/net/softnet_stat (§1.3), qdisc drops in tc -s qdisc, IP, TCP and UDP errors in the MIB counters of /proc/net/snmp and /proc/net/netstat (read with nstat), and per-socket drops in the skmem field of ss -m. Since Linux 5.17, most drop sites also pass an enum skb_drop_reason to kfree_skb_reason(), so the single tracepoint skb:kfree_skb reports both the location and the reason of every drop (§3.4).

Softirqs and process context

Networking was one of the original reasons for softirqs. As Chapter 4 describes, NET_TX_SOFTIRQ and NET_RX_SOFTIRQ are the third- and fourth-highest-priority softirqs. Their handlers are registered at the end of net_dev_init() in net/core/dev.c:

/* net/core/dev.c (net_dev_init, abridged) */
	open_softirq(NET_TX_SOFTIRQ, net_tx_action);
	open_softirq(NET_RX_SOFTIRQ, net_rx_action);

The receive path below the socket runs in softirq context, either on the tail of a hardware interrupt or in ksoftirqd when the softirq load is heavy (Chapter 4). The exception is threaded NAPI (§5.2), which moves the same work into a dedicated kernel thread. Softirq context cannot sleep, so everything on the receive path allocates with GFP_ATOMIC. When a packet reaches a socket that a task is using at that moment, the softirq cannot take the sleeping socket lock. It parks the packet on the socket's backlog instead, and the task processes it when it releases the lock (§2.4).

Transmit normally runs in the context of the task that called sendmsg(), with bottom halves disabled around the device-queue code by rcu_read_lock_bh(). Several kinds of transmission start in softirq context instead. TCP’s retransmission, delayed-ACK and keepalive timers are ordinary timer_list timers that expire in TIMER_SOFTIRQ. Its pacing and compressed-ACK timers are soft hrtimers, which expire in HRTIMER_SOFTIRQ. TCP Small Queues resumes a throttled sender from a BH work item on system_bh_wq, which replaced a per-CPU tasklet in Linux 6.17. Most ACKs are sent from NET_RX_SOFTIRQ in response to received data, and packets that the qdisc layer could not send immediately are rescheduled through NET_TX_SOFTIRQ. When one of these softirq paths finds the socket owned by a task, it cannot wait for the lock. It sets a flag such as TCP_WRITE_TIMER_DEFERRED in sk->sk_tsq_flags, and tcp_release_cb() does the work when the owner releases the socket (§8.2). TCP therefore has to cope with both contexts. The same mix explains why so much of net/ uses _bh lock variants: a lock taken by a sender in process context must keep the receive softirq on the same CPU from re-entering and deadlocking on it.

PREEMPT_RT, which mainline supports on both x86-64 and ARM64 since Linux 6.12, keeps these rules but changes what enforces them. Softirqs run in the task that re-enables bottom halves or in ksoftirqd, and local_bh_disable() becomes a per-CPU lock that leaves the section preemptible. Two tasks can therefore interleave on one CPU inside bottom-half-disabled sections, and per-CPU data that networking used to protect implicitly by disabling bottom halves needed explicit protection. Since Linux 6.11 such data is guarded by local_lock_nested_bh(), which is only a lockdep annotation on non-RT kernels. On RT kernels the transmit recursion counter and the xmit_more flag live in the task (current->net_xmit) instead of in per-CPU data, and on all kernels the XDP redirect state is reached through current->bpf_net_context.

Each CPU keeps its own networking state in a per-CPU struct softnet_data (include/linux/netdevice.h). It holds:

  • poll_list, the NAPI instances waiting to be polled by net_rx_action();
  • backlog, a napi_struct of the CPU’s own whose poll function, process_backlog(), drains input_pkt_queue (filled by RPS from other CPUs and by non-NAPI drivers through netif_rx()) by moving it in bulk to the private process_queue;
  • rps_ipi_list and csd, used to batch the inter-processor interrupts that tell other CPUs their backlogs have work, and flow_limit, the optional per-flow limiter for the backlog;
  • output_queue, the qdiscs waiting for NET_TX_SOFTIRQ, and completion_queue, transmitted sk_buffs that were released with interrupts disabled and wait to be freed there;
  • xmit, the transmit recursion counter and the xmit_more flag on non-RT kernels;
  • statistics: processed, time_squeeze, received_rps and, since Linux 6.18, drop_counters, a pair of drop counters on separate cache lines so that CPUs on two NUMA nodes do not contend for one line when a backlog overflows.

The counters are exported through /proc/net/softnet_stat, one line of 15 hexadecimal columns per online CPU — the first place to look when packets are being dropped before they reach any socket. The first three columns count packets processed, packets dropped because the backlog was full (netdev_max_backlog), and time squeezes: net_rx_action() runs that ended with work left because the 300-packet budget or the two-jiffy time limit ran out, a sign that netdev_budget is too small or the CPU is overloaded. Six zero columns follow for compatibility (they once held fastroute and collision counts). Then come packets received through RPS, packets dropped by the flow limiter, the backlog length, the CPU number and, since Linux 6.4, the lengths of input_pkt_queue and process_queue separately.

Sockets

A socket is the application's handle on a communication endpoint. To user space it is a file descriptor that can be read, written, polled and closed like any other. To the kernel it is two objects with distinct jobs. struct socket is the VFS-facing half, embedded in a sockfs inode. struct sock is the protocol-facing half, which owns the queues, buffers and state. Two operation tables sit between them: proto_ops on the socket side and proto on the sock side.

The two halves also have different lifetimes. struct socket lives exactly as long as its file. struct sock is reference-counted and can outlive the file. A TCP connection, for example, finishes its closing handshake long after the application has called close() (§2.3). The code shared by all protocols is in two files. net/socket.c holds the system calls and sockfs, and net/core/sock.c holds the generic sock code: allocation, socket options, locking, memory accounting and the default wakeup callbacks.

The socket system calls

BSD sockets in Linux have their own system-call family, listed in Table 22-2. Every entry point is defined with SYSCALL_DEFINE in net/socket.c and immediately calls an internal __sys_*() function. The __sys_*() function resolves the descriptor to a struct socket with sock_from_file(), which fails with ENOTSOCK for any other kind of file. It copies a user-supplied address into a kernel struct sockaddr_storage (128 bytes) with move_addr_to_kernel(), runs the LSM hook (for example security_socket_connect()), and calls the matching method in sock->ops. Most calls have a second internal layer that starts from an already-resolved socket or file instead of a descriptor: __sys_bind_socket(), __sys_listen_socket(), __sys_connect_file(), do_accept(), __sys_shutdown_sock() and do_sock_setsockopt(). io_uring calls these functions when it issues socket operations without a system call (Chapter 24). It gained IORING_OP_SOCKET in Linux 5.19 and IORING_OP_BIND and IORING_OP_LISTEN in 6.11, and it issues getsockopt, setsockopt and, since 6.19, getsockname through the socket’s uring_cmd method. Since Linux 6.19 the bind and connect methods receive the address as struct sockaddr_unsized, a type with a flexible sa_data[] array. The old struct sockaddr declares only 14 bytes of address data, which misled the compiler’s bounds checking for longer addresses such as IPv6 and Unix-domain ones. On 32-bit x86 the original multiplexer socketcall() (syscall 102) still exists for old binaries. x86_64 and native ARM64 have only the individual calls. Neither of their 64-bit tables has send or recv: the C library implements them as sendto()/recvfrom() with a null address.

The data-transfer calls all funnel into sock_sendmsg() and sock_recvmsg(). So do read() and write() on a socket descriptor, through the file operations described next. __sys_sendto() shows the pattern. It imports the user buffer into an iov_iter and resolves the file to a socket with sock_from_file(). It copies any destination address into a kernel sockaddr_storage, clears flags such as MSG_SPLICE_PAGES that only kernel callers may set, turns O_NONBLOCK on the file into MSG_DONTWAIT, and calls __sock_sendmsg(). That function runs security_socket_sendmsg() and then the protocol family's method:

/* net/socket.c */
static inline int sock_sendmsg_nosec(struct socket *sock, struct msghdr *msg)
{
	int ret = INDIRECT_CALL_INET(READ_ONCE(sock->ops)->sendmsg, inet6_sendmsg,
				     inet_sendmsg, sock, msg,
				     msg_data_left(msg));
	BUG_ON(ret == -EIOCBQUEUED);

	if (trace_sock_send_length_enabled())
		call_trace_sock_send_length(sock->sk, ret, 0);
	return ret;
}

INDIRECT_CALL_INET() (include/linux/indirect_call_wrapper.h) appears all over the stack. With CONFIG_MITIGATION_RETPOLINE, an indirect call is expensive, so the macro compares the function pointer against the likely targets — here inet6_sendmsg and inet_sendmsg — and makes a direct call when one matches. Without retpolines it collapses to a plain indirect call. You will see the same idiom in the IP, TCP and device layers.

The batching calls exist because the per-call overhead dominates for small datagrams. sendmmsg() sets MSG_BATCH on every message but the last, which lets protocols defer work such as flushing until the end of the batch. It also calls cond_resched() between messages. recvmmsg() loops ___sys_recvmsg() until the vector is full, the timeout expires, or — with MSG_WAITFORONE — the first message has arrived and the socket would otherwise block. The timeout is checked only after each message, so a blocking recvmmsg() can still wait indefinitely for the next one. If an error occurs after some messages were received, the call returns the count and stores the error in sk_err, to be reported by the next call or by SO_ERROR.

sockfs: a socket is a file

Sockets live in sockfs, a pseudo filesystem that is never mounted in the user-visible tree (Chapter 12 describes how such internal mounts work). Figure 22-2 shows the objects. The inode and the struct socket are allocated together as one struct socket_alloc, so SOCKET_I() and SOCK_INODE() convert between them with container_of():

/* include/net/sock.h and net/socket.c (abridged) */
struct socket_alloc {
	struct socket socket;
	struct inode vfs_inode;
};

struct socket *sock_alloc(void)
{
	struct inode *inode;
	struct socket *sock;

	inode = new_inode_pseudo(sock_mnt->mnt_sb);
	if (!inode)
		return NULL;

	sock = SOCKET_I(inode);

	inode->i_ino = get_next_ino();
	inode->i_mode = S_IFSOCK | S_IRWXUGO;
	inode->i_uid = current_fsuid();
	inode->i_gid = current_fsgid();
	inode->i_op = &sockfs_inode_ops;

	return sock;
}

__sock_create() first runs the security_socket_create() LSM hook, then calls sock_alloc() and looks up the address family in the RCU-protected net_families[] array. If the family is not registered, it first tries request_module("net-pf-%d"). It pins the family’s module with try_module_get() and calls the family’s create method. Once create has chosen a proto_ops, the reference moves to the module that owns that table, so a protocol module cannot be unloaded while one of its sockets exists. security_socket_post_create() lets the LSM label the new socket. __sys_socket() finally wraps the result in a file with sock_alloc_file(). That function calls alloc_file_pseudo() with socket_file_ops and stores the socket in file->private_data. The dentry name it creates is what /proc/pid/fd shows as socket:[inode] (sockfs_dname()).

Kernel subsystems create sockets too. NFS, SMB, iSCSI, the SUNRPC layer and tunnel drivers call sock_create_kern(), which passes kern = 1 and an explicit network namespace and never creates a file. They then use the kernel_bind(), kernel_connect(), kernel_sendmsg() and kernel_recvmsg() helpers in place of the system calls. A kernel socket skips the CAP_NET_RAW check and the cgroup BPF sock_create hook, and it does not keep its namespace alive. Since Linux 6.14 it holds only a passive reference that keeps the struct net memory valid but lets the namespace be dismantled. A subsystem whose socket must keep the namespace running calls sk_net_refcnt_upgrade().

socket_file_ops maps the file interface onto socket methods:

  • read_iter and write_iter become sock_recvmsg() and sock_sendmsg();
  • poll becomes sock_poll() and then ops->poll;
  • unlocked_ioctl, sock_ioctl(), handles a few requests itself: bridge and VLAN configuration, timestamp queries, and SIOCGSKNS, which returns a descriptor for the socket’s network namespace to a caller with CAP_NET_ADMIN. Everything else goes to ops->ioctl first, for example SIOCINQ. Interface requests such as SIOCGIFADDR or SIOCSIFMTU that the family does not handle fall through to dev_ioctl(), which is why any socket can configure a network interface;
  • mmap reaches ops->mmap, used by packet rings, TCP receive zero-copy and AF_XDP;
  • splice_read, splice_write and splice_eof connect sockets to pipes (Chapter 19);
  • uring_cmd lets io_uring issue socket commands;
  • fasync manages the O_ASYNC list in socket_wq, and show_fdinfo lets a family add lines to /proc/pid/fdinfo;
  • release, sock_close(), drops the last reference and calls ops->release.

Because a socket is a file, the generic machinery applies to it unchanged: descriptor passing over Unix sockets, epoll (Chapter 19), dup(), fork() inheritance and close-on-exec. Chapter 19 covers AF_UNIX sockets in detail. This chapter concentrates on AF_INET and AF_INET6.

struct socket, struct sock, proto_ops and proto

struct socket (include/linux/net.h) is small. It holds a state (SS_UNCONNECTED, SS_CONNECTING, SS_CONNECTED…), the socket type (SOCK_STREAM, SOCK_DGRAM, SOCK_RAW…), back-pointers to the file and the sk, the ops table, and an embedded struct socket_wq. That last structure contains the wait queue that poll() and blocking calls sleep on, together with the O_ASYNC list and flags such as SOCKWQ_ASYNC_NOSPACE. Because the sockfs inode is freed only after an RCU grace period, softirq code may reach the wait queue through the RCU pointer sk->sk_wq even while the socket is being closed. struct sock (include/net/sock.h) is large. It begins with a struct sock_common that holds the addresses, ports, hash linkage, the network namespace and the skc_prot pointer — just enough for the lookup tables to identify a connection. After that come the queues, memory counters, locks, timers, callbacks and dozens of option fields. Protocols extend it by embedding: struct inet_sock begins with a struct sock, struct tcp_sock begins with an inet_connection_sock that begins with an inet_sock, and so on (§8.1). Each struct proto has its own slab cache sized for the full extension.

The two method tables split the work differently, as Table 22-3 shows. struct proto_ops is the interface between the generic socket layer and an address family. Its methods take a struct socket * and mirror the system calls one for one. struct proto is the interface between the family and a transport protocol. Its methods take a struct sock * and include the hooks that the protocol-independent sock code needs: hashing into lookup tables, port allocation, backlog processing and memory pressure. Most inet_stream_ops methods (inet_sendmsg(), inet_recvmsg(), inet_bind()…) are thin wrappers that defer to sk->sk_prot.

Neither table is fixed for the life of a socket. A TCP upper-layer protocol (ULP), attached with setsockopt(TCP_ULP), copies tcp_prot and inet_stream_ops, overrides a few methods, and installs the copies on the live socket. Kernel TLS (§10.4) and ESP-in-TCP encapsulation do this. A BPF sockmap does the same to sk_prot to redirect data between sockets. When an MPTCP listener accepts a peer that does not speak MPTCP, it hands the new socket to plain TCP by switching its ops, and setsockopt(IPV6_ADDRFORM) turns an IPv6 socket that carries only IPv4-mapped traffic into a plain IPv4 one. Because of these switches, the generic code reads both pointers with READ_ONCE(), and the writers use WRITE_ONCE().

Two details are worth noting. The CAP_NET_RAW check uses ns_capable() against the user namespace that owns the network namespace. A process that is root in its own user and network namespaces can therefore open raw sockets there (Chapter 25). And sock_init_data() links the two halves. It initializes the queues, sets sk_rcvbuf/sk_sndbuf from net.core.rmem_default and wmem_default, points sk->sk_wq at the socket's socket_wq, and installs the default callbacks sock_def_readable(), sock_def_write_space(), sock_def_wakeup() and sock_def_error_report(). It also sets defaults that socket options can change later: sk_rcvlowat of 1 byte, no send or receive timeout, and the busy-poll interval from net.core.busy_read (§5.2). The rest of inet_create() hashes a raw socket at once, because its “port” is the protocol number, and calls the protocol’s init method. For TCP this is tcp_v4_init_sock(), which sets up the retransmission and delayed-ACK timers, the initial congestion window and the congestion-control module, and sets the initial buffer sizes from tcp_wmem[1] and tcp_rmem[1]. Last, for user sockets, it runs any cgroup BPF sock_create program, which can reject the socket or set fields such as its mark or bound device.

Closing reverses only part of this work. sock_close() calls ops->release, which for INET is inet_release(), and that calls sk_prot->close(sk, timeout). The timeout is nonzero only when SO_LINGER is set and the process is not exiting. tcp_close() sends a FIN, or a RST if unread data is discarded, and then calls sock_orphan(). That marks the sock SOCK_DEAD and clears sk_socket and sk_wq under sk_callback_lock. The file, inode and struct socket are freed, but the orphaned struct sock stays in the connection table until the closing handshake completes. The number of orphans is limited by net.ipv4.tcp_max_orphans, and a connection that reaches TIME_WAIT is replaced by a much smaller inet_timewait_sock (§8.1).

The sock itself is freed by reference counting. Each hash-table lookup, timer and in-flight operation holds sk_refcnt (sock_hold()/ sock_put()). The last sock_put() calls sk_free(). That function only drops a bias of one from sk_wmem_alloc, so the memory is released when the last transmitted sk_buff charged to the socket has also been freed. Lookups run under RCU in softirq context, and two strategies make that safe. UDP sockets and TCP listeners set SOCK_RCU_FREE and are freed only after a grace period. TCP’s connection sockets are too numerous for that. Their slab cache is SLAB_TYPESAFE_BY_RCU, so an object can be freed and reused for another TCP socket while a reader still holds a pointer to it. __inet_lookup_established() therefore takes a reference with refcount_inc_not_zero(), checks the addresses and ports again, and restarts if they no longer match. The hash chains are “nulls” lists whose end marker names the bucket, so a reader that was moved to another chain by a reused object notices it and starts over.

User space inspects sockets in two ways. The text files /proc/net/tcp, udp and their IPv6 versions list every socket with its inode number, which matches the socket:[inode] link in /proc/pid/fd. They are slow on large systems and show little state. The ss tool uses the NETLINK_SOCK_DIAG netlink family instead (§9.4). Each family registers a handler with sock_diag_register(), and inet_diag dumps TCP, UDP and raw sockets, filtering them in the kernel by state, address or port and attaching TCP internals such as tcp_info, congestion-control state and memory use. With CONFIG_INET_DIAG_DESTROY, a process with CAP_NET_ADMIN can also close a socket through SOCK_DESTROY (ss -K). BPF socket iterators offer a third, programmable way to walk the same tables.

Socket locking, memory accounting and wakeups

A socket is touched from two directions at once: by tasks making system calls and by the receive softirq delivering packets. socket_lock_t sk_lock handles both with a hybrid design. It contains a spinlock (slock), an owned flag and a wait queue. Process context calls lock_sock(), which takes the spinlock with bottom halves disabled. If another task owns the socket, it sleeps on the wait queue. Otherwise it sets owned = 1 and drops the spinlock. The task now owns the socket like a mutex and may sleep — to copy from user space or to wait for memory — while still holding it. Softirq code calls bh_lock_sock(), which takes only the spinlock, and then tests sock_owned_by_user(). If a task owns the socket, the softirq must not touch the protocol state. It appends the packet to sk->sk_backlog with sk_add_backlog() instead and returns.

The deferred work happens when the owner lets go. release_sock() notices a non-empty backlog and drains it through sk_backlog_rcv — for TCP, tcp_v4_do_rcv(), the same function the softirq would have called:

/* net/core/sock.c */
void __release_sock(struct sock *sk)
	__releases(&sk->sk_lock.slock)
	__acquires(&sk->sk_lock.slock)
{
	struct sk_buff *skb, *next;
	int nb = 0;

	while ((skb = sk->sk_backlog.head) != NULL) {
		sk->sk_backlog.head = sk->sk_backlog.tail = NULL;

		spin_unlock_bh(&sk->sk_lock.slock);

		while (1) {
			next = skb->next;
			prefetch(next);
			DEBUG_NET_WARN_ON_ONCE(skb_dst_is_noref(skb));
			skb_mark_not_on_list(skb);
			sk_backlog_rcv(sk, skb);

			skb = next;
			if (!skb)
				break;

			if (!(++nb & 15))
				cond_resched();
		}

		spin_lock_bh(&sk->sk_lock.slock);
	}

	/*
	 * Doing the zeroing here guarantee we can not loop forever
	 * while a wild producer attempts to flood us.
	 */
	sk->sk_backlog.len = 0;
}

void release_sock(struct sock *sk)
{
	spin_lock_bh(&sk->sk_lock.slock);
	if (sk->sk_backlog.tail)
		__release_sock(sk);

	if (sk->sk_prot->release_cb)
		INDIRECT_CALL_INET_1(sk->sk_prot->release_cb,
				     tcp_release_cb, sk);

	sock_release_ownership(sk);
	if (waitqueue_active(&sk->sk_lock.wq))
		wake_up(&sk->sk_lock.wq);
	spin_unlock_bh(&sk->sk_lock.slock);
}

This is why TCP processes some incoming segments in process context, inside a sendmsg() or recvmsg() call, rather than in the softirq. The release_cb hook serves a similar purpose for timers. When a TCP timer or the TSQ handler fires while the socket is owned, it sets a deferred-work flag, and tcp_release_cb() performs the work at release time (§8.2). The backlog is bounded: sk_add_backlog() refuses a packet when sk_backlog.len plus sk_rmem_alloc exceeds a limit chosen by the caller. tcp_add_backlog() first tries to merge the segment into the last backlogged one. Its limit is twice sk_rcvbuf, plus half of sk_sndbuf because the backlog also carries ACKs that will free send-buffer space, plus 64 KB of headroom. TCP counts a refused packet as TCPBacklogDrop. For short critical sections that cannot sleep, lock_sock_fast() keeps the spinlock held and takes full ownership only when it must.

Memory is accounted at three levels:

  • Per socket, sk_rmem_alloc and sk_wmem_alloc sum the truesize of the sk_buffs charged to the receive and transmit sides. truesize covers the whole allocation, metadata included, not just the payload. These sums are checked against sk_rcvbuf and sk_sndbuf. skb_set_owner_r() charges a received buffer and sets its destructor to sock_rfree(). skb_set_owner_w() does the same for transmit with sock_wfree(), which also wakes writers when space frees up. sk_wmem_alloc counts only data that has left the socket and is not yet freed. Stream protocols limit their unsent and unacknowledged data separately, with sk_wmem_queued (§8.2).
  • Per protocol, sk_forward_alloc is a per-socket reservation drawn from the protocol-wide memory_allocated counter in page units. __sk_mem_schedule() raises the reservation and compares the global total against the three-value sysctl_mem array — net.ipv4.tcp_mem for TCP. Above the middle value the protocol enters memory pressure and shrinks buffers, and it leaves pressure only when the total falls below the first value. Above the top value allocations fail. Even under pressure, a socket whose buffers are below tcp_rmem[0] or tcp_wmem[0] may still grow, so that every connection can make progress. The global counter would be a contended cache line, so since Linux 6.0 each CPU batches its changes in a per-CPU reserve (per_cpu_fw_alloc) and updates memory_allocated only when the reserve exceeds net.core.mem_pcpu_rsv (1 MB by default, tunable since 6.9). The current totals, in pages, appear as mem in /proc/net/sockstat.
  • Per cgroup, the same charge goes to the socket's memory cgroup (sk_memcg, mem_cgroup_sk_charge()), so network buffers count against a container's memory limit and appear as sock in memory.stat. A memory cgroup under reclaim pressure puts its sockets under memory pressure too. Because a container’s sockets are already limited by its cgroup, Linux 6.19 added net.core.bypass_prot_mem (and an equivalent per-socket BPF option): a socket created while it is set skips the global protocol counters and is limited by its memory cgroup alone.

TCP sizes sk_rcvbuf automatically between the bounds in tcp_rmem unless the application locks it with SO_RCVBUF. The kernel doubles the value given to SO_RCVBUF or SO_SNDBUF to allow for sk_buff overhead, after capping it at net.core.rmem_max or wmem_max, and getsockopt() reports the doubled value. SO_RCVBUFFORCE and SO_SNDBUFFORCE ignore the cap but require CAP_NET_ADMIN.

Wakeups go through callbacks rather than direct wait-queue calls, so that kernel users of sockets (NFS, iSCSI, BPF sockmap, kTLS) can intercept them. Such a user replaces the function pointers, and usually stores its own context in sk_user_data, while holding sk_callback_lock for writing. There are four callbacks. sk_data_ready reports new data, sk_write_space reports freed send-buffer space, sk_state_change reports state changes such as a connection being established or closed, and sk_error_report reports a new error in sk_err. When data is queued, the protocol calls sk->sk_data_ready(sk). The default sock_def_readable() wakes sleepers on sk_wq with EPOLLIN and sends SIGIO to O_ASYNC owners:

/* net/core/sock.c */
void sock_def_readable(struct sock *sk)
{
	struct socket_wq *wq;

	trace_sk_data_ready(sk);

	rcu_read_lock();
	wq = rcu_dereference(sk->sk_wq);
	if (skwq_has_sleeper(wq))
		wake_up_interruptible_sync_poll(&wq->wait, EPOLLIN | EPOLLPRI |
						EPOLLRDNORM | EPOLLRDBAND);
	sk_wake_async_rcu(sk, SOCK_WAKE_WAITD, POLL_IN);
	rcu_read_unlock();
}

The skwq_has_sleeper() test contains a memory barrier that pairs with the one in sock_poll_wait(). Without it, a reader could check the queue, find it empty, and go to sleep just after the softirq had looked for sleepers and found none. A blocked recvmsg() waits in sk_wait_data(); a blocked TCP sendmsg() waits in sk_stream_wait_memory(). Both drop the socket lock while sleeping and take it back afterwards. A reader is woken only when at least sk_rcvlowat bytes are available (SO_RCVLOWAT). The default sock_def_write_space() wakes a writer only when less than half of sk_sndbuf is in use, so that it can make real progress. TCP replaces it with sk_stream_write_space(), which applies the same idea to sk_wmem_queued. SO_RCVTIMEO and SO_SNDTIMEO bound the sleeps, and a timeout surfaces as EAGAIN.

The Socket Buffer: struct sk_buff

Every packet in the stack, in either direction, is described by a struct sk_buff (include/linux/skbuff.h), universally called an skb. The structure is a descriptor, not the packet itself. It points into a separately allocated data buffer and possibly to a list of page fragments. It also carries the metadata that the layers attach on the way: the device, the owning socket, the route, offsets of each protocol header, checksum state, timestamps, a hash and a 48-byte scratch area. The design aims to let each layer add or strip headers in place and to share data between clones without copying.

The descriptor takes a little under four 64-byte cache lines on a typical 64-bit build, and its layout follows from how it is used. The first word is a union of list linkages, because an skb sits on at most one list at a time. next and prev link it into a struct sk_buff_head queue; rbnode places it in a red-black tree, as TCP's retransmit and out-of-order queues (§8.2, §8.3), netem and IPv4 reassembly do; and ll_node puts it on a lock-free llist, such as the deferred-free lists (§3.4). A struct sk_buff_head starts with the same two pointers, so the head and its buffers form one circular list, and adds a length (qlen) and a spinlock. skb_queue_tail() and skb_dequeue() take that spinlock. The __skb_queue_tail() family leaves locking to callers that already hold a lock, such as the socket lock. Most per-packet metadata sits in a struct_group named headers, which __copy_skb_header() copies with one memcpy() when an skb is cloned or copied. The fields that describe the buffer itself (tail, end, head, data, truesize and users) come last, because a new descriptor is cleared only up to tail.

State that few packets need is kept out of the descriptor. An skb extension (struct skb_ext, CONFIG_SKB_EXTENSIONS) is a separately allocated, reference-counted block with one area per extension type: the IPsec security path, bridge-netfilter state, the TC state that lets software classification resume where a hardware offload stopped, MPTCP option data, MCTP flow state, PSP state (Linux 6.18) and, since 7.0, CAN metadata that used to be kept in the headroom. active_extensions is a bitmap of the types present. Clones share the block, and skb_ext_add() copies it first if it is shared.

Head, data, tail and end

The linear part of a packet lives in one contiguous buffer, described by four fields. head is the start of the allocation and end its usable end. data and tail bracket the bytes that currently belong to the packet. The gap between head and data is the headroom, into which lower layers will push their headers. The gap between tail and end is the tailroom. Immediately after end sits a struct skb_shared_info. It describes the paged part of the packet, and skb_shinfo(skb) finds it from end. On 64-bit kernels, tail and end are stored as offsets from head (sk_buff_data_t is an unsigned int), which saves space. The header positions mac_header, network_header and transport_header are 16-bit offsets from head as well. Figure 22-3 shows the arrangement for a received TCP segment.

Four primitives move these pointers. None of them copies any data:

/* net/core/skbuff.c and include/linux/skbuff.h (abridged) */
void *skb_put(struct sk_buff *skb, unsigned int len)
{
	void *tmp = skb_tail_pointer(skb);
	SKB_LINEAR_ASSERT(skb);
	skb->tail += len;
	skb->len  += len;
	if (unlikely(skb->tail > skb->end))
		skb_over_panic(skb, len, __builtin_return_address(0));
	return tmp;
}

void *skb_push(struct sk_buff *skb, unsigned int len)
{
	skb->data -= len;
	skb->len  += len;
	if (unlikely(skb->data < skb->head))
		skb_under_panic(skb, len, __builtin_return_address(0));
	return skb->data;
}

static inline void skb_reserve(struct sk_buff *skb, int len)
{
	skb->data += len;
	skb->tail += len;
}

skb_reserve() is called once on a fresh, empty buffer to create headroom. skb_put() appends data at the tail and returns where to write it. On transmit, each layer calls skb_push() to prepend its header: TCP builds its header first, then IP pushes 20 bytes in front of it, then the neighbour code pushes the 14-byte Ethernet header. On receive, the inverse skb_pull() advances data past a header once the layer has consumed it. The header offsets remain valid, so ip_hdr(skb) still works in TCP. Running out of headroom on skb_push() is a kernel bug, not an error return. Code that cannot guarantee headroom calls skb_cow_head() or skb_expand_head() first, as ip_finish_output2() does (§6.3). TCP avoids the problem by allocating every segment with MAX_TCP_HEADER bytes of headroom — enough for TCP, IP and a link-layer header plus tunnel encapsulations.

len is the total packet length from data. data_len is the part held outside the linear buffer. skb_headlen(), the difference, is how many bytes may be dereferenced directly at data. Protocol handlers must not assume that a header is linear. Before reading one they call pskb_may_pull(skb, n), which, if fewer than n bytes are linear, copies enough bytes from the fragments into the head (__pskb_pull_tail()). ip_rcv_core() does this for the IP header and tcp_v4_rcv() for the TCP header.

__pskb_pull_tail() may have to reallocate the head when it is cloned or too short. A pointer into the packet taken before pskb_may_pull() is therefore stale after it, which is why handlers reload iph = ip_hdr(skb) after each pull. Code that only reads a header, such as netfilter matches and the flow dissector, calls skb_header_pointer() instead. It returns a pointer into the linear data when the bytes are there and otherwise copies them into a caller-supplied buffer on the stack (skb_copy_bits()), leaving the skb untouched. skb_linearize() pulls the whole packet into the head, for the rare code that cannot handle fragments at all.

truesize is what the packet costs in memory, not how long it is: the descriptor, the whole head allocation including skb_shared_info, and the full size of every fragment buffer. SKB_TRUESIZE(X) gives the value for an X-byte head. Socket accounting charges truesize (§2.4), so a 100-byte datagram that a driver received into a 2 KB buffer charges more than 2 KB against sk_rcvbuf. Small packets therefore fill receive buffers far faster than their length suggests. This is why TCP coalesces adjacent segments and, under memory pressure, collapses its queues into compact skbs (§8.3).

Paged data, clones and sharing

Large packets rarely fit in one linear buffer, and copying payload into one would defeat zero-copy. struct skb_shared_info therefore holds an array of up to MAX_SKB_FRAGS page fragments (CONFIG_MAX_SKB_FRAGS, default 17). Since Linux 6.4 the limit can be raised to 45, so that zero-copy BIG TCP packets built from 4 KB pages can carry more data. Each skb_frag_t is a netmem reference with an offset and length. netmem_ref is usually a struct page pointer but may name device memory (§10.1). When pp_recycle is set, the fragments came from a page_pool and go back to the pool, not to the page allocator, when the skb is freed (§10.1). unreadable marks an skb with device-memory fragments that the CPU cannot access (§10.2). Drivers attach receive buffers with skb_add_rx_frag(). TCP appends user data to fragments on transmit, and sendfile()/ splice() attach page-cache pages directly. A second level of non-linearity, frag_list, chains whole sk_buffs. IP reassembly and some GRO and UDP-GSO paths use it. The rest of skb_shared_info holds:

  • segmentation-offload state: gso_size, gso_segs and gso_type (§7.4);
  • timestamping state: the transmit timestamp request (tx_flags, tskey) and a hardware timestamp (hwtstamps), described in §3.3;
  • flags, such as SKBFL_SHARED_FRAG. That flag marks fragments that their owner can still change, for example pages spliced from a file. A transmit checksum over such fragments must be computed on a private copy;
  • destructor_arg, which points to the ubuf_info tracking MSG_ZEROCOPY pages (§8.3). For multi-buffer XDP the same space holds the fragment sizes (xdp_frags_size);
  • meta_len, the size of XDP metadata stored just before the packet in the headroom;
  • dataref.

Two reference counts let several holders share one packet:

  • skb->users counts references to the descriptor itself. skb_get() takes one, and skb_shared() reports more than one. A shared skb must not be modified at all; skb_share_check() clones it if necessary.
  • skb_shinfo(skb)->dataref counts descriptors that point at the same data buffer. skb_clone() allocates a new sk_buff that points to the same head and frags, increments dataref, and marks both copies cloned. Clones are cheap and are how AF_PACKET taps receive a packet without copying it, and how TCP keeps the original segment for retransmission while handing a clone to IP.

Because clone data is shared, a layer that needs to modify packet bytes must first check skb_cloned() (cloned and dataref not 1). It then calls skb_cow() or pskb_expand_head() to get a private copy of the head. skb_copy() copies everything; pskb_copy() copies only the linear part and shares the fragments. The upper 16 bits of dataref count payload-only references (SKB_DATAREF_SHIFT). TCP marks each segment it keeps for retransmission as payload-only with __skb_header_release(), which sets nohdr and promises never to touch the headroom. The single clone it sends down the stack can then push IP and link-layer headers into the shared headroom without a copy. skb_header_cloned() subtracts the payload-only references and finds the clone the only user of the headers, and hdr_len records how much of the headroom the clone may write.

TCP's clone-per-transmission habit is common enough to justify a special allocator. A fast clone is allocated from skbuff_fclone_cache as a struct sk_buff_fclones: two sk_buffs and a shared fclone_ref. When skb_clone() is called on the first, it returns the pre-allocated second instead of going to the slab. tcp_stream_alloc_skb() allocates every TCP send buffer this way.

A packet that changes hands must also leave its old owner. skb_orphan() calls the destructor, which uncharges the sending socket, and clears skb->sk. The loopback driver does this before handing a transmitted packet to the receive path, so that the receiving socket can charge it instead. When a packet is passed to another device's receive path, as a veth pair does, skb_scrub_packet() drops the route, the conntrack entry and the extensions and resets pkt_type and skb_iif. If the packet also moves to another network namespace, the function clears mark and the timestamp as well. skb_orphan_frags() is the counterpart for the payload. If the frags belong to a user zero-copy buffer, it copies them into kernel pages and releases the user's buffer. This is done before the skb is queued somewhere it might stay indefinitely, so the sender's completion is not held up.

Header offsets and checksum offload

Each layer records where its header starts. The driver or eth_type_trans() sets mac_header. __netif_receive_skb_core() resets network_header (and transport_header, if nothing has set it yet) as it hands the packet up, and the IP layer moves transport_header past the IP options. On transmit, each layer sets its offset after pushing its header (skb_reset_network_header(), skb_reset_transport_header()). skb->protocol holds the EtherType in network byte order and drives protocol dispatch (§5.4). The cb[48] control buffer is private scratch space for whichever layer currently owns the skb. TCP keeps its per-segment state there as struct tcp_skb_cb (TCP_SKB_CB(skb)): sequence numbers, flags and SACK state. IP keeps struct inet_skb_parm there (IPCB(skb)).

Timestamps are kept in two places. On receive, net_timestamp_check() fills skb->tstamp from ktime_get_real() when the packet enters the stack, but only while some socket has asked for timestamps (SO_TIMESTAMP, SO_TIMESTAMPING). Otherwise a static key (netstamp_needed_key) keeps the clock read off the fast path. A NIC that timestamps in hardware stores the value in skb_hwtstamps(skb), in skb_shared_info. On transmit, sock_tx_timestamp() copies the socket's SO_TIMESTAMPING flags into tx_flags and sets an identifying key in tskey; for TCP the key is the sequence number of the last byte of the write. At each requested point __skb_tstamp_tx() queues a notification carrying the timestamp on the socket's error queue, and the application reads it with recvmsg(MSG_ERRQUEUE). The points are:

  • entering the qdisc layer (SCM_TSTAMP_SCHED);
  • being handed to the driver, or stamped by the NIC (SCM_TSTAMP_SND);
  • transmit completion (SCM_TSTAMP_COMPLETION, Linux 6.15);
  • for TCP, acknowledgment by the peer (SCM_TSTAMP_ACK).

Since Linux 6.15 a BPF program can request the same timestamps (SKBTX_BPF) without involving the application.

CHECKSUM_COMPLETE is the most general receive offload because it needs no protocol knowledge in hardware. The stack keeps skb->csum correct as it pulls headers (skb_postpull_rcsum()). Protocols consume this state through a few helpers. tcp_v4_rcv() calls skb_checksum_init(). If the device verified the checksum, or CHECKSUM_COMPLETE plus the pseudo-header sums to zero, the segment is accepted at no cost. Otherwise the pseudo-header sum is left in skb->csum. The full sum is computed later (tcp_checksum_complete()), once TCP has found the socket and decided to process the segment. Packets of 76 bytes or less (CHECKSUM_BREAK) are summed immediately. UDP goes further. When an application reads a whole datagram, UDP verifies the checksum while copying it to user space (skb_copy_and_csum_datagram_msg()), so the data is read only once. csum_valid records that software has verified the checksum. GRE and UDP tunnel sockets then call skb_checksum_try_convert() to turn the packet into CHECKSUM_COMPLETE, so that the inner packet can be verified cheaply too.

Tunnels and non-IP checksums extend the scheme:

  • A tunnel driver sets encapsulation and the inner_*_header offsets. A device that lists the offloads in hw_enc_features can then checksum and segment the inner TCP packet.
  • The outer UDP checksum is computed in software, but cheaply, by local checksum offload (lco_csum()). Once the inner checksum is filled in, the sum from the inner checksum field to the end of the packet equals the complement of the inner pseudo-header sum. The outer checksum can therefore be computed without reading the payload.
  • SCTP and FCoE use CRC32c instead of the Internet checksum. They reuse CHECKSUM_PARTIAL with NETIF_F_SCTP_CRC or NETIF_F_FCOE_CRC. For SCTP, csum_not_inet tells the driver which algorithm is meant, and skb_crc32c_csum_help() is the software fallback.

Allocating socket buffers

An skb involves two allocations: the struct sk_buff descriptor and the data buffer. Descriptors come from the slab caches skbuff_cache and skbuff_fclone_cache (both reached through net_hotdata, the cache-line-packed structure that holds the stack's hottest global variables). __alloc_skb() obtains the data buffer with kmalloc(), or from the dedicated skb_small_head_cache for small heads, and appends room for skb_shared_info. That path suits transmit, where the size is known and the caller can sleep.

Details of __alloc_skb():

  • The small-head cache is sized for MAX_TCP_HEADER or a GRO header, whichever is larger. Its size is deliberately not a power of two, so a head from it can be recognized by its size alone.
  • kmalloc_size_roundup() may return more than was asked for, and skb_shared_info is placed at the very end of the allocation, so the slack becomes tailroom.
  • Since Linux 6.19 the descriptor comes from the per-CPU NAPI cache described below even in process context, with bottom halves briefly disabled. The exceptions are fast clones and allocations for another NUMA node.
  • Callers that want a large packet without a high-order linear buffer use alloc_skb_with_frags(). sock_alloc_send_pskb(), which Unix-domain and packet sockets use, builds a small head plus page fragments this way. It blocks while the socket's send buffer is full.

Receive has different constraints. It runs in softirq context at millions of packets per second, and the buffer must exist before the packet arrives, because the NIC writes into it by DMA. Drivers therefore take one of two routes:

  • Allocate first, wrap later. The driver posts raw buffers (pages or page fragments) to the RX ring. When a frame lands, it builds an sk_buff around the buffer in place with build_skb() or napi_build_skb(). The buffer must be sized to leave headroom and room for skb_shared_info at the end. Alternatively, the driver allocates a small skb and attaches the page as a fragment. Most high-speed drivers do one of these, typically with buffers from a page_pool (§10.1).
  • Allocate and copy. The driver calls napi_alloc_skb() or netdev_alloc_skb() to get an skb with headroom already reserved and copies the frame (or just its headers) into it. Small frames are often handled this way ("copybreak"), because copying 100 bytes is cheaper than tying up a whole receive page.

Both receive allocators use a page fragment cache, the facility that Chapter 8 left to this chapter. A struct page_frag_cache (include/linux/mm_types_task.h, mm/page_frag_cache.c) owns one high-order page and carves consecutive fragments from it. __page_frag_cache_refill() tries a PAGE_FRAG_CACHE_MAX_SIZE (32 KB) compound page with __GFP_NORETRY | __GFP_NOMEMALLOC and falls back to a single page. With 64 KB base pages, which some ARM64 kernels use, the 32 KB attempt is skipped entirely. Instead of touching the page's reference count once per fragment, the cache adds a large bias to _refcount up front and decrements a private pagecnt_bias per fragment. When the page is exhausted it subtracts the remaining bias. If that drops the count to zero — every fragment has already been freed — it reuses the page in place; otherwise it allocates a new one. Each fragment is freed with page_frag_free(), which simply drops one page reference. napi_alloc_skb() shows the whole receive allocation:

/* net/core/skbuff.c (abridged) */
struct sk_buff *napi_alloc_skb(struct napi_struct *napi, unsigned int len)
{
	gfp_t gfp_mask = GFP_ATOMIC | __GFP_NOWARN;
	struct napi_alloc_cache *nc;
	struct sk_buff *skb;

	...

	skb_reserve(skb, NET_SKB_PAD + NET_IP_ALIGN);
	skb->dev = napi->dev;

}

NET_SKB_PAD (at least 32 bytes, or one cache line) is the headroom that lets a later skb_push() succeed without reallocation. NET_IP_ALIGN is the classic 2-byte offset that makes the IP header following a 14-byte Ethernet header 4-byte aligned. Both x86_64 and ARM64 define it as 0 in their asm/processor.h. Their CPUs handle unaligned loads cheaply, and an unaligned DMA start can cost more than the misaligned header. The local_lock_nested_bh() call documents, and on PREEMPT_RT enforces, that the per-CPU cache is protected by disabled bottom halves. __napi_build_skb() takes its descriptor from the per-CPU napi_alloc_cache.skb_cache[] array of NAPI_SKB_CACHE_SIZE (128) descriptors. The array is refilled from the slab 32 at a time with kmem_cache_alloc_bulk(). Freed descriptors return to the array, and when it is full, 32 go back to the slab with kmem_cache_free_bulk().

The pfmemalloc handling serves swapping and block I/O over the network. NFS (when it backs a swap file), NBD, NVMe/TCP, iSCSI and WireGuard mark their sockets SOCK_MEMALLOC (sk_set_memalloc()). While such sockets exist, receive allocations may dip into the emergency reserves (__GFP_MEMALLOC), because the packet that completes a page-out may be the one that frees memory. An skb built from reserve memory is marked pfmemalloc, and two checks keep it away from ordinary sockets:

  • __netif_receive_skb_core() delivers it only to ARP, IPv4, IPv6 and VLAN;
  • sk_filter_trim_cap() drops it, counting PFMEMALLOCDROP, unless the receiving socket is SOCK_MEMALLOC.

Freeing has variants:

  • kfree_skb_reason() frees a packet that was dropped and records an enum skb_drop_reason (include/net/dropreason-core.h). The core defines about 130 reasons. mac80211 and Open vSwitch register their own sets with drop_reasons_register_subsys(). The skb:kfree_skb tracepoint records the caller's address and the reason, and since Linux 6.11 the receiving socket, through sk_skb_reason_drop(). Tools such as dropwatch, perf or bpftrace use it to show exactly where packets die. dropwatch talks to drop_monitor (net/core/drop_monitor.c, Linux 2.6.30), which attaches to the tracepoint and to devlink:devlink_trap_report, so packets that a switch ASIC or NIC drops in hardware are reported too, over its NET_DM generic netlink family, either as per-location counts or as whole packets. Plain kfree_skb() reports SKB_DROP_REASON_NOT_SPECIFIED, and kfree_skb_list_reason() frees a chain of segments and returns their descriptors to the slab in bulk.
  • consume_skb() frees a packet that was used normally. It fires skb:consume_skb instead, so normal traffic does not appear as drops.
  • napi_consume_skb() is called from drivers' transmit-completion handlers inside NAPI poll. It returns descriptors to the per-CPU cache instead of the slab. Since Linux 6.19 it hands an skb allocated on another CPU to the deferred-free mechanism.

TCP and UDP receive call skb_attempt_defer_free() when a task finishes copying a packet on a different CPU from the one that allocated it (skb->alloc_cpu). The skb is put on a lock-free list that its home CPU empties during its next net_rx_action(), busy-poll loop or threaded-NAPI loop (skb_defer_free_flush()). Memory therefore goes back to the per-CPU caches where it came from, and allocation and free do not bounce slab cache lines between CPUs. Since Linux 6.18 each CPU keeps one list per NUMA node, so freeing CPUs on different nodes do not contend for one list head. The length of each list is capped by net.core.skb_defer_max (default 128); past the cap the skb is freed locally. When a list reaches half the cap, an IPI makes the home CPU raise NET_RX_SOFTIRQ. Skbs that carry zero-copy fragments are never deferred, because their completion notifications must not be delayed.

Network Devices

A network interface — a physical NIC, a loopback, a veth end, a bridge, a VLAN, a tunnel — is a struct net_device. Unlike block and character devices, network interfaces have no device node in /dev. User space names them by interface name or index, reaches them through sockets and netlink, and finds them in /sys/class/net. The structure is large because it serves every kind of interface, but the packet path needs only a few parts of it: an operation table, feature flags that say what the hardware can do, and arrays of RX and TX queues that let one device spread its traffic over many CPUs.

Devices come into existence in three ways. A hardware driver allocates and registers one from its probe routine. That may be a PCI NIC driver's probe(), or, on most ARM64 SoCs, a platform driver for an integrated Ethernet controller matched through the device tree. The driver records the bus device as the parent with SET_NETDEV_DEV(), so the struct device embedded in every net_device (dev->dev, class net) appears beneath its controller in sysfs, for example /sys/devices/pci0000:00/0000:00:1c.0/0000:03:00.0/net/enp3s0, with /sys/class/net/enp3s0 as a symlink to it (Chapter 13). Software devices such as veth, bridge, VLAN, bond, VXLAN and WireGuard are created on demand by ip link add … type kind. Each kind registers a struct rtnl_link_ops with rtnl_link_register(). rtnl_newlink() looks the kind up by name, allocates the device with the kind's priv_size and setup callback, and calls its newlink method, which configures the device and registers it. A few devices are created by the kernel in every network namespace: lo, and fallback tunnel devices such as sit0 and gre0 once their modules are loaded. The net.core.fb_tunnels_only_for_init_net sysctl confines the fallback devices to the initial namespace or suppresses them altogether. Whatever its origin, every device then goes through the same registration, open and teardown sequence (§4.2).

struct net_device and its operations

struct net_device (include/linux/netdevice.h) has well over a hundred members, and its layout is engineered for the packet path. The first members are grouped into cache-line groups such as net_device_read_tx, net_device_read_txrx and net_device_read_rx, marked with __cacheline_group_begin(), so that transmit and receive each touch as few lines as possible. Documentation/networking/net_cachelines/net_device.rst records which path reads each field. The fields this chapter relies on are:

  • identity: name, ifindex, nd_net (the owning network namespace), dev_addr, mtu, type;
  • operations: netdev_ops, ethtool_ops and header_ops (link-layer header construction);
  • state: flags (IFF_UP, IFF_PROMISC…), priv_flags, reg_state, and operstate with the carrier bit set by netif_carrier_on()/netif_carrier_off() (§4.2). Beside priv_flags sits lltx, a bit (Linux 6.12, formerly the NETIF_F_LLTX feature) that marks a device whose ndo_start_xmit needs no TX queue lock (§7.2);
  • capabilities: features, hw_features and wanted_features; the masks that stacked and tunnel devices inherit (vlan_features, hw_enc_features, mpls_features); xdp_features; and the segmentation size limits (gso_max_size, tso_max_size, gro_max_size and their IPv4 counterparts);
  • queues: _tx and num_tx_queues/real_num_tx_queues, _rx and real_num_rx_queues, qdisc (the root qdisc), tx_queue_len, xps_maps;
  • receive hooks: rx_handler (used by bridge, bonding, macvlan, team), ptype_all/ptype_specific (per-device taps and protocol handlers), tcx_ingress/tcx_egress (tc BPF), and nf_hooks_ingress;
  • napi_list, the device's NAPI instances, and napi_config, their persistent settings (§5.2);
  • statistics: the legacy stats block, per-CPU counters selected by pcpu_stat_type, and core_stats for drops counted by the core itself;
  • links to the rest of the system: the embedded struct device dev, phydev and sfp_bus for the PHY and a pluggable optics module, devlink_port, and the instance lock lock (§4.2).

A driver allocates the structure with alloc_netdev_mqs(sizeof_priv, name, name_assign_type, setup, txqs, rxqs). Ethernet drivers use alloc_etherdev_mqs() or its device-managed form devm_alloc_etherdev_mqs(). One kvzalloc() covers the net_device and the driver's private area. Since Linux 6.11 that area is the cache-aligned flexible array priv[], sized by priv_len, and netdev_priv() simply returns it. The function then:

  • allocates the per-CPU reference count, the TX and RX queue arrays, the ethtool state, the queue configuration and a napi_config array with one slot per queue. The array sizes txqs and rxqs are fixed for the life of the device;
  • sets conservative defaults, among them 64 KB gso_max_size and tso_max_size (GSO_LEGACY_MAX_SIZE). A driver whose hardware accepts larger TSO requests raises tso_max_size with netif_set_tso_max_size(). The administrator can then raise gso_max_size up to that limit with ip link, which is how BIG TCP is enabled (§7.4);
  • calls setup. For Ethernet that is ether_setup(). It fills in the type (ARPHRD_ETHER), eth_header_ops, a 1500-byte MTU, 6-byte addresses, the broadcast and multicast flags, and a tx_queue_len of 1000. A setup routine that leaves tx_queue_len at 0 gets the device marked IFF_NO_QUEUE, which is how most virtual devices end up with no qdisc (§7.2).

The name may be a pattern such as eth%d. The kernel records how the name was chosen in name_assign_type and exports it in sysfs. The values are NET_NAME_ENUM for a kernel-enumerated pattern, NET_NAME_PREDICTABLE, NET_NAME_USER and NET_NAME_RENAMED. udev uses this value to decide whether to replace eth0 with a predictable name such as enp3s0. Names are limited to IFNAMSIZ, which is 16 bytes including the terminator. Since Linux 5.5 a device can therefore also carry alternative names of up to 127 characters (ip link property add dev dev altname name). These are hashed alongside the primary name, so lookups by either succeed. free_netdev() releases the structure after unregistration.

Interface counters come from several layers. dev_get_stats() merges them into one struct rtnl_link_stats64 for ip -s link and /proc/net/dev:

  • the driver's ndo_get_stats64, which usually reads hardware registers or per-ring counters;
  • otherwise, per-CPU software counters that the core allocates and frees itself, selected by pcpu_stat_type (Linux 6.7). The choices are lstats (packets and bytes, used by loopback), tstats (RX and TX packets and bytes, used by tunnels) and dstats (which add drop counts). The netdev netlink family returns them (qstats-get) under fixed names such as rx-alloc-fail, rx-hw-drops and rx-csum-unnecessary. Monitoring tools therefore no longer have to parse each driver's ethtool -S strings. Those strings remain for driver-private counters.

The feature words come in sets. hw_features lists what the user may toggle, wanted_features what the user asked for, and features what is active. §10.4 describes the NETIF_F_* bits and how they are recomputed; 7.0 defines 62 of them in a 64-bit netdev_features_t. Other sets describe what survives stacking:

  • vlan_features is what a VLAN device on top may use;
  • hw_enc_features applies to encapsulated packets (§3.3);
  • mpls_features applies to MPLS.

Bonds and teams combine the features of their lower devices with netdev_increment_features(). If an upper device has not asked for a feature in NETIF_F_UPPER_DISABLES (currently only LRO), the core forces it off in every device below it. Any change fires NETDEV_FEAT_CHANGE. XDP capabilities are advertised separately in xdp_features (Linux 6.3): basic actions, acting as an XDP_REDIRECT target, AF_XDP zero-copy, multi-buffer support and so on. The netdev netlink family reports them.

Registration, namespaces and ethtool

A driver initializes its net_device, adds NAPI instances with netif_napi_add(), and calls register_netdev(), which takes the RTNL lock and calls register_netdevice(). Registration proceeds in order:

  1. validate or assign the name (dev_get_valid_name() expands patterns such as eth%d);
  2. call ndo_init;
  3. reserve an ifindex;
  4. compute the initial feature set: wanted_features becomes features & hw_features, plus the always-available software GSO and GRO;
  5. create the sysfs kobject (netdev_register_kobject());
  6. set reg_state to NETREG_REGISTERED, and resolve the final features with __netdev_update_features(), which consults ndo_fix_features;
  7. mark the device present, initialize its link-watch state, and attach the no-op qdisc (dev_init_scheduler());
  8. link the device into the namespace's lists and hash tables (list_netdevice());
  9. fire the NETDEV_REGISTER notifier chain, which routing, IPv6 address configuration, netfilter, bridges and many others subscribe to via register_netdevice_notifier();
  10. broadcast an RTM_NEWLINK netlink message.

register_netdevice_notifier() replays NETDEV_REGISTER and NETDEV_UP for every existing device to a new subscriber, so a module loaded late sees the same events as one built in. register_netdevice_notifier_net() and register_netdevice_notifier_dev_net() limit a subscriber to one namespace or one device. The chain carries about forty events (enum netdev_cmd). Besides registration, the ones most subsystems care about are:

  • NETDEV_PRE_UP, NETDEV_UP, NETDEV_GOING_DOWN and NETDEV_DOWN, for administrative state. IPv4 and IPv6 add or flush addresses and routes on these;
  • NETDEV_CHANGE, for a change in operational (carrier) state;
  • NETDEV_CHANGEMTU, NETDEV_CHANGEADDR, NETDEV_CHANGENAME and NETDEV_FEAT_CHANGE, for attribute changes. NETDEV_PRECHANGEMTU and NETDEV_PRE_CHANGEADDR are sent first, and a subscriber may veto them;
  • NETDEV_PRECHANGEUPPER and NETDEV_CHANGEUPPER, for stacking changes (below);
  • NETDEV_UNREGISTER: the device is going away, and every holder must drop its references.

The device stays down until something calls dev_open(), typically ip link set dev up through dev_change_flags(). __dev_open() proceeds as follows:

  1. check that the device is present. A hot-unplugged or suspended NIC is not;
  2. send NETDEV_PRE_UP, which a subscriber can veto;
  3. set __LINK_STATE_START, so that netif_running() becomes true;
  4. call ndo_validate_addr and ndo_open;
  5. set IFF_UP and program the address filters (dev_set_rx_mode());
  6. call dev_activate(), which replaces the no-op qdisc with the real one. That is mq for a multiqueue device, noqueue for an IFF_NO_QUEUE device, and otherwise the qdisc named by net.core.default_qdisc (§7.2).

netif_open() then broadcasts RTM_NEWLINK and NETDEV_UP. dev_close() reverses the sequence. It sends NETDEV_GOING_DOWN, clears __LINK_STATE_START, deactivates the qdiscs, calls ndo_stop, clears IFF_UP, and sends NETDEV_DOWN.

IFF_UP is only the administrative state. Whether packets can flow is the operational state, which the driver drives from the link itself:

  1. A driver calls netif_carrier_on() or netif_carrier_off() from its link-change interrupt or, for SoC MACs with an external PHY, from the phylib/phylink state machine. These calls flip __LINK_STATE_NOCARRIER and call linkwatch_fire_event(). That function only queues the device, because the caller may be in interrupt context.
  2. A work item (linkwatch_event() in net/core/link_watch.c) takes RTNL and processes the queue. To absorb flapping links it runs at most once per second. Urgent events skip that delay: for example, carrier coming up while a qdisc change is pending, or a change on a bonding or team port.
  3. For each device the work item computes operstate following RFC 2863: IF_OPER_UP, DOWN, LOWERLAYERDOWN (a stacked device whose lower device is down), DORMANT or TESTING.
  4. If the device is up, the work item calls dev_activate() or dev_deactivate(), so packets are not queued to a link with no carrier. It then calls netif_state_change(), which sends NETDEV_CHANGE and RTM_NEWLINK.

User space sees the result as IFF_RUNNING (operstate up) and IFF_LOWER_UP (carrier) in ip link. While the carrier is up, the transmit watchdog (dev_watchdog()) checks for stuck TX queues.

Unregistration (unregister_netdev()) undoes registration. For a batch, as when a namespace is destroyed, unregister_netdevice_many() does the same and shares the expensive steps across many devices. The steps are:

  1. close the device if it is up;
  2. unlink it from the namespace's lists and set reg_state to NETREG_UNREGISTERING, so lookups no longer find it;
  3. flush every CPU's backlog of its packets (flush_all_backlogs()), then wait for an RCU grace period (synchronize_net()) so no receive path still uses it;
  4. destroy its qdiscs (dev_shutdown()) and uninstall XDP programs;
  5. fire NETDEV_UNREGISTER, on which routes, neighbours, addresses and sockets bound to the device let go of it;
  6. send RTM_DELLINK, call ndo_uninit, and remove the sysfs entries.

The final step, which comes after RTNL is released, is a classic source of hangs. netdev_run_todo() waits for every reference taken with dev_hold()/netdev_hold() to be dropped. While it waits, it rebroadcasts NETDEV_UNREGISTER once a second, so that holders of cached references, such as dst entries, release them. Every net.core.netdev_unregister_timeout_secs (default 10) seconds it also prints "unregister_netdevice: waiting for dev to become free. Usage count = N". The netdevice_tracker argument of netdev_hold() exists so that CONFIG_NET_DEV_REFCNT_TRACKER can identify which holder leaked. Only after the wait does the driver call free_netdev(). For devices that set needs_free_netdev, the core calls it instead.

Most device configuration is serialized by the global RTNL mutex (rtnl_lock()), the oldest big lock in networking. §9.4 discusses its scaling limits and the per-namespace rtnl_net_lock() of Linux 6.13. Each device also has an instance mutex, dev->lock. It was introduced for net shapers in 6.13 and became general in 6.14 with netdev_lock(). It always nests inside RTNL. On its own it protects the NAPI list and the per-NAPI settings (threaded, gro_flush_timeout, napi_defer_hard_irqs) and reg_state. Jointly with RTNL it protects up, nd_net and xdp_features. Linux 6.15 widened it into an ops lock. A device qualifies if it implements the queue-management or net-shaper operations, or sets request_ops_lock. For such a device the core calls nearly every ndo, ethtool and sysfs callback with the instance lock held (netdev_lock_ops()), and a single queue can be reconfigured under that lock. The naming convention since then is that the dev_xxx() helpers in net/core/dev_api.c take the instance lock, and the netif_xxx() variants expect the caller to hold it.

Devices stack. A VLAN, macvlan or ipvlan device sits on top of a lower device. A bridge, bond, team or VRF is the master of its ports. The relation is recorded with netdev_upper_dev_link() or netdev_master_upper_dev_link(). These maintain adjacency lists (dev->adj_list.upper and .lower), which netdev_walk_all_lower_dev() and its relatives traverse, and they refuse to nest deeper than MAX_NEST_DEV (8) levels. Linking first sends NETDEV_PRECHANGEUPPER, which any subscriber may veto, and then NETDEV_CHANGEUPPER. A switch driver, for example, can veto joining a bridge it cannot offload. A master usually also installs an rx_handler on each port, which diverts the port's received packets to the master (§5.4).

Every device belongs to exactly one network namespace, recorded in dev->nd_net and read with dev_net(). Registration links the device into that namespace's name and index hash tables, so eth0 can exist in many namespaces at once. dev_change_net_namespace() moves a device by closing it, sending NETDEV_UNREGISTER and RTM_DELLINK in the old namespace, and sending NETDEV_REGISTER in the new one. It keeps its ifindex unless that number is taken there. Devices with netns_immutable set (called netns_local before Linux 6.15) cannot move. They include loopback, bridges, bonds, VRFs and the fallback tunnel devices. Chapter 25 covers network namespaces as an isolation mechanism and the veth pairs that connect them. Here it is enough to know that nearly every global table in the stack — routes, sockets, netfilter rules, sysctls — is reached through a struct net * taken from the device or socket.

The ethtool interface configures what the generic netdev operations do not: link speed and autonegotiation, ring sizes, interrupt coalescing, channel (queue) counts, offload features, the RSS indirection table and hash key, flow-steering rules, firmware flashing, statistics and self tests. The driver side is struct ethtool_ops (include/linux/ethtool.h), with methods such as get_ringparam, get_channels, get_coalesce, get_rxnfc and get_link_ksettings. The user side was originally the SIOCETHTOOL ioctl, handled by dev_ethtool() in net/ethtool/ioctl.c. Since Linux 5.6 there is also a generic-netlink family named "ethtool", implemented by one file per message group in net/ethtool/ (rings.c, channels.c, coalesce.c, rss.c…). It supports notifications and extensible attributes. Current ethtool binaries prefer netlink and fall back to the ioctl. Before calling the driver, the ethtool core checks a request against what the driver declared in ethtool_ops: the supported_coalesce_params and supported_ring_params bitmasks, and the RSS table and key sizes. Drivers therefore do not each reimplement validation. Newer message groups cover things the ioctl never could:

  • additional RSS contexts, tracked by the core since Linux 6.11 and created over netlink since 6.17 (§4.3);
  • cable diagnostics and Power-over-Ethernet (PSE) control;
  • PHY topology, for links with several PHYs or SFP modules;
  • since 6.14, the choice of which PTP clock, in the MAC or in the PHY, timestamps packets (TSCONFIG, recorded in dev->hwprov).

Configuration that belongs to a whole adapter rather than one interface goes through devlink (net/devlink/), another generic-netlink family. One ASIC may expose several netdevs, such as switch ports or SR-IOV representors, or none at all while its firmware recovers. Adapter-wide settings therefore live in devlink:

  • firmware versions and flashing;
  • health reporters with automatic recovery and state dumps;
  • driver parameters, reload and resource partitioning;
  • the switchdev eswitch mode for SR-IOV.

A netdev points to its devlink_port. Unless the driver implements ndo_get_phys_port_name, the port supplies the phys_port_name that udev appends to predictable names, as in enp3s0f0np0.

Multiqueue devices

A modern NIC has many transmit and receive queues — commonly one pair per CPU — each with its own descriptor ring, interrupt vector and NAPI instance. The hardware spreads incoming flows over the RX queues with receive-side scaling (RSS). RSS hashes the addresses and ports of each packet and looks the hash up in an indirection table, so the packets of one flow always land on the same queue, and therefore the same CPU. The kernel mirrors the queues in two arrays:

  • dev->_tx holds one struct netdev_queue per TX queue. Each has a pointer to its qdisc, the _xmit_lock that serializes calls into the driver, a state word with the stop bits (§7.3), the Byte Queue Limits state dql, an optional AF_XDP buffer pool, and the NAPI instance that completes its transmissions. It also holds trans_start, the time of the last transmission, which the watchdog uses to detect a stuck queue, and tx_maxrate, a per-queue rate limit for hardware that supports one (ndo_set_tx_maxrate).
  • dev->_rx holds one struct netdev_rx_queue (include/net/netdev_rx_queue.h) per RX queue. Each has the RPS map and flow table (§5.3), the XDP receive-queue info xdp_rxq, the memory-provider parameters mp_params used by devmem TCP and io_uring zero-copy receive (§10.2), the queue's NAPI, an AF_XDP pool, and since Linux 7.0 the per-queue configuration qcfg (below).

Both are exposed in sysfs under /sys/class/net/dev/queues/ (rx-N/rps_cpus, tx-N/xps_cpus, tx-N/byte_queue_limits/). The netdev generic-netlink family (net/core/netdev-genl.c) reports which NAPI and IRQ serve each queue.

num_tx_queues and num_rx_queues are fixed when the device is allocated. real_num_tx_queues and real_num_rx_queues say how many are in use. A driver changes them with netif_set_real_num_tx_queues() and netif_set_real_num_rx_queues(), usually when the administrator changes the channel count with ethtool -L. The arrays never shrink, so a device sized for the maximum can grow and shrink without being re-registered. Most drivers choose their default channel count with netif_get_num_default_rss_queues(). It counts physical cores, each group of SMT siblings once, and halves the result when there are more than two. A 64-core server therefore starts with 32 queue pairs; a kdump kernel gets one.

RSS is configured through ethtool:

  • The indirection table typically has 64 to 512 entries. By default (ethtool_rxfh_indir_default()) it is filled round-robin over the active RX queues. ethtool -X can weight it or confine it to a subset of queues.
  • ethtool -N … rx-flow-hash chooses which header fields are hashed for each flow type.
  • The hash key is normally a random key that drivers fetch with netdev_rss_key_fill(). It is shared by all devices and visible as net.core.netdev_rss_key.

A NIC can also hold additional RSS contexts, each with its own table and key. ntuple filters (ethtool -N … context N) send selected flows to them. That isolates, for example, the queues bound to a devmem or io_uring zero-copy consumer from ordinary traffic (§10.2).

Drivers declare which NAPI instance serves each queue with netif_queue_set_napi(), and which IRQ drives each NAPI with netif_napi_set_irq() (both Linux 6.8). The netdev family reports this mapping to user space, which can then place a busy-polling thread next to its queue. A driver that creates its NAPIs with netif_napi_add_config() binds each one to a persistent napi_config slot (§5.2). Since Linux 6.15 such a driver can also call netif_enable_irq_affinity(). The core then saves each vector's affinity in the slot and restores it when rings are rebuilt, so the administrator's setting survives an ethtool -L or -G. With rx_cpu_rmap_auto the core likewise maintains the CPU-to-queue reverse map that accelerated RFS needs (§5.3).

Reconfiguring a ring used to mean taking the whole interface down and up. The queue-management operations (struct netdev_queue_mgmt_ops, Linux 6.10, include/net/netdev_queues.h) let the core restart one RX queue instead. netdev_rx_queue_restart() proceeds in four steps, and if starting the new memory fails it restarts the queue with the old memory:

  1. ask the driver for a complete new set of ring memory for the queue (ndo_queue_mem_alloc, into a buffer of ndo_queue_mem_size bytes);
  2. stop the queue, saving its old memory (ndo_queue_stop);
  3. start it with the new memory (ndo_queue_start);
  4. free the old memory (ndo_queue_mem_free).

Traffic on the other queues is undisturbed. This is how a memory provider is attached to a single queue (§10.2). Linux 6.18 added ndo_queue_get_dma_dev, which tells a zero-copy consumer which device to map its buffers for. Linux 7.0 adds per-queue configuration: a struct netdev_queue_config in each RX queue's qcfg, filled with defaults by ndo_default_qcfg and checked by ndo_validate_qcfg. Its first parameter, rx_page_size, lets io_uring zero-copy receive ask for receive buffers larger than a page, on drivers that advertise QCFG_RX_PAGE_SIZE.

Each queue's interrupt is normally an MSI-X vector (Chapter 4), and the vector's CPU affinity (Chapter 4) decides which CPU runs that queue's NAPI poll. Matching IRQ affinity, RSS, XPS and application placement is the core of network performance tuning on both architectures. On x86_64, MSI-X vectors are delivered through the local APIC with a per-vector destination CPU. On ARM64, they usually arrive as LPIs through a GICv3 Interrupt Translation Service, whose per-device tables route each event to a CPU. The kernel affinity interface is the same for both.

DMA is where the architectures differ most for drivers. Drivers map RX and TX buffers with the streaming DMA API (Chapter 13). On x86_64, PCIe DMA is cache-coherent, so dma_sync_single_for_cpu() before reading a received frame does no cache maintenance. It costs something only when an IOMMU or SWIOTLB bounce buffer is involved. Many ARM64 SoC network controllers are not coherent. There, the same call invalidates the cache lines covering the buffer, and the "for device" sync before reposting a buffer cleans them. That cost scales with the bytes synced, which is why page_pool syncs only the length the device can actually have written (§10.1). Server-class ARM64 systems with coherent PCIe behave like x86_64.

The Receive Path

An interrupt per packet stops scaling long before a 10 Gb/s link is full. In Linux 2.6.11, most drivers still called netif_rx() from their interrupt handler for every frame. The few that used the then-new polling interface implemented dev->poll(dev, &quota) directly on the net_device. Linux 2.6.24 moved polling into a separate struct napi_struct, so one device can have many independent polling contexts. Everything on the modern receive path is built around it: the interrupt only schedules a poll, and the poll function, running in softirq context under a budget, pulls frames off the ring, merges them with GRO, and hands them to receive steering and the protocol handlers.

A driver hands frames to the core through one of four entry points:

  • napi_gro_receive() is the normal choice. The driver builds the skb itself and passes it to GRO.
  • napi_gro_frags() suits drivers that receive into pages. The driver attaches the page fragments to the skb that napi_get_frags() returns, and GRO reads the headers in place from the first fragment (frag0). It pulls them into the linear area only if it has to hold the packet.
  • netif_receive_skb() and netif_receive_skb_list() are for NAPI drivers that bypass GRO.
  • netif_rx() is for code that does not run in a NAPI poll: non-NAPI drivers, virtual devices and some tunnels. It queues the skb on a per-CPU backlog (§5.3) and returns at once. Since Linux 5.18 it may be called from both interrupt and process context, and netif_rx_ni() is gone.

All four converge on __netif_receive_skb_core() (§5.4). Everything before that point is per NAPI instance, and therefore per queue and usually per CPU.

NAPI and net_rx_action

NAPI ("New API") replaces per-packet interrupts with interrupt-triggered polling. Each RX queue has a struct napi_struct (include/linux/netdevice.h) holding:

  • the driver's poll function and its weight (normally NAPI_POLL_WEIGHT, 64);
  • a state bit field (NAPI_STATE_SCHED, NAPI_STATE_MISSED, NAPI_STATE_THREADED…);
  • the poll_list linkage;
  • a GRO context (struct gro_node gro);
  • an hrtimer;
  • an optional kernel thread;
  • a global napi_id that sockets remember for busy polling.

A driver creates its instances in a fixed lifecycle:

  • Add. netif_napi_add() creates an instance, usually one per RX/TX queue pair. netif_napi_add_config() also ties it to a persistent napi_config slot (§4.3), and netif_napi_add_tx() registers a TX-only instance that busy polling never uses. A new instance starts with NAPI_STATE_SCHED and NAPI_STATE_NPSVC set, so nothing can schedule it yet. A weight above NAPI_POLL_WEIGHT draws a one-time error message.
  • Enable. napi_enable(), called from ndo_open, clears those bits, restores the saved configuration and assigns the napi_id. IDs start above NR_CPUS because the skb field that carries the ID shares a union with sender_cpu, which transmit uses for XPS.
  • Disable. napi_disable(), called from ndo_stop or before a ring reconfiguration, sets NAPI_STATE_DISABLE and sleeps until any running poll finishes. It then sets SCHED again to block new polls and saves the per-NAPI settings, including the ID, into the instance's napi_config.
  • Delete. netif_napi_del() removes the instance.

Figure 22-4 shows the cycle. When the NIC raises the queue's interrupt, the handler calls napi_schedule_prep(), which atomically sets NAPI_STATE_SCHED. If the bit was clear, the handler masks the queue's interrupt in the device and calls __napi_schedule(). From then on the device does not interrupt again until polling is finished, however many frames arrive.

____napi_schedule() either hands the instance to its dedicated thread or puts it on the current CPU's poll list and raises the softirq:

/* net/core/dev.c */
static inline void ____napi_schedule(struct softnet_data *sd,
				     struct napi_struct *napi)
{
	struct task_struct *thread;

	lockdep_assert_irqs_disabled();

	if (test_bit(NAPI_STATE_THREADED, &napi->state)) {
		...
		thread = READ_ONCE(napi->thread);
		if (thread) {
			if (use_backlog_threads() && thread == raw_cpu_read(backlog_napi))
				goto use_local_napi;

			set_bit(NAPI_STATE_SCHED_THREADED, &napi->state);
			wake_up_process(thread);
			return;
		}
	}

use_local_napi:
	DEBUG_NET_WARN_ON_ONCE(!list_empty(&napi->poll_list));
	list_add_tail(&napi->poll_list, &sd->poll_list);
	WRITE_ONCE(napi->list_owner, smp_processor_id());
	/* If not called from net_rx_action()
	 * we have to raise NET_RX_SOFTIRQ.
	 */
	if (!sd->in_net_rx_action)
		raise_softirq_irqoff(NET_RX_SOFTIRQ);
}

Because the instance goes on the list of the CPU that took the interrupt, IRQ affinity decides where receive processing runs. net_rx_action() then polls the listed instances under two global limits. net.core.netdev_budget (default 300) caps the packets processed in one invocation, and net.core.netdev_budget_usecs (default two jiffies' worth) caps the time:

/* net/core/dev.c (net_rx_action, abridged) */
	unsigned long time_limit = jiffies +
		usecs_to_jiffies(READ_ONCE(net_hotdata.netdev_budget_usecs));
	int budget = READ_ONCE(net_hotdata.netdev_budget);
	...
	for (;;) {
		struct napi_struct *n;

		skb_defer_free_flush();

		if (list_empty(&list)) {
			...
			break;
		}

		n = list_first_entry(&list, struct napi_struct, poll_list);
		budget -= napi_poll(n, &repoll);

		/* If softirq window is exhausted then punt.
		 * Allow this to run for 2 jiffies since which will allow
		 * an average latency of 1.5/HZ.
		 */
		if (unlikely(budget <= 0 ||
			     time_after_eq(jiffies, time_limit))) {
			/* Pairs with READ_ONCE() in softnet_seq_show() */
			WRITE_ONCE(sd->time_squeeze, sd->time_squeeze + 1);
			break;
		}
	}

	local_irq_disable();

	list_splice_tail_init(&sd->poll_list, &list);
	list_splice_tail(&repoll, &list);
	list_splice(&list, &sd->poll_list);
	if (!list_empty(&sd->poll_list))
		__raise_softirq_irqoff(NET_RX_SOFTIRQ);
	else
		sd->in_net_rx_action = false;

	net_rps_action_and_irq_enable(sd);

The driver's poll(napi, budget) function does the real work. It first reclaims completed TX descriptors. TX cleanup does not count against the budget, and a budget of 0 means "TX cleanup only", as netpoll uses it. Then it walks the RX ring. For each completed descriptor it syncs the buffer for the CPU, builds an skb, sets protocol with eth_type_trans(), records the RSS hash and checksum status, and passes the skb to napi_gro_receive(). It refills the ring with fresh buffers and returns the number of packets processed. If that is less than the budget, the ring is empty: the driver calls napi_complete_done() and unmasks the interrupt. If the driver used its whole budget, it must leave NAPI scheduled. __napi_poll() then flushes aged GRO packets and puts the instance on the repoll list, so a busy queue cannot starve the others. When net_rx_action() runs out of budget or time, it increments time_squeeze (the third column of /proc/net/softnet_stat) and re-raises the softirq. Under sustained load, softirq processing then migrates to ksoftirqd, where the scheduler can balance it against user tasks. The softirq core itself makes that switch once it has restarted 10 times, has run for 2 ms, or sees that the CPU needs to reschedule.

Driver writers must get three more details of the poll contract right:

  • Check the return value. napi_complete_done() returns a bool, and the driver may re-enable the interrupt only if it returns true. It returns false in three cases: a busy poller currently owns the instance (NAPI_STATE_IN_BUSY_POLL), MISSED forced a reschedule, or IRQ deferral armed the timer instead (§5.2).
  • Report the work done. With a nonzero count and no deferral configured, completion flushes every packet GRO is still holding, so GRO never holds a packet across an idle period. With a gro_flush_timeout, it flushes only packets from an earlier jiffy, and the timer takes care of the rest.
  • Flush XDP redirects. A driver that runs XDP must call xdp_do_flush() before returning. That sends the frames XDP_REDIRECT batched in per-CPU bulk queues. On CONFIG_DEBUG_NET kernels, __napi_poll() checks with xdp_do_check_flushed() and warns about drivers that forget.

Because the poll runs on the CPU that owns the queue, pages the stack frees there go straight back to the queue's page_pool cache (§10.1).

The NAPI_STATE_MISSED bit closes a race. If an interrupt arrives while a poll is already running, perhaps on another CPU, napi_schedule_prep() sets MISSED instead of failing silently. napi_complete_done() sees it, keeps SCHED set, and reschedules the instance instead of completing. A packet that arrived during completion is therefore never stranded until the next interrupt.

The napi:napi_poll tracepoint records every call with the device, the work done and the budget. A poll that keeps returning its full weight shows a queue that cannot keep up. The net:napi_gro_receive_entry, net:netif_receive_skb and net:netif_rx tracepoints mark the entry points.

Threaded NAPI, busy polling and IRQ deferral

The basic cycle runs NAPI in softirq context on the interrupted CPU. That is efficient but has two weaknesses: softirq time is invisible to the scheduler and hard to prioritize, and every completion re-enables an interrupt whose cost can dominate at high packet rates. Several mechanisms, added over a decade, address these. Table 22-7 lists their controls.

  • Threaded NAPI (Linux 5.12) gives each NAPI instance a kernel thread named napi/dev-id, created by napi_kthread_create(). ____napi_schedule() wakes the thread instead of raising the softirq, and the thread loops calling the poll function with bottom halves disabled. The work becomes an ordinary schedulable task that can be given a CPU affinity, a priority or a cgroup. On PREEMPT_RT kernels, the per-CPU backlog that RPS uses is also threaded by default (backlog_napi/cpu, Linux 6.10). Each pass of the thread loop also sends pending RPS IPIs and flushes deferred skb frees, as net_rx_action() does. The thread gets no automatic CPU affinity, so administrators usually pin it next to its interrupt. The threaded sysfs attribute switches a whole device (0 or 1), and since Linux 6.17 the netdev netlink napi-set command can switch single instances. A driver can make threading its default with netif_threaded_enable(). Linux 6.19 added a busy-polling mode (NETDEV_NAPI_THREADED_BUSY_POLL), which only netlink can select. The thread then keeps NAPI_STATE_IN_BUSY_POLL set, so napi_complete_done() never completes and the interrupt stays off. The thread polls continuously, flushing old GRO packets and calling cond_resched() on each pass. It consumes a whole CPU and is meant for an isolated core.
  • Busy polling (Linux 3.11) lets a task waiting for data poll the device queue itself instead of sleeping until an interrupt. Every received skb carries the napi_id of the instance that produced it, and sockets record it in sk_napi_id. When recvmsg() or poll() finds no data and busy polling is enabled for the socket (SO_BUSY_POLL or net.core.busy_read/busy_poll), sk_busy_loop() calls napi_busy_loop(). That function runs the driver's poll function directly in the task's context for up to the configured number of microseconds. The loop claims the instance only if it is idle, by setting SCHED and IN_BUSY_POLL with one compare-and-swap. If softirq or another poller already owns it, the task just spins and re-checks. Each call polls with a small budget (BUSY_POLL_BUDGET, 8, or SO_BUSY_POLL_BUDGET) and passes GRO's batch up at once. The loop ends when data arrives, the time runs out or the scheduler wants the CPU. busy_poll_stop() then hands the instance back to normal processing. Busy-polled packets are counted in BusyPollRxPackets in /proc/net/netstat. epoll does the same for all its sockets when they share one NAPI ID. The EPIOCSPARAMS ioctl (Linux 6.9) sets busy-poll parameters per epoll instance.
  • IRQ deferral (Linux 5.8) keeps the interrupt masked after a poll completes. With napi_defer_hard_irqs set to N, napi_complete_done() does not truly complete. It arms the NAPI hrtimer for gro_flush_timeout nanoseconds, and napi_watchdog() reschedules the poll when the timer fires, up to N consecutive empty polls. Only then is the interrupt re-enabled. At high load this trades a little latency for far fewer interrupts.
  • Preferred busy polling (SO_PREFER_BUSY_POLL, Linux 5.11) combines the two. While an application is busy polling, softirq processing of the instance backs off and its interrupts stay deferred, so the application does all the work in its own context.
  • IRQ suspension (Linux 6.13) extends this to epoll. When an epoll busy poll finds events, napi_suspend_irqs() arms the timer with the much longer irq_suspend_timeout, and IRQs stay suspended for as long as the application keeps finding work. When an epoll wait finds nothing, napi_resume_irqs() re-enables normal processing. The timeout is only a safety net against an application that stops polling.

GRO, RPS and RFS

Per-packet overhead in the upper layers — route lookup, netfilter, socket lookup, TCP processing — is mostly independent of packet size. Generic Receive Offload (GRO, Linux 2.6.29) exploits this by merging consecutive segments of the same flow into one large skb before the stack sees them. It is the receive-side counterpart of TSO. Since 6.15 the GRO state is a struct gro_node embedded in each NAPI instance. It holds GRO_HASH_BUCKETS (8) lists of packets being held, selected by the RSS hash, plus rx_list, the batch of completed packets waiting to go up. The split from napi_struct lets GRO run outside NAPI too: since the same release, the BPF cpumap kthreads that receive frames redirected by XDP merge them through their own gro_node.

napi_gro_receive() calls gro_receive_skb(), and dev_gro_receive() in net/core/gro.c does the work. It marks which held packets might belong to the same flow (gro_list_prepare() compares flow hash, device, VLAN tag and MAC header), then calls the gro_receive callback of the struct packet_offload registered for the EtherType. For IPv4 that is inet_gro_receive(), which checks the IP headers and calls the transport's net_offload callback: tcp4_gro_receive() → tcp_gro_receive(), or udp4_gro_receive(). TCP merges a segment into the held packet if it is the next in sequence and its flags and options match. The payload is appended to the held skb's frags, or to its frag_list when the frags are full, and gso_size/gso_segs record the original segmentation. A segment with PSH, a mismatched option, or a full held packet (64 KB by default, gro_max_size) forces a flush. gro_complete() then fixes up the headers via each layer's gro_complete callback and passes the merged packet to gro_normal_one(). That function batches packets on rx_list and hands them to netif_receive_skb_list_internal() in groups of gro_normal_batch. The rest of the stack thus sees fewer, larger packets, and often a list of them at once. When forwarding, GSO splits the merged packet again on the way out (§7.4). Some NICs do the merging in hardware (NETIF_F_GRO_HW) under the same rules.

GRO keeps its per-packet state in the skb's control block, accessed as NAPI_GRO_CB(skb) (struct napi_gro_cb in include/net/gro.h). It holds:

  • same_flow and flush, the two verdicts each layer refines;
  • count, the number of segments merged so far;
  • age and last, used for flushing and for appending;
  • the header offsets;
  • checksum-validation state, so inner headers are not checksummed twice;
  • encap_mark and a recursion counter that stops nested tunnel parsing at GRO_RECURSION_LIMIT (15).

Each hash bucket holds at most MAX_GRO_SKBS (8) packets. A new flow arriving at a full bucket forces the oldest held packet up the stack. The return value of gro_receive_skb() tells the caller what happened to the skb:

  • GRO_MERGED or GRO_MERGED_FREE: its data joined a held packet;
  • GRO_HELD: it now heads a new flow;
  • GRO_NORMAL: it went up unmerged;
  • GRO_CONSUMED: a callback took it.

Not all traffic is merged. netif_elide_gro() skips GRO entirely on a device without NETIF_F_GRO (ethtool -K dev gro off) or with a generic XDP program attached, because that program must see every original packet. Otherwise TCP is always merged. UDP has no stream semantics, so udp_gro_receive() merges only where that is known to be safe:

  • For a local socket, only when the socket asked for it with UDP_GRO (§8.4).
  • For a UDP tunnel socket (VXLAN, Geneve, FOU) with its own gro_receive callback. GRO then continues into the encapsulated packet and merges the inner TCP segments.
  • For forwarded traffic, only when the device enables NETIF_F_GRO_UDP_FWD (rx-udp-gro-forwarding, Linux 5.12) or NETIF_F_GRO_FRAGLIST (rx-gro-list, Linux 5.6). Fraglist GRO chains the original packets unmodified on frag_list, so GSO can split them again on output at almost no cost (§7.4).

Tunnel devices that re-inject decapsulated packets, such as VXLAN, Geneve, MACsec and bareudp, pass them to gro_cells_receive() instead of netif_rx(). That function queues them on a per-CPU NAPI instance of the tunnel device, so the inner packets get GRO as well. The held-packet limit of 64 KB (gro_max_size, and gro_ipv4_max_size for IPv4) can be raised for BIG TCP (§7.4).

RSS spreads flows over queues only as far as the hardware has queues and hash functions. Receive Packet Steering (RPS, Linux 2.6.35) does the same in software. When a queue's rps_cpus mask is set, netif_receive_skb_internal() asks get_rps_cpu() for a target CPU. The packet then goes to enqueue_to_backlog() instead of straight up the stack. GRO's batches take the list variant, netif_receive_skb_list_internal(), which makes the same decision for each packet and passes the rest on as a list:

/* net/core/dev.c */
static int netif_receive_skb_internal(struct sk_buff *skb)
{
	int ret;

	net_timestamp_check(READ_ONCE(net_hotdata.tstamp_prequeue), skb);

	if (skb_defer_rx_timestamp(skb))
		return NET_RX_SUCCESS;

	rcu_read_lock();
#ifdef CONFIG_RPS
	if (static_branch_unlikely(&rps_needed)) {
		struct rps_dev_flow voidflow, *rflow = &voidflow;
		int cpu = get_rps_cpu(skb->dev, skb, &rflow);

		if (cpu >= 0) {
			ret = enqueue_to_backlog(skb, cpu, &rflow->last_qtail);
			rcu_read_unlock();
			return ret;
		}
	}
#endif
	ret = __netif_receive_skb(skb);
	rcu_read_unlock();
	return ret;
}

enqueue_to_backlog() appends the skb to the target CPU's softnet_data.input_pkt_queue. It drops the packet, counting it in the second column of softnet_stat, if the queue is longer than netdev_max_backlog or the per-flow limiter skb_flow_limit() objects. It then schedules that CPU's backlog NAPI instance, sd->backlog, whose poll function is process_backlog(). A remote CPU is not interrupted per packet. net_rps_action_and_irq_enable(), at the end of net_rx_action(), sends one IPI per target CPU that received work in this round. The same backlog serves the legacy netif_rx() interface, which non-NAPI drivers and virtual devices such as loopback and veth use.

get_rps_cpu() hashes the packet with skb_get_hash(). It reuses the NIC's RSS hash when the driver recorded one, and otherwise runs the flow dissector. It then indexes the queue's rps_map with reciprocal_scale(), so packets of one flow always land on the same CPU. The map comes from the queue's rps_cpus mask. Since Linux 6.3, newly created queues start with net.core.rps_default_mask, which is useful for containers whose veth devices appear after boot. Remote CPUs are woken through smp_call_function_single_async() on each target's csd. The handler only schedules the target's backlog NAPI. With backlog threads (§5.2), no RPS IPI is queued: the remote backlog thread is simply woken.

The flow limiter protects the backlog from a single heavy flow. It acts only on CPUs listed in net.core.flow_limit_cpu_bitmap and only once that CPU's backlog is more than half full. It then remembers the flow hashes of the last 128 packets that arrived while the backlog was in that state, and drops any packet whose flow accounts for more than half of them. Short, latency-sensitive flows therefore still get through while an elephant flow is trimmed. These drops are counted in the flow-limit column of softnet_stat (§1.3).

Receive Flow Steering (RFS, also 2.6.35) refines RPS by steering a flow to the CPU where the application consumes it, not just to some CPU chosen by hash. Each time a task calls recvmsg(), sendmsg() or accept() on an INET socket, sock_rps_record_flow() writes the current CPU into the global rps_sock_flow_table, sized by net.core.rps_sock_flow_entries and indexed by flow hash. Each 32-bit entry combines the upper bits of the flow hash with the CPU number. Only sockets in TCP_ESTABLISHED state record themselves, including connected UDP sockets, which use the same state value. The test is cheap and covers nearly every useful case. Since Linux 6.16, a socket's entry is also cleared when it is unhashed, so a closed connection leaves no stale hint behind. get_rps_cpu() first consults this table. If the stored hash bits match the packet's, it uses the CPU named there. Otherwise another flow owns the slot, and it falls back to the plain RPS map. It avoids reordering by switching a flow's CPU only when the per-queue rps_dev_flow entry shows that every packet previously queued for the old CPU has been dequeued (the last_qtail check). With CONFIG_RFS_ACCEL and a driver that implements ndo_rx_flow_steer, set_rps_cpu() also programs a NIC filter steering the flow to the RX queue whose interrupt is affine to that CPU. This is accelerated RFS, and the software hop disappears.

Accelerated RFS needs NETIF_F_NTUPLE and a CPU-to-queue reverse map, dev->rx_cpu_rmap. The core builds that map itself when the driver sets rx_cpu_rmap_auto (§4.3). The driver's ndo_rx_flow_steer returns a filter ID, which is recorded in the flow-table slot. The driver later asks rps_may_expire_flow() whether a filter can be removed. Since Linux 6.18, set_rps_cpu() also refuses to take over a slot whose filter still belongs to a different, recently active flow. Hash collisions therefore no longer bounce filters between two busy flows. Documentation/networking/scaling.rst suggests 32768 socket-table entries, divided evenly among the RX queues for rps_flow_cnt.

Protocol demultiplexing

Whether it arrives from GRO, the backlog or a non-NAPI driver, a packet ends up in __netif_receive_skb_core(). That function is the protocol-independent switch of the receive path. Figure 22-5 shows its stages in order.

The earliest hook comes before the core function, in the driver itself. A driver with native XDP support runs the attached BPF program on the raw receive buffer before allocating any skb. The program can drop the frame, bounce it back out (XDP_TX), redirect it to another device, CPU or AF_XDP socket, or pass it on. Chapter 23 describes XDP from the BPF side. For devices without native support, __netif_receive_skb_core() runs the same program in "generic" mode on the skb (do_xdp_generic()), which gives the same semantics at higher cost. The program expects the packet in one buffer with XDP_PACKET_HEADROOM (256 bytes) of headroom. Since Linux 6.9, a cloned or fragmented skb is therefore first copied into pages from a per-CPU system page_pool, instead of always being linearized. Packets that tc reinjected are not run again. Each pass through the function sets skb_iif, the ifindex the packet arrived on, and counts the packet in the CPU's processed statistic. The function then strips an in-band VLAN tag into skb->vlan_tci if the hardware did not, and walks the remaining stages:

The pt_prev idiom appears throughout. Each matching handler is remembered rather than called at once. When the next match is found, the previous one is called via deliver_skb(), which takes an extra reference on the skb first. The last handler is returned to the caller in *ppt_prev and called without an extra reference. In the common case of exactly one handler (IP), no reference counting happens at all. __netif_receive_skb_one_core() makes that final call through INDIRECT_CALL_INET(pt_prev->func, ipv6_rcv, ip_rcv, …). The list path, __netif_receive_skb_list_core(), runs the core function on each skb of the batch. It collects consecutive packets with the same final handler and the same original device into a sublist, and calls pt_prev->list_func (ip_list_rcv()) once per sublist. Ordering is preserved, because a sublist is dispatched as soon as the handler changes.

The stages, in order:

  • Taps are struct packet_type entries with type ETH_P_ALL, kept on the namespace's or device's ptype_all list. Every AF_PACKET socket bound to all protocols is one, so a running tcpdump adds a delivery to every packet. packet_rcv() runs the socket's classic BPF filter first and clones the skb only if the filter accepts it.
  • Ingress classification: sch_handle_ingress() runs the tcx BPF programs (Linux 6.6) first and then the classic tc ingress filters (Chapter 23). A verdict can drop the packet (TC_ACT_SHOT), steal it, or redirect it with skb_do_redirect(). bpf_redirect_peer() (Linux 5.10) is the fast case. It switches the skb to the peer of a veth or netkit pair, typically inside a container's namespace, and the packet re-enters another_round on that device without a trip through the backlog. nf_ingress() then runs netfilter's per-device ingress hook. Packets that tc marked to skip classification bypass both the taps and this stage.
  • VLAN devices: if the packet carries a tag, vlan_do_receive() looks up the VLAN device stacked on skb->dev for that VLAN ID. If one exists, the packet restarts on it. A tagged packet that matches no VLAN device is marked PACKET_OTHERHOST, so IPv4 and IPv6 drop it after the taps have seen it. A priority-only tag (VLAN 0) is simply removed.
  • rx_handler lets a device that is enslaved to an upper device (a bridge port, a bond member, a macvlan lower device) divert the packet. A device can have only one handler, registered with netdev_rx_handler_register(), so a port cannot belong to a bridge and a bond at once. The handler returns one of four verdicts. RX_HANDLER_CONSUMED means it took the packet, for example to forward it through the bridge. RX_HANDLER_ANOTHER restarts processing with skb->dev changed to the upper device. RX_HANDLER_EXACT lets only handlers bound to this exact device see the packet, as for frames on an inactive bond member. RX_HANDLER_PASS continues on the current device.
  • Protocol dispatch: the remaining handlers are found by EtherType in the 16-bucket ptype_base hash and in the namespace's and device's ptype_specific lists. inet_init() registers ip_packet_type (.type = ETH_P_IP, .func = ip_rcv, .list_func = ip_list_rcv) with dev_add_pack(). IPv6 and ARP register theirs the same way. Since Linux 6.15, ptype_all and ptype_specific also exist per namespace (they were global), so a packet socket in one container no longer sits on a list every namespace walks. A packet that no handler wants is freed with SKB_DROP_REASON_UNHANDLED_PROTO and counted in the device's rx_dropped, or in rx_nohandler when only exact-match delivery was allowed.

Memory-reserve packets take a restricted route. When swap over the network is active, the driver may allocate skbs from the emergency reserves, and skb_pfmemalloc() marks them. __netif_receive_skb() then processes them with PF_MEMALLOC set. The core skips the taps, so no packet socket can pin reserve memory, and it delivers only ARP, IPv4, IPv6 and VLAN frames. Any other protocol is dropped with SKB_DROP_REASON_PFMEMALLOC. Further up, only sockets marked SOCK_MEMALLOC may receive such packets.

The IP Layer

The network layer decides what happens to each packet: deliver it to a local socket, forward it to another interface, or drop it. It also builds headers for locally generated packets and finds the link-layer address of the next hop. In the 2.6.11 kernel, a global routing cache of recent lookups sat in front of a hash-based FIB. Both are gone. Since Linux 2.6.39 the FIB is always the LC-trie of net/ipv4/fib_trie.c, and Linux 3.6 removed the routing cache, so every lookup goes to the trie. The functions are otherwise recognizable. IPv6 follows the same design with its own functions and its own FIB, a radix tree in net/ipv6/ip6_fib.c. Most of this state (FIB tables and rules, fragment queues, the net.ipv4.* sysctls) is per network namespace, in struct netns_ipv4 (net->ipv4).

Receiving: ip_rcv to the transport

Figure 22-6 shows the IPv4 paths and the five netfilter hooks that sit on them (§9.1). ip_rcv(), the handler registered in ip_packet_type, validates the packet and immediately enters the first hook:

/* net/ipv4/ip_input.c */
int ip_rcv(struct sk_buff *skb, struct net_device *dev, struct packet_type *pt,
	   struct net_device *orig_dev)
{
	struct net *net = dev_net(dev);

	skb = ip_rcv_core(skb, net);
	if (skb == NULL)
		return NET_RX_DROP;

	return NF_HOOK(NFPROTO_IPV4, NF_INET_PRE_ROUTING,
		       net, NULL, skb, dev, NULL,
		       ip_rcv_finish);
}

ip_rcv_core() does the following:

  • drops frames addressed to another host's MAC address (PACKET_OTHERHOST, seen in promiscuous mode), counting them in the device's rx_otherhost_dropped statistic;
  • unshares the skb (skb_share_check()) if a tap still holds a reference;
  • makes sure the base header, and then the full ihl-sized header, are in the linear area (pskb_may_pull());
  • checks the version, header length (ihl at least 5) and header checksum (ip_fast_csum()), counting failures as InHdrErrors and InCsumErrors in /proc/net/snmp;
  • reads the total length with iph_totlen(), which uses skb->len for a BIG TCP packet larger than 64 KB whose tot_len is 0 (§7.4); drops truncated packets; and trims link-layer padding beyond the total length with pskb_trim_rcsum();
  • records where the transport header starts, clears the IP control block (IPCB(skb), a struct inet_skb_parm overlaid on skb->cb) and stores the input interface index in it;
  • orphans the skb, unless a TC BPF program has already assigned it a socket with bpf_sk_assign().

NF_HOOK() runs the PRE_ROUTING hook functions: connection tracking, destination NAT, raw and mangle tables. If they all accept the packet, it calls the okfn, ip_rcv_finish(). The list variant ip_list_rcv() does the same for a batch, split into sublists of consecutive packets with the same device and namespace. Within a sublist, a packet with the same destination address and TOS as its predecessor reuses that packet's route (a "route hint"). No hint is offered when custom policy rules exist, because rules can select on fields other than the destination, nor for broadcast, zero-network and multipath results (ip_extract_route_hint()).

ip_rcv_finish() first offers the packet to an L3 master device (l3mdev_ip_rcv()). For an interface enslaved to a VRF this switches skb->dev to the VRF device, so the lookup uses the VRF's table (§6.2). ip_rcv_finish_core() then attaches a route. If a route hint applies, it is used. Otherwise comes early demux (net.ipv4.ip_early_demux, on by default, with the per-protocol switches tcp_early_demux and udp_early_demux). It is attempted only for non-fragments that have neither a route nor a socket yet. TCP looks up an established socket by the 4-tuple; UDP handles only connected sockets with an exact 4-tuple match and multicast destinations. If a socket is found, its cached input route (sk_rx_dst) is reused when it is still valid and was learned on the same input interface (sk_rx_dst_ifindex). That skips the FIB lookup for most packets of a busy connection. The socket is also attached to the skb, so the transport receive function does not look it up again. Otherwise ip_route_input_noref() performs the full lookup described in §6.2. Since Linux 6.13 the input routing functions return an enum skb_drop_reason rather than an errno, so a routing drop shows up in the skb:kfree_skb tracepoint as, for example, IP_RPFILTER, IP_INVALID_SOURCE or IP_LOCALNET.

With the route attached, ip_rcv_finish_core() handles IP options when the header is longer than 20 bytes. ip_rcv_options() unshares the header, parses it into IPCB(skb)->opt with ip_options_compile(), and drops source-routed packets unless accept_source_route is enabled both in conf/all (off by default) and on the device. The function also counts multicast and broadcast receptions. If drop_unicast_in_l2_multicast is set, it drops a unicast IP packet that arrived in a link-layer multicast or broadcast frame, a Wi-Fi hardening against the "Hole 196" attack.

Once the skb has a route, dst_input() calls skb_dst(skb)->input. For local delivery that is ip_local_deliver(), which reassembles fragments with ip_defrag() (net/ipv4/ip_fragment.c). A partial datagram is a struct ipq in a per-namespace rhashtable, keyed by source, destination, ID, protocol and VRF. Its fragments are kept in an rbtree sorted by offset, and a datagram with overlapping fragments is discarded. The generic part, net/ipv4/inet_fragment.c, is shared with IPv6. Memory is bounded by net.ipv4.ipfrag_high_thresh (4 MB by default); above it, new fragments are dropped. (ipfrag_low_thresh has been unused since Linux 4.17 removed the eviction worker.) A datagram that is not complete within ipfrag_time (30 seconds) expires, and if its first fragment was received, the sender gets an ICMP Time Exceeded (fragment reassembly time exceeded). ipfrag_max_dist (64) drops a queue when that many fragments from the same source have arrived for other datagrams in the meantime, which protects against combining stale fragments after the 16-bit ID wraps. When connection tracking is loaded, fragments are reassembled earlier, in PRE_ROUTING at priority −400 (§9.3), because conntrack needs whole datagrams to see the ports. ip_local_deliver() then enters the LOCAL_IN hook. Raw sockets for the protocol get a clone first. inet_protos[] is a 256-entry array of struct net_protocol, indexed by the IP protocol number and filled by inet_add_protocol(). A negative return value means "resubmit as this protocol", which IPsec and some tunnel decapsulators use.

A packet is forwarded only if forwarding is enabled on the input device (net.ipv4.ip_forward, per device in conf/dev/forwarding). The route lookup checks this and installs ip_forward as input only then. ip_forward() (net/ipv4/ip_forward.c) then does the following, in order:

  • drops packets not addressed to this host at the link layer, packets that already carry a socket, and (with a warning) LRO-merged packets, which cannot be resegmented exactly; checks the IPsec forward policy;
  • hands packets with the Router Alert option to raw sockets that asked for them with IP_ROUTER_ALERT (ip_call_ra_chain());
  • drops the packet with an ICMP Time Exceeded if the TTL would expire;
  • applies IPsec forward routing (xfrm4_route_forward()) and rejects a strict source route whose next hop is not directly connected;
  • sends ICMP Fragmentation Needed if the packet is too big for the output MTU and has DF set. The MTU is the device MTU, not a learned path MTU, unless net.ipv4.ip_forward_use_pmtu is set, and a GSO packet is checked by the size of its segments;
  • unshares the header with skb_cow(), reserving headroom for the output device, and decrements the TTL with ip_decrease_ttl(), which also fixes the checksum incrementally;
  • sends an ICMP Redirect if the route lookup flagged that the packet leaves through the interface it arrived on, toward a next hop the sender could reach directly (IPSKB_DOREDIRECT);
  • maps the TOS to skb->priority (ip_forward_update_priority, on by default);
  • runs the FORWARD hook. Its okfn, ip_forward_finish(), updates options such as Record Route, clears the receive timestamp and calls dst_output(). A packet that a switch ASIC has already forwarded in hardware (skb->offload_l3_fwd_mark) is consumed there instead.

ICMP is registered in inet_protos[] like a transport protocol. icmp_rcv() (net/ipv4/icmp.c) checks the checksum and dispatches by type through icmp_pointers[]. icmp_echo() answers pings, unless icmp_echo_ignore_all is set; broadcast pings are ignored by default. Error messages (Destination Unreachable, Time Exceeded, Parameter Problem, Redirect) go to icmp_socket_deliver(). It reads the quoted header of the original datagram and calls the err_handler of that datagram's protocol (tcp_v4_err(), udp_err()), which finds the socket and reports the error to it. Fragmentation Needed is how path MTU discovery learns. TCP calls tcp_v4_mtu_reduced(), deferred to socket release if a user holds the socket lock, which records the new MTU through dst->ops->update_pmtu (§6.2) and shrinks the MSS. Errors are sent with icmp_send(). It never sends an error about an ICMP error, a non-first fragment, or a packet addressed to a broadcast or multicast address. For the types in icmp_ratemask (by default Destination Unreachable, Source Quench, Time Exceeded and Parameter Problem), two rate limits apply: a per-namespace token bucket (icmp_msgs_per_sec 1000, icmp_msgs_burst 50) and a per-destination limit in the inet_peer cache (icmp_ratelimit, 1 second), from which loopback is exempt. Fragmentation Needed is never rate-limited, because PMTU discovery depends on it. Suppressed messages are counted as OutRateLimitGlobal and OutRateLimitHost in /proc/net/snmp.

Routing: the FIB, rules and the dst cache

A route lookup takes a flow key and produces a struct fib_result. The key is a struct flowi4 (include/net/flow.h): destination and source address, input and output interface, firewall mark, DSCP (a dscp_t since Linux 6.18; earlier the TOS byte), scope, IP protocol and ports, UID, and the L3 master device. The result names the matching prefix (prefix, prefixlen), the route type and scope, the fib_info and selected nexthop (fi, nhc), and the table it came from.

Routes live in numbered tables (struct fib_table), hashed per namespace. Three exist from the start: RT_TABLE_LOCAL (255), which holds the host's own and broadcast addresses; RT_TABLE_MAIN (254), where ip route adds routes by default; and RT_TABLE_DEFAULT (253), normally empty. Policy routing rules (ip rule, net/core/fib_rules.c and net/ipv4/fib_rules.c) choose which tables to consult. fib_rules_lookup() walks the rules in priority order; the defaults are 0 → local, 32766 → main and 32767 → default. A rule can match the input or output interface, firewall mark and mask, source and destination prefix, DSCP, IP protocol, port ranges, UID range, L3 master device and tunnel ID. Its action is to look up a table, jump to another rule, do nothing, or return blackhole, unreachable or prohibit. suppress_prefixlength and suppress_ifgroup reject a table's result that is too general; for example, a VPN setup can accept anything except the default route from the main table. If a table has no match, the walk continues with the next rule, and a throw route forces the same. As long as only the default rules exist, the rules engine is bypassed. The local and main tables then share one trie, and the inline fib_lookup() in include/net/ip_fib.h consults main and then default. Adding the first rule sets fib_has_custom_rules and calls fib_unmerge(), which splits the local routes back into their own table.

VRF (virtual routing and forwarding) devices partition routing inside one namespace. They are L3 master devices (drivers/net/vrf.c, net/l3mdev/, Linux 4.4), each bound to a table. Enslaving an interface to a VRF makes l3mdev_ip_rcv() on receive and l3mdev_ip_out() on send mark the flow with the VRF. An l3mdev rule, which the VRF driver installs at priority 1000, then sends the lookup to the VRF's table. Sockets join a VRF with SO_BINDTODEVICE.

Each table is an LC-trie (level-compressed trie, after Nilsson and Karlsson) in net/ipv4/fib_trie.c. A node is a struct key_vector. key holds the prefix bits, and pos and bits say which address bits the node indexes: an internal node has 1 << bits child slots, and a node with bits 0 is a leaf holding the routes for one key. slen, the longest suffix length of any prefix below the node, lets a lookup skip subtrees that cannot match. The trie adapts its shape. After each change resize() doubles a node whose children are densely populated (inflate()) and halves a sparse one (halve()), with thresholds tuned to keep the root wide so that typical lookups touch few levels. A lookup descends from the root, using the next bits of the destination as the child index at each level, until it reaches a leaf or an empty slot. If the leaf does not match, it backtracks, clearing the lowest set bit of the child index to try progressively shorter prefixes. Lookups run entirely under RCU; updates are serialized under RTNL.

The routes of a leaf are struct fib_alias entries, one per prefix length, DSCP and metric combination. fa_slen encodes the prefix length, and fa_type, fa_dscp and tb_id give the route type, a DSCP restriction and the table. The alias also carries offload, trap and offload_failed flags, which a switch driver sets to report whether the route was programmed into hardware. The attributes proper are in a struct fib_info shared by all aliases with identical values through a hash table: protocol (kernel, boot, static, a routing daemon), scope, preferred source address (fib_prefsrc), metric (fib_priority), route metrics (MTU, advmss, initcwnd…) and the nexthops. A matching alias is accepted only if its scope and DSCP fit the key and its fib_info is not dead. For non-unicast types, fib_props[] turns the type into the lookup result: RTN_BLACKHOLE drops silently, RTN_UNREACHABLE returns −EHOSTUNREACH, RTN_PROHIBIT returns −EACCES, and RTN_THROW returns −EAGAIN, which continues the rule walk.

A route's nexthops are struct fib_nh. Their common part, struct fib_nh_common, is shared with IPv6. It holds the output device; the gateway, where nhc_gw_family allows an IPv6 gateway for an IPv4 route (Linux 5.2); scope; flags such as RTNH_F_DEAD and RTNH_F_LINKDOWN; a weight; lightweight-tunnel state; and the route caches described below. A route with several nexthops is an ECMP (multipath) route. fib_select_path() picks one by hashing the flow with fib_multipath_hash() and comparing the hash with each nexthop's upper_bound, which divides the 31-bit hash space in proportion to the weights. net.ipv4.fib_multipath_hash_policy selects the hash input: 0 (default) the addresses, 1 the 5-tuple, 2 the inner addresses of encapsulated packets, and 3 a custom field set from fib_multipath_hash_fields. fib_multipath_hash_seed (Linux 6.11) lets several routers hash identically. With fib_multipath_use_neigh set, nexthops whose neighbour entry has failed are skipped. Since Linux 5.3 nexthops can also be standalone objects (ip nexthop, net/ipv4/nexthop.c) referenced from fib_info->nh. Changing one object updates every route that uses it, and resilient nexthop groups (Linux 5.13) keep most flows on their old path when a member is added or removed.

ip_route_input_slow() builds a flowi4 from the packet and first rejects martians: a multicast, limited-broadcast or zero-network source; a zero-network destination; and loopback addresses arriving on a non-loopback device, unless route_localnet is set. A limited broadcast goes straight to local input. After fib_lookup() it branches on the route type:

  • RTN_LOCAL: the source is validated, and the result is a local-input route whose input is ip_local_deliver.
  • RTN_BROADCAST: delivered locally, unless bc_forwarding is enabled on the device, in which case the directed broadcast is forwarded.
  • RTN_UNICAST: forwarding must be enabled on the input device. Then ip_mkroute_input() selects a multipath nexthop, and __mkroute_input() validates the source and builds a forwarding route whose input is ip_forward. It sets IPSKB_DOREDIRECT when the packet would leave through the interface it arrived on.
  • A failed lookup, or a unicast destination with forwarding disabled: an unreachable route whose input, ip_error(), sends the matching ICMP Destination Unreachable (rate-limited) and drops the packet. A blackhole result drops silently.
  • Any other type, such as a multicast route for a unicast packet: dropped as a martian destination.

Martians are logged when log_martians is enabled.

Source validation is fib_validate_source(). Its main job is reverse-path filtering (rp_filter, RFC 3704): it looks up the packet's source address as a destination, with the input interface as the output. In strict mode (1) the packet is accepted only if that reverse route leaves through the interface the packet arrived on; in loose mode (2) any route back to the source will do. The effective mode is the maximum of conf/all/rp_filter and the device's value, and packets that IPsec has already decrypted are not filtered. The kernel default is 0, but most distributions enable strict or loose mode through their sysctl configuration. Failures are counted as IPReversePathFilter in /proc/net/netstat. Validation also computes the realm tag (tclassid) used by route-based classification. When filtering is off and no realms are in use, fib_validate_source() takes a fast path that skips the reverse lookup.

The route attached to a packet is a struct rtable, whose first member is the protocol-independent struct dst_entry (include/net/dst.h):

  • dev: the output device.
  • input and output: the next functions on the packet's path. For a local destination input is ip_local_deliver; for a forwarded one it is ip_forward; output is normally ip_output.
  • _metrics: per-route MTU, initial congestion window and similar values; expires; lwtstate for lightweight tunnels (MPLS, SRv6, BPF).
  • obsolete: DST_OBSOLETE_FORCE_CHK on IPv4 routes, so anyone holding a cached route must revalidate it with dst_check() (dst_ops->check(), here ipv4_dst_check()) before reuse; DST_OBSOLETE_DEAD once the route has been unlinked.
  • __rcuref: the reference count, an rcuref_t since Linux 6.4, which scales better under contention than a plain atomic; __use and lastuse record usage.
  • In struct rtable: rt_type (RTN_LOCAL, RTN_UNICAST, RTN_BROADCAST…); the generation number rt_genid; rt_is_input and rt_iif; the gateway (rt_gw_family, rt_gw4/rt_gw6) and rt_uses_gateway; and a learned path MTU (rt_pmtu, with rt_mtu_locked).

Without a global cache, the expensive part is allocating a dst_entry per lookup. That is avoided by caching the resulting rtable in the FIB nexthop: nhc_rth_input for input routes and a per-CPU nhc_pcpu_rth_output for output routes (include/net/ip_fib.h). A new route is installed with cmpxchg(), so concurrent lookups race harmlessly. Validity is tracked with a generation number instead of by walking caches. Any FIB change calls rt_cache_flush(), which bumps the namespace's IPv4 route generation (rt_genid_bump_ipv4()). rt_cache_valid() then rejects every cached route with a stale rt_genid, and the next lookup replaces it. Routes that cannot be cached in a nexthop, for instance those carrying a realm tag or those that lost the cmpxchg() race, are put on a per-CPU uncached list. When a device is unregistered, rt_flush_dev() repoints them to blackhole_netdev, so the device can go away while sockets still hold them. The input path attaches the shared route without taking a reference (skb_dst_set_noref()), which is safe because the packet is processed inside one RCU read-side section. Anything that keeps the skb beyond that, such as a socket's receive queue or backlog or a qdisc, first calls skb_dst_force() to take a real reference.

Per-destination state that differs from the route cannot live in the shared route: a path MTU learned from ICMP Fragmentation Needed, or a gateway learned from an ICMP Redirect. It goes into a nexthop exception (struct fib_nh_exception, "fnhe"). The exceptions form a 2048-bucket hash table hanging off the nexthop (nhc_exceptions), keyed by destination address. Each entry holds the PMTU, the redirect gateway, an expiry time, and its own cached input and output routes. A chain longer than a randomized depth of 5 to 9 loses its oldest entries, which limits memory and frustrates side-channel probing. ip_rt_update_pmtu() (ipv4_dst_ops.update_pmtu) creates or updates the entry. The PMTU is never set below net.ipv4.route.min_pmtu (552) and expires after mtu_expires (600 seconds), after which the original MTU applies again. Lookups for that destination find the exception (find_exception()) and return its route instead of the nexthop's. Accepting redirects is controlled by accept_redirects and secure_redirects; the latter accepts only gateways that are already default gateways. A router sends redirects if send_redirects is set, backing off exponentially. After redirect_number (9) redirects are ignored, it stops until redirect_silence passes.

Output routes are computed by ip_route_output_key_hash_rcu(), reached from ip_route_output_flow(). Output routing has more freedom than input routing. If the caller fixed a source address, it must be local; for multicast, it can also select the output device. With no destination, the packet goes to loopback. If the lookup fails but an output interface was given, the destination is assumed to be on-link. After the lookup, fib_select_path() chooses the multipath nexthop, or a live default gateway with fib_select_default() when one table has several default routes. If the caller left the source address zero, it fills it in: the route's preferred source (ip route … src), or else inet_select_addr(), which picks a primary address of the output device with suitable scope. __mkroute_output() then returns the cached per-CPU route or builds a new one. Its output is ip_output, or ip_mc_output for multicast and broadcast destinations that must also be looped back to local listeners. Finally ip_route_output_flow() passes the route through xfrm_lookup_route(), which replaces it with an IPsec bundle if a policy matches. A socket keeps the result in sk_dst_cache (§6.3), so this runs once per route change rather than per packet.

Most routes in the local table come from address configuration rather than from ip route. An interface's IPv4 state is a struct in_device (dev->ip_ptr). It holds the list of struct in_ifaddr addresses, multicast memberships, ARP parameters and the per-device ipv4_devconf sysctls. When an address is added, the inetaddr_chain notifier calls fib_add_ifaddr(). It inserts into the local table an RTN_LOCAL /32 route for the address and RTN_BROADCAST routes for the broadcast address, and into the main table a prefix route for the subnet, unless the address was added with noprefixroute. Removing the address or taking the device down deletes them (fib_del_ifaddr(), fib_disable_ip()). Nexthops through a device that has lost carrier are marked RTNH_F_LINKDOWN and are skipped if ignore_routes_with_linkdown is set.

ip route get runs a real lookup in the kernel (inet_rtm_getroute()) for a given destination, source, input interface, mark or UID, and prints the chosen route, including any exception such as a cached PMTU or redirect. /proc/net/fib_trie dumps the trie, and /proc/net/fib_triestat gives its node counts and depth. /proc/net/rt_cache remains only as an empty compatibility file; /proc/net/stat/rt_cache holds per-CPU lookup statistics. The fib:fib_table_lookup and fib6:fib6_table_lookup tracepoints report every lookup with its key and result. Hardware offload uses the same changes: a switch driver registers with register_fib_notifier() (net/core/fib_notifier.c), receives a replay of the existing FIB followed by every addition and deletion, programs the routes into the ASIC, and reports back through the alias flags described above.

Sending: ip_queue_xmit to the neighbour

A TCP segment reaches IP through icsk->icsk_af_ops->queue_xmit, which for IPv4 is ip_queue_xmit(); __ip_queue_xmit() does the work. Its first step is the socket's cached route. __sk_dst_check() validates sk->sk_dst_cache. Only if that fails does it call ip_route_output_flow() and store the result with sk_setup_caps(), which also copies the device's offload features into sk_route_caps so that TCP knows whether it may build TSO packets. A connected socket thus does one route lookup per route change, not per packet. The function then pushes and fills the IP header. DF follows the socket's PMTU discovery mode (IP_MTU_DISCOVER). The default is IP_PMTUDISC_WANT, or IP_PMTUDISC_DONT if net.ipv4.ip_no_pmtu_disc is set, so TCP segments normally carry DF. The TTL is the socket's IP_TTL, or else the route's hop-limit metric, which defaults to net.ipv4.ip_default_ttl (64). ip_options_build() writes any options set with IP_OPTIONS. The 16-bit ID comes from ip_select_ident_segs(). A connected socket uses its own counter (inet_id), advanced by the number of GSO segments so that each segment the NIC produces gets a distinct ID. A DF packet from an unconnected socket gets ID 0. Anything else draws from an array of counters indexed by a SipHash of the addresses and protocol (__ip_select_ident()), so that IDs neither repeat quickly toward one destination nor expose a global counter. The function copies the socket's priority and mark into the skb and calls ip_local_out(). If no route can be found, it counts OutNoRoutes and returns −EHOSTUNREACH. UDP and raw sockets build headers through ip_make_skb()/ip_append_data() and route per sendmsg() unless connected, but they join the same path at ip_local_out().

From there the chain is:

  1. __ip_local_out() sets the total length (iph_set_totlen(), 0 for a BIG TCP packet over 64 KB) and the header checksum, lets an L3 master device such as a VRF take the packet (l3mdev_ip_out()), and runs the LOCAL_OUT hook;
  2. dst_output() calls dst->output, i.e. ip_output();
  3. ip_output() runs the POST_ROUTING hook, skipped for packets that were rerouted by IPsec. For multicast and broadcast routes that loop back to local listeners, ip_mc_output() takes its place and passes a copy to dev_loopback_xmit();
  4. ip_finish_output() runs cgroup egress BPF programs;
  5. __ip_finish_output() takes the MTU from ip_skb_dst_mtu() (the device MTU or the learned path MTU, depending on the socket's PMTU mode) and chooses among three cases. A GSO packet passes if each of its segments will fit (skb_gso_validate_network_len()). Otherwise, for example when forwarding a GRO-merged packet without DF to a link with a smaller MTU, it is segmented in software and each segment is fragmented as needed. A packet longer than the MTU, or one carrying IPCB(skb)->frag_max_size because conntrack reassembled it from fragments, goes to ip_fragment(). That function refuses with ICMP Fragmentation Needed if DF is set. Otherwise ip_do_fragment() splits the packet, never into pieces larger than the original fragments; it reuses an existing frag list as the fragments when the pieces already have the right sizes. Anything else goes to ip_finish_output2().

ip_finish_output2() makes sure there is headroom for the link-layer header (skb_expand_head()). A lightweight tunnel with its own transmit function takes the packet here (lwtunnel_xmit_redirect()). Otherwise the function finds the next hop's neighbour entry (struct neighbour, include/net/neighbour.h) with ip_neigh_for_gw(). The next hop is the route's gateway if it has one, and otherwise the packet's own destination (an on-link route). The entry is created if it does not exist; if that fails, the packet is dropped with the NEIGH_CREATEFAIL reason. When an IPv4 route uses an IPv6 gateway, the entry belongs to nd_tbl, and neigh_output() is told to skip the cached header, because that header carries the IPv6 EtherType:

/* include/net/neighbour.h */
static inline int neigh_output(struct neighbour *n, struct sk_buff *skb,
			       bool skip_cache)
{
	const struct hh_cache *hh = &n->hh;

	/* n->nud_state and hh->hh_len could be changed under us.
	 * neigh_hh_output() is taking care of the race later.
	 */
	if (!skip_cache &&
	    (READ_ONCE(n->nud_state) & NUD_CONNECTED) &&
	    READ_ONCE(hh->hh_len))
		return neigh_hh_output(hh, skb);

	return READ_ONCE(n->output)(n, skb);
}

The neighbour subsystem (net/core/neighbour.c) is generic: ARP (arp_tbl) and IPv6 Neighbour Discovery (nd_tbl) are two instances of struct neigh_table. Each entry runs a state machine of NUD_* states: INCOMPLETE while resolving; REACHABLE when recently confirmed; STALE, DELAY and PROBE as confirmation ages; FAILED; and PERMANENT/NOARP for static entries. neigh_timer_handler() drives the transitions. In a NUD_CONNECTED state with a cached hardware header, neigh_hh_output() copies the prebuilt Ethernet header in front of the packet under a seqlock and calls dev_queue_xmit(). Otherwise n->output is neigh_resolve_output(). It calls __neigh_event_send(), which queues the packet on arp_queue, bounded by unres_qlen_bytes, and has arp_solicit() or ndisc_solicit() send a request. The queued packets are transmitted when the reply arrives. TCP confirms reachability when ACKs show forward progress: it sets sk_dst_pending_confirm, and sock_confirm_neigh() in ip_finish_output2() applies it at the next transmission. Applications can do the same with MSG_CONFIRM. A busy neighbour entry therefore rarely needs to be re-probed.

A struct neighbour is keyed by device and next-hop address (primary_key[]) and lives in the table's RCU hash. Besides nud_state and its timer, it holds the hardware address ha[] under a seqlock (ha_lock), the cached header hh, the current output function, the queue of unresolved packets, the probe count, and three timestamps: confirmed (last proof of reachability), updated (last state change) and used. Its behaviour is set per device by struct neigh_parms, exposed as net.ipv4.neigh.dev.*:

  • base_reachable_time_ms (30 seconds), randomized to between half and one and a half times that value so that entries do not expire in step;
  • delay_first_probe_time (5 seconds), the time spent in DELAY;
  • ucast_solicit and mcast_solicit, 3 probes each;
  • unres_qlen_bytes, the per-entry queue limit, which defaults to SK_WMEM_DEFAULT (about 200 KB).

Garbage collection is bounded by three table-wide thresholds. Below gc_thresh1 (128 entries) the periodic worker does nothing. Above gc_thresh2 (512), allocating an entry first runs a synchronous neigh_forced_gc() if none ran in the last 5 seconds. At gc_thresh3 (1024) a forced collection always runs, and if it frees nothing, the allocation fails with "neighbor table overflow!". The periodic worker removes unreferenced entries that are FAILED or unused for gc_stale_time (60 seconds). Permanent entries and externally learned ones (NTF_EXT_LEARNED, from a switch driver or an EVPN control plane, for example) are exempt from collection and do not count toward the thresholds. Since Linux 5.16 an entry can be managed (NTF_MANAGED): the kernel keeps it resolved even without traffic, which helps hardware-offloaded next hops. If a queued packet cannot be delivered because resolution failed, neigh_ops->error_report (arp_error_report()) reports a link failure on its route, and the sender gets an ICMP Host Unreachable. ARP itself (net/ipv4/arp.c) answers requests in arp_process(), subject to per-device policies: arp_ignore (which local addresses to answer for), arp_announce (which source address to use in requests), arp_filter, proxy_arp, and arp_accept (whether gratuitous ARP may create entries). ip neigh shows the table, and the neigh: tracepoints (neigh_create, neigh_update, neigh_timer_handler and others) follow state changes.

IPv6

IPv6 is implemented in net/ipv6/ as a parallel stack with the same structure. The receive handler is registered by EtherType, there are the same five netfilter hooks, a protocol table indexed by next-header, routes are dst_entry subclasses, and neighbour resolution uses the shared neighbour code. Table 22-8 maps the functions. Two differences matter. Routers never fragment IPv6 packets: ip6_forward() sends ICMPv6 Packet Too Big instead, and only the sender fragments, via ip6_fragment(). And the IPv6 FIB is a radix tree of struct fib6_node (net/ipv6/ip6_fib.c) rather than an LC-trie, with learned PMTUs and redirects kept as per-route exceptions (struct rt6_exception). A socket created with AF_INET6 can also carry IPv4 traffic using v4-mapped addresses. TCP then switches the socket's icsk_af_ops to ipv6_mapped, which points at the IPv4 functions.

The IPv6 receive path differs mainly in header parsing. ip6_rcv_core() validates the fixed 40-byte header and, if the next header is Hop-by-Hop Options, parses those options at once (ipv6_parse_hopopts()), because every router must examine them. The other extension headers (routing, fragment, destination options) are registered in inet6_protos[] like transport protocols, so ip6_protocol_deliver_rcu() walks the chain by resubmitting with each header's next-header value. Reassembly (net/ipv6/reassembly.c) uses the shared fragment code. In the FIB, routes are struct fib6_info entries, separated since Linux 4.18 from the rt6_info dst objects attached to packets. As in IPv4, routes are cached in the nexthop, here as a per-CPU rt6i_pcpu copy in each struct fib6_nh, and per-destination PMTUs and redirects live in a 1024-bucket exception table hanging off the nexthop. Validation uses serial numbers instead of a generation count. Every change bumps fn_sernum on the tree nodes up to the root; a cached dst remembers the value as a cookie, and ip6_dst_check() compares the two. Addresses are managed by net/ipv6/addrconf.c. Every interface gets a link-local address, and global addresses can be configured by SLAAC from router advertisements. Each new address stays tentative until Duplicate Address Detection completes, and privacy extensions (RFC 8981) add temporary addresses. IPv6 BIG TCP changed in Linux 7.0. A packet larger than 64 KB used to carry a Hop-by-Hop Jumbo Payload option, which the stack inserted and drivers had to strip. It now simply has payload_len 0, and the length comes from the skb, as with IPv4.

The Transmit Path

On the way out, a packet leaves the protocol layer through dev_queue_xmit(). Before it reaches the driver, the device layer selects a hardware TX queue, passes the packet through that queue's queuing discipline, segments and checksums it in software if the hardware cannot, and limits how much data sits in the NIC ring. In 2.6.11 a device had a single queue and a single hard_start_xmit method behind a pfifo_fast qdisc. The modern path is multi-queue throughout, mostly lockless, and tuned to keep queues short rather than full. Whatever happens to the packet, dev_queue_xmit() consumes the skb and reports only a status: NET_XMIT_SUCCESS, NET_XMIT_DROP, NET_XMIT_CN (the qdisc is congested and dropped a packet, not necessarily this one) or a negative errno.

__dev_queue_xmit and queue selection

Figure 22-7 shows the transmit path and the completion loop that keeps it moving. __dev_queue_xmit() (net/core/dev.c) runs with bottom halves disabled. That keeps the softirq-context TX path off the same CPU and serves as the RCU read-side section for the device's qdisc pointers. Abridged:

/* net/core/dev.c (__dev_queue_xmit, abridged) */
	rcu_read_lock_bh();

	skb_update_prio(skb);

	tcx_set_ingress(skb, false);

The elided top of the function prepares the packet for accounting. skb_reset_mac_header() marks the start of the link-layer header that the neighbour layer has just built. If the socket asked for a scheduling timestamp, __skb_tstamp_tx() reports SCM_TSTAMP_SCHED here (§3.3). qdisc_pkt_len_segs_init() stores in the qdisc control block the length a qdisc should charge for the packet. For a GSO packet that is the payload plus one copy of the headers per segment, so a 64 KB TSO packet is charged as the roughly 45 frames it becomes on the wire. Since Linux 6.19 it also records the segment count, and it drops a GSO packet whose header lengths do not add up (SKB_DROP_REASON_SKB_BAD_GSO), a defence against malformed packets injected through tap devices or packet sockets. Inside the RCU section, skb_update_prio() applies the net_prio cgroup's per-device priority map to packets whose skb->priority is still 0.

The egress hooks are the mirror of the ingress hooks in §5.4. They run netfilter's per-device egress chain and tc egress (tcx BPF programs and clsact filters), both before queue selection, so a program can still redirect the packet or pick its queue. A tc skbedit queue_mapping action at egress fixes the queue outright, and __dev_queue_xmit() then skips queue selection. Next the route reference is settled. Most drivers never look at skb_dst(), so for a device with IFF_XMIT_DST_RELEASE the dst is released here, before the packet can wait in a qdisc. A device that needs it (it calls netif_keep_dst()) gets a counted reference instead (skb_dst_force()), because the RCU-protected one is valid only until rcu_read_unlock_bh(). netdev_core_pick_tx() then records the sending CPU in skb->sender_cpu and, if more than one TX queue is in use, chooses the queue in one of two ways:

  • A driver with its own policy implements ndo_select_queue. It can still call netdev_pick_tx() for ordinary traffic, and dev_pick_tx_zero() is a ready-made policy that always answers queue 0.
  • Otherwise netdev_pick_tx() reuses the queue cached in the socket (sk_tx_queue_get()). The cached queue is abandoned if its index is no longer valid, or if the flow can move without risk of reordering. TCP signals that by setting skb->ooo_okay when none of the socket's earlier packets is still in a qdisc or ring, or when nothing awaits acknowledgement. Since Linux 6.19 a cached mapping also expires after net.core.txq_reselection_ms (1000 ms by default; 0 disables it), so a flow that never goes idle can still be rebalanced. Failing the cache, it consults XPS (Transmit Packet Steering, Linux 2.6.38). XPS maps the RX queue the flow arrives on (xps_rxqs, tried first) or else the sending CPU (xps_cpus) to a set of TX queues, and the flow hash picks one queue from the set. TX completion interrupts thus land on the CPU that sent the data. Without XPS, skb_tx_hash() spreads flows over the queues by hash. With mqprio traffic classes it restricts the choice to the queues of the packet's class (skb->priority → prio_tc_map → tc_to_txq), and a forwarded packet that still records its RX queue is sent on the TX queue with the same index. The result is cached in the socket only for full sockets with a cached route.

Pinning a socket's queue matters because packets of one flow on different TX queues can be reordered on the wire.

Virtual devices such as loopback, veth, VLAN, VXLAN and most tunnels have no qdisc (noqueue, signalled by IFF_NO_QUEUE). For them, __dev_queue_xmit() validates the packet and calls the driver directly under the TX queue lock. Two checks catch a stack of virtual devices that loops back on itself: the TX lock already being held by this CPU (netif_tx_owned()), and a nesting counter (per CPU, or per task on PREEMPT_RT) capped at XMIT_RECURSION_LIMIT (8). Either one logs "Dead loop on virtual device" and drops the packet (SKB_DROP_REASON_RECURSION_LIMIT) rather than overflowing the stack. A virtual driver has no queue to fall back on: if it reports busy or its queue is stopped, the kernel logs "Virtual device %s asks to queue packet!" and the packet is dropped.

The qdisc layer

A queuing discipline (struct Qdisc, include/net/sch_generic.h) is an object with enqueue and dequeue methods, a flags word, a queue length limit and statistics, plus private data for the algorithm. It is attached to a netdev_queue. Qdiscs can be classful and contain child qdiscs (HTB, for example), and the tc tool configures them via rtnetlink. When a device is activated without a configured qdisc, attach_default_qdiscs() gives a multi-queue device the mq root qdisc, which simply has one child per hardware TX queue. A single-queue device gets the default qdisc directly as its root (flagged TCQ_F_ONETXQUEUE), and a device with IFF_NO_QUEUE gets noqueue. Each mq child is an instance of the default qdisc, selected by net.core.default_qdisc. If the default cannot be created, the kernel warns and falls back to noqueue. The device's tx_queue_len (1000 for Ethernet) is the packet limit that pfifo_fast and the plain FIFOs inherit. The kernel's built-in default is pfifo_fast unless CONFIG_NET_SCH_DEFAULT chooses another. systemd sets the sysctl to fq_codel at boot, so that is what most distributions actually run. Because the qdisc lock was a classic multi-CPU bottleneck, __dev_xmit_skb() has three ways in:

  • A TCQ_F_NOLOCK qdisc (pfifo_fast) is enqueued without the root lock. qdisc_run_begin() uses a per-qdisc spinlock taken with trylock, so exactly one CPU dequeues at a time while others keep enqueueing. A CPU that loses the trylock sets __QDISC_STATE_MISSED and tries once more. The owner tests that bit in qdisc_run_end() and reschedules the qdisc, so a packet enqueued during the hand-over is never stranded.
  • A locked qdisc does not make each CPU contend for the lock. Since Linux 6.19, packets are first pushed onto a lockless defer_list (an llist). Only the CPU that found the list empty takes the root lock. It detaches the whole list with llist_del_all(), reverses it to restore arrival order, and enqueues everyone's packets in one batch; if the qdisc has meanwhile been deactivated, it drops them. The list is bounded by net.core.qdisc_max_burst (1000), and packets beyond that are dropped with SKB_DROP_REASON_QDISC_BURST_DROP. Ownership of the dequeue loop is the q->running flag, tested under the root lock.
  • Either way, a work-conserving qdisc (TCQ_F_CAN_BYPASS) that is empty and idle is bypassed: sch_direct_xmit() sends the packet immediately, without enqueueing it at all. With the defer_list, this happens only when the batch holds a single packet.

Two more 6.19 changes trim time spent under the root lock. __netif_schedule() returns at once if the defer_list is not empty, because a CPU inside __dev_xmit_skb() is then certain to run the queue itself. The CoDel family (codel, fq_codel, cake) drops packets during dequeue. Those qdiscs set TCQ_F_DEQUEUE_DROPS and park the victims on q->to_free, which qdisc_run_end() hands back so they are freed after the lock is released.

Once a CPU owns the qdisc, __qdisc_run() dequeues and transmits until the qdisc is empty or a quota is exhausted:

/* net/sched/sch_generic.c */
void __qdisc_run(struct Qdisc *q)
{
	int quota = READ_ONCE(net_hotdata.dev_tx_weight);
	int packets;

	while (qdisc_restart(q, &packets, quota)) {
		quota -= packets;
		if (quota <= 0) {
			if (q->flags & TCQ_F_NOLOCK)
				set_bit(__QDISC_STATE_MISSED, &q->state);
			else
				__netif_schedule(q);

			break;
		}
	}
}

The quota (dev_weight × dev_weight_tx_bias, 64 packets by default) stops one task from spending unbounded time transmitting other tasks' packets from inside its sendmsg(). __netif_schedule() puts the qdisc on the per-CPU output_queue and raises NET_TX_SOFTIRQ; the __QDISC_STATE_SCHED bit keeps a qdisc on at most one CPU's list. net_tx_action() first frees the completion_queue: skbs that drivers released from hard-IRQ context with dev_kfree_skb_irq(), where they cannot be freed directly. It then detaches the output_queue with interrupts disabled. For each qdisc it takes the root lock (locked qdiscs only), clears SCHED and calls qdisc_run(). A lockless qdisc that has been deactivated is skipped.

qdisc_restart() gets its packets from dequeue_skb(), which looks in three places in order:

  1. the gso_skb slot, holding a packet the driver refused earlier; it is already validated and waits until its TX queue runs again;
  2. skb_bad_txq, a packet parked because it was dequeued for a different TX queue than the one being served;
  3. the qdisc's own dequeue method.

A qdisc that feeds a single TX queue then keeps dequeueing into a list (try_bulk_dequeue_skb()) until the bytes reach what BQL says the ring can take (qdisc_avail_bulklimit()). Any other qdisc collects at most eight more packets, and only for the same queue. qdisc_restart() then calls sch_direct_xmit(). That function drops the root lock and calls validate_xmit_skb_list() (§7.4) with neither lock held, so software segmentation and checksumming do not stall CPUs enqueueing on the same qdisc. It then takes the TX queue lock (HARD_TX_LOCK, skipped for lockless devices that set dev->lltx) and calls dev_hard_start_xmit(), unless the queue is stopped or frozen (netif_tx_lock() freezes all queues during reconfiguration). If the queue is stopped or the driver returns NETDEV_TX_BUSY, the packet is requeued in the qdisc's gso_skb slot. Any other failure code is a driver bug and logs "BUG dev code N".

dev_hard_start_xmit() walks the list of segments. For each one, xmit_one() delivers a copy to taps (dev_queue_xmit_nit(), which is where tcpdump sees outgoing packets) and calls netdev_start_xmit() → ndo_start_xmit. On NETDEV_TX_OK it stamps the queue's trans_start. The tracepoints net:net_dev_queue, net:net_dev_start_xmit and net:net_dev_xmit mark entry to the device layer and each driver call, and qdisc:qdisc_enqueue/qdisc:qdisc_dequeue mark qdisc traffic. The more argument, visible to the driver through netdev_xmit_more(), says another packet follows immediately. The driver can then post descriptors without writing the NIC's doorbell register, and write it once for the whole batch. Just before the doorbell, the driver calls skb_tx_timestamp(), the software SCM_TSTAMP_SND point (§3.3). A driver whose ring is nearly full stops the queue with netif_tx_stop_queue() (the __QUEUE_STATE_DRV_XOFF bit).

A queue that stays stopped means the NIC has stopped completing. For a driver that implements ndo_tx_timeout, dev_watchdog() is a per-device timer that runs every watchdog_timeo (5 s unless the driver sets another value). While the device is present, running and has carrier, it looks for a TX queue stopped by the driver or by BQL whose trans_start is older than watchdog_timeo. For the first one it finds, it increments the queue's tx_timeout counter in sysfs and fires the net_dev_xmit_timeout tracepoint. It also logs "NETDEV WATCHDOG: CPU: C: transmit queue Q timed out T ms" and calls ndo_tx_timeout(dev, Q) with the queues frozen. Most drivers respond by resetting the hardware.

Byte Queue Limits and TX completion

A qdisc can only manage what is queued in it. If the driver's ring holds thousands of descriptors, packets sit there in FIFO order, beyond the reach of fq_codel's dropping or fq's scheduling. The latency this adds is called bufferbloat. Byte Queue Limits (BQL, Linux 3.3, lib/dynamic_queue_limits.c) bound the bytes outstanding in each hardware queue to roughly what the NIC can transmit between two completion interrupts. Packets beyond that wait in the qdisc instead of the ring. The driver reports bytes as it posts and reclaims them:

/* include/linux/netdevice.h */
static inline void netdev_tx_sent_queue(struct netdev_queue *dev_queue,
					unsigned int bytes)
{
#ifdef CONFIG_BQL
	dql_queued(&dev_queue->dql, bytes);

	if (likely(dql_avail(&dev_queue->dql) >= 0))
		return;
	...
	set_bit(__QUEUE_STATE_STACK_XOFF, &dev_queue->state);

	/*
	 * The XOFF flag must be set before checking the dql_avail below,
	 * because in netdev_tx_completed_queue we update the dql_completed
	 * before checking the XOFF flag.
	 */
	smp_mb__after_atomic();

	/* check again in case another CPU has just made room avail */
	if (unlikely(dql_avail(&dev_queue->dql) >= 0))
		clear_bit(__QUEUE_STATE_STACK_XOFF, &dev_queue->state);
#endif
}

A driver that batches with more calls __netdev_tx_sent_queue(txq, bytes, netdev_xmit_more()) instead. While more packets follow, it only accounts the bytes. Its return value tells the driver whether to ring the doorbell now: always for the last packet of a batch, and early if the queue has just been stopped, since no further packet would come to flush the batch.

struct dql (include/linux/dynamic_queue_limits.h) is split across cache lines between its two writers. The transmit side owns num_queued and adj_limit, which is limit plus num_completed, so the hot test dql_avail() is one subtraction, adj_limit − num_queued. The completion side owns limit, num_completed and the history that dql_completed() uses to adapt the limit once per completion batch:

  • Starvation. If the queue was over its limit in the previous interval and has now run completely dry, the NIC went idle while the stack was holding data back. The limit grows by the bytes completed beyond the previous queue total, plus the previous overshoot.
  • Slack. If the queue stayed busy through the whole interval, the excess beyond what was needed (roughly the limit minus twice the bytes just completed) is slack. The lowest slack seen is remembered, and once per hold_time (1 s, from dql_init(&queue->dql, HZ)) the limit shrinks by that amount.

The result is clamped between limit_min and limit_max. When the limit is exceeded, the queue's STACK_XOFF bit stops further dequeues. The limits and the current in-flight count appear under /sys/class/net/dev/queues/tx-N/byte_queue_limits/ (limit, limit_min, limit_max, hold_time, inflight, and stall detection in stall_thrs/stall_cnt/stall_max).

Because BQL sees both sides of the ring, it can also spot a NIC that has stopped completing (Linux 6.9). dql_queued() marks the jiffies at which data was queued in a small bitmap ring (history). If stall_thrs is set, dql_completed() looks back when completions resume. If data was queued early in a gap of at least stall_thrs with no completion, it counts a stall in stall_cnt, keeps the longest in stall_max, and fires the dql_stall_detected tracepoint. Unlike the watchdog, this catches stalls too short to trigger a reset.

Completion is the other half of Figure 22-7. The NIC raises an interrupt, normally the same vector and NAPI instance as the paired RX queue. The poll function then does the following:

  1. walks the TX ring for descriptors the hardware has finished;
  2. unmaps their DMA buffers;
  3. frees the skbs with napi_consume_skb(), which recycles them into the per-CPU skb cache. Since Linux 6.19 an skb allocated on another CPU is handed back to that CPU with skb_attempt_defer_free() instead. With a budget of 0 (netpoll) the function falls back to dev_consume_skb_any();
  4. reports the totals with netdev_tx_completed_queue(), which clears STACK_XOFF and reschedules the qdisc once there is room;
  5. wakes a queue it had stopped itself with netif_tx_wake_queue().

The helpers in include/net/netdev_queues.h (netif_txq_maybe_stop(), netif_txq_completed_wake() and their netif_subqueue_* variants) package the subtle barriers between stopping and waking. The transmit side stops the queue when free descriptors fall below a stop threshold, issues a full barrier, and re-checks. If the completion side made room in the meantime, it restarts the queue. The completion side reports to BQL, which implies the matching barrier, and wakes the queue only once free descriptors reach a start threshold. That threshold is usually higher than the stop one, so the queue is not woken for a single free slot. Either wake-up path ends in __netif_schedule(), and NET_TX_SOFTIRQ drains the qdisc into the freed ring space. On a busy link the transmit path is thus clocked by completions, not by the senders.

GSO and TSO

Like GRO on receive, segmentation offload amortizes per-packet costs on transmit. TCP builds packets much larger than the MTU, up to 64 KB, or more with "BIG TCP" (IPv6 in Linux 5.19, IPv4 in 6.3). The limits are per device. gso_max_size (IPv6) and gso_ipv4_max_size bound what the stack builds. Both are 64 KB by default, and the administrator can raise them up to tso_max_size. The driver raises that limit to what its hardware accepts, at most GSO_MAX_SIZE (8 × 65535 bytes, about 512 KB). gso_max_segs (65535 by default) bounds the number of segments. Each such skb is marked with gso_size (the MSS), gso_segs and a gso_type such as SKB_GSO_TCPV4, SKB_GSO_TCPV6 or SKB_GSO_UDP_L4. Modifier bits qualify the type: SKB_GSO_TCP_ECN and SKB_GSO_TCP_ACCECN (Linux 6.15) say how the CWR flag is spread over the segments, and SKB_GSO_DODGY marks metadata from an untrusted source (tap, packet sockets, virtio) that must be re-checked. The whole stack below TCP, including netfilter and the qdisc, handles one skb instead of dozens. At the last moment, validate_xmit_skb() decides who splits it:

  • If the device advertises the matching feature (NETIF_F_TSO, NETIF_F_TSO6, NETIF_F_GSO_UDP_L4…) for this packet, the NIC segments it: TSO. It replicates and fixes up the headers and computes every checksum.
  • Otherwise skb_gso_segment() (net/core/gso.c) does it in software. It calls the gso_segment callbacks layer by layer, inet_gso_segment() → tcp4_gso_segment() → tcp_gso_segment(), which use skb_segment() to produce a list of MTU-sized skbs. Mostly these share the original's page frags instead of copying. This GSO step is still worthwhile without hardware support, because it happens once, as late as possible.

The full sequence in validate_xmit_skb() is:

  1. Drop an skb with unreadable devmem frags (§10.2), unless the device supports netmem TX (Linux 6.16) and is the device the memory is bound to.
  2. Compute the features that apply to this packet with netif_skb_features(). Within it, gso_features_check() withdraws GSO offload from a packet with more segments than gso_max_segs or larger than the device's GSO limit. It also removes partial-GSO features unless the packet asks for them, IPv4 ID mangling for a packet that may be fragmented (DF clear), and IPv6 checksum and TSO offload for a packet with IPv6 extension headers. The driver's ndo_features_check then applies its own per-packet veto.
  3. Insert the VLAN tag into the packet data if the device cannot insert it in hardware (validate_xmit_vlan()).
  4. Let the socket transform the packet (sk_validate_xmit_skb()). kTLS device offload uses this hook to fall back to software encryption when the packet is leaving through a device that does not hold the crypto state. PSP, which has no software implementation, uses it to drop such a packet (§10.4). A packet marked for device encryption with no such socket is dropped rather than sent in clear.
  5. Segment in software if netif_needs_gso() says the device cannot. Otherwise, linearize the skb if the device cannot gather its frags and, for a CHECKSUM_PARTIAL skb whose protocol the device cannot checksum, compute the checksum with skb_csum_hwoffload_help().
  6. Pass IPsec packets to the xfrm offload code (validate_xmit_xfrm()). While earlier packets still wait in the per-CPU xfrm backlog, it sets the again flag, and the caller requeues the packet to keep the order.

Any failure frees the packet and counts it in the device's tx_dropped. Tunnels use SKB_GSO_PARTIAL and the encapsulation bit so that a NIC that can segment only the inner TCP packet can still offload them. The stack fixes up the outer headers once, as for a single segment, and the NIC replicates them unchanged. UDP fraglist GSO (SKB_GSO_FRAGLIST) lets a forwarding host re-emit packets that GRO chained on frag_list without copying them. skb_segment_list() unlinks the original skbs and rewrites only their headers.

TCP and UDP

The transport protocols are the largest part of the IPv4 directory. TCP alone (net/ipv4/tcp*.c) is about 37,000 lines in 7.0.12, and an implementation-level treatment of it would fill a book. Almost all of that code is independent of the address family. tcp_ipv4.c and net/ipv6/tcp_ipv6.c hold only the lookup, connect, checksum and SYN-handling glue, and IPv6 reuses the rest unchanged. This section names the IPv4 entry points. What the rest of the kernel sees is TCP's data structures, its send and receive paths, and a few mechanisms — pacing, small queues, pluggable congestion control, zero-copy — through which TCP interacts with qdiscs, timers and memory management. UDP is far simpler: it has no connection state and no retransmission, and each datagram is queued whole to the receiving socket.

TCP sockets and connection setup

Every struct proto records the size of its socket objects (§2.3), and for tcp_prot that obj_size is sizeof(struct tcp_sock). Figure 22-8 shows the nesting that makes this work. Each structure embeds the previous one as its first member, so a single allocation is, depending on the pointer type, a sock, an inet_sock, an inet_connection_sock or a tcp_sock. The accessors inet_sk(), inet_csk() and tcp_sk() are casts. The middle layer, inet_connection_sock (include/net/inet_connection_sock.h), holds what any connection-oriented INET protocol needs:

  • the accept queue;
  • the retransmission timeout state (icsk_rto);
  • the delayed-ACK and keepalive timers;
  • three operation tables: the congestion control in use (icsk_ca_ops), the address-family operations (icsk_af_ops, whose queue_xmit is ip_queue_xmit or inet6_csk_xmit), and an optional upper-layer protocol (icsk_ulp_ops, used by kTLS and MPTCP).

The retransmission timer itself has been sk->tcp_retransmit_timer in struct sock since Linux 6.19. Before that it was icsk_retransmit_timer.

Every TCP socket on the host is found through one struct inet_hashinfo (tcp_hashinfo, include/net/inet_hashtables.h), which has four tables:

  • ehash, keyed by the full 4-tuple, holds established sockets, request socks and TIME_WAIT sockets. Lookups are lockless under RCU over hlist_nulls chains, and insertions take a per-bucket spinlock from ehash_locks.
  • bhash, keyed by local port, and bhash2 (Linux 6.1), keyed by port and local address, record bound ports. They are used for the conflict checks of bind() and connect().
  • lhash2 holds listeners, keyed by port and local address.

__inet_lookup_skb() tries ehash first and falls back to lhash2. By default all network namespaces share one ehash. Since Linux 6.1, net.ipv4.tcp_child_ehash_entries gives a namespace created afterwards a private one, so a container cannot fill the host's table.

An active open starts in tcp_v4_connect(). ip_route_connect() routes to the destination and fills in the source address if the socket has none. The socket moves to SYN_SENT, and inet_hash_connect() picks a local port and inserts the socket into ehash in one step. __inet_hash_connect() starts at an offset in net.ipv4.ip_local_port_range (32768–60999). Following RFC 6056, the offset comes from a keyed hash of the addresses and destination port plus a perturbation table, so ports are hard to predict. The search tries even ports first, stepping by two, and odd ports second. bind() to port 0 (inet_csk_get_port()) prefers odd ports, so the two kinds of users rarely compete. A per-socket IP_LOCAL_PORT_RANGE (Linux 6.3) narrows the range and drops the parity split. For each candidate the function checks the bind tables and ehash. A TIME_WAIT socket that already holds the 4-tuple may be taken over (tcp_twsk_unique()), as described below. secure_tcp_seq_and_ts_off() derives the initial sequence number and a per-connection timestamp offset from a keyed SipHash of the 4-tuple plus a clock (RFC 6528). tcp_connect() then:

  1. builds the SYN with its options — MSS, window scale, SACK-permitted, timestamps, and the ECN or AccECN request;
  2. puts the SYN on the retransmit queue and transmits it;
  3. arms the retransmission timer with the initial RTO of 1 s.

An unanswered SYN is retransmitted net.ipv4.tcp_syn_retries (6) times, plus tcp_syn_linear_timeouts (4, Linux 6.5) extra times. Those first retransmissions are spaced linearly, 1 s apart, before exponential backoff begins. With the defaults the last SYN leaves after 67 s, and connect() fails with ETIMEDOUT after 131 s.

Passive opens use two kinds of objects (top right of Figure 22-8). When a SYN reaches a listener, tcp_conn_request() does not create a full socket. It allocates a small struct request_sock (inet_reqsk_alloc()) with state TCP_NEW_SYN_RECV, inserts it into the global established-connections hash (inet_csk_reqsk_queue_hash_add() → inet_ehash_insert()), and answers with a SYN-ACK. The request's own timer, reqsk_timer_handler(), retransmits the SYN-ACK. This "SYN queue" is therefore not a list but a count of request socks per listener. Before Linux 4.1 request socks lived in a per-listener hash table under the listener's lock. That move, and processing a listener's packets without the socket spinlock (Linux 4.4), let SYNs for one listener be processed on all CPUs in parallel.

When the final ACK arrives, the ehash lookup in tcp_v4_rcv() finds the request sock. tcp_check_req() validates the ACK and calls icsk_af_ops->syn_recv_sock (tcp_v4_syn_recv_sock()), which clones the listener into a full child socket. inet_csk_complete_hashdance() then replaces the request sock in the hash with the child and appends the child to the listener's icsk_accept_queue. accept() reaches inet_csk_accept(), which sleeps until the queue is non-empty and dequeues one child. If the listener is closed while it still has queued connections, and it belongs to an SO_REUSEPORT group, net.ipv4.tcp_migrate_req (Linux 5.14, off by default) moves its request socks and children to another member of the group. Otherwise they are aborted.

Two limits apply. The accept queue is bounded by the listen() backlog, capped at net.core.somaxconn. When it is full, tcp_conn_request() drops the SYN outright and counts ListenOverflows (visible as TcpExtListenOverflows in nstat), relying on the client to retransmit. The number of request socks is bounded by the same backlog and by net.ipv4.tcp_max_syn_backlog. Without SYN cookies, the last quarter of that limit is reserved for peers that TCP has already seen complete a connection (tcp_peer_is_proven()). If the request count reaches the backlog, or always if net.ipv4.tcp_syncookies is 2, tcp_conn_request() switches to SYN cookies. It then keeps no state: it encodes the connection parameters into the SYN-ACK's initial sequence number, and cookie_v4_check() reconstructs the request from the returning ACK. A SYN flood thus cannot exhaust memory. The price is fidelity. The MSS survives only as an index into a four-entry table (msstab), and window scaling, SACK and ECN survive only if the client uses timestamps, because those bits are hidden in the timestamp value (cookie_init_timestamp()).

TCP Fast Open (net.ipv4.tcp_fastopen) lets a client that holds a cookie from an earlier connection send data in the SYN, which the server can deliver before the handshake completes. The default, 1, enables only the client side. A server needs bit 0x2 or the TCP_FASTOPEN socket option on the listener. With TCP_FASTOPEN_CONNECT, connect() returns at once, and the SYN leaves with the first write() (tcp_fastopen_defer_connect()).

At the other end of a connection's life, the side that closes first enters TIME_WAIT for 60 s (TCP_TIMEWAIT_LEN, a constant; net.ipv4.tcp_fin_timeout governs FIN_WAIT_2 instead). The full socket is replaced by a small inet_timewait_sock in ehash (inet_twsk_hashdance_schedule()). tcp_timewait_state_process() re-ACKs retransmitted FINs. It also accepts a new SYN for the same 4-tuple if the SYN's sequence number or timestamp is newer than the old connection's, and starts the new connection with an ISN beyond the old snd_nxt. net.ipv4.tcp_max_tw_buckets (half the ehash size) caps the number of such sockets. Beyond it, connections close without TIME_WAIT. An outgoing connect() may take over a TIME_WAIT 4-tuple only if timestamps were in use and net.ipv4.tcp_tw_reuse allows it. The default, 2, allows it on loopback only. Since Linux 6.14, at least tcp_tw_reuse_delay (1000 ms) must also have passed since the socket entered TIME_WAIT.

Sending: tcp_sendmsg to tcp_write_xmit

tcp_sendmsg() is lock_sock(), then tcp_sendmsg_locked(), then release_sock(). The locked part copies user data into the skb at the tail of sk_write_queue, or into a new one. Payload goes into page frags taken from the per-task page_frag, so an skb grows up to the size TCP is willing to send as one TSO packet. Each skb is charged to sk_wmem_queued against sk_sndbuf, and sk_stream_wait_memory() blocks when the buffer is full. net.ipv4.tcp_wmem sets the initial and maximum sk_sndbuf, and TCP grows it automatically. tcp_push() then calls __tcp_push_pending_frames() → tcp_write_xmit(). TCP autocorking (tcp_should_autocork()) delays the push while earlier data is still in the qdisc or driver, so small writes coalesce into one segment.

tcp_write_xmit() is the gatekeeper. Before its loop it refreshes the connection's clock (tcp_mstamp_refresh()). If Packetization-Layer Path MTU Discovery (RFC 4821) is active, it may also send one larger probe segment (tcp_mtu_probe()). net.ipv4.tcp_mtu_probing controls PLPMTUD: 0, the default, disables it; 1 enables it only once repeated timeouts suggest an ICMP black hole; 2 always enables it. Then, for each skb at the head of the write queue, the function does the following:

  1. checks the pacing timer (tcp_pacing_check());
  2. checks that the congestion window has room (tcp_cwnd_test()) and that the peer's receive window does too (tcp_snd_wnd_test());
  3. applies Nagle's algorithm, and for TSO, decides whether waiting for more data would give a better-sized burst (tcp_tso_should_defer());
  4. splits the skb if only part of it may go now (tso_fragment());
  5. applies TCP small queues;
  6. calls tcp_transmit_skb(), then tcp_event_new_data_sent(). The latter advances snd_nxt and moves the original skb from sk_write_queue to the retransmit queue, an rbtree (tcp_rtx_queue) ordered by sequence number. If nothing was in flight before, it also arms the RTO timer.

__tcp_transmit_skb() transmits a clone, so the original remains available for retransmission. It pushes and fills the TCP header on the clone, sets CHECKSUM_PARTIAL, and hands the clone to icsk_af_ops->queue_xmit. After the loop, tcp_schedule_loss_probe() arms the tail-loss probe timer.

TCP Small Queues (TSQ, Linux 3.6) limit how much of one socket's data may sit below TCP, in qdiscs and device rings, at once. Without TSQ, a single bulk sender fills every queue on the path and inflates latency for everything else:

/* net/ipv4/tcp_output.c (tcp_small_queue_check, abridged) */
	limit = max_t(unsigned long,
		      2 * skb->truesize,
		      READ_ONCE(sk->sk_pacing_rate) >> READ_ONCE(sk->sk_pacing_shift));
	limit = min_t(unsigned long, limit,
		      READ_ONCE(sock_net(sk)->ipv4.sysctl_tcp_limit_output_bytes));
	limit <<= factor;
	...
	if (refcount_read(&sk->sk_wmem_alloc) > limit) {
		/* Always send skb if rtx queue is empty or has one skb.
		 * No need to wait for TX completion to call us back,
		 * after softirq schedule.
		 * This helps when TX completions are delayed too much.
		 */
		if (tcp_rtx_queue_empty_or_single_skb(sk))
			return false;

		set_bit(TSQ_THROTTLED, &sk->sk_tsq_flags);
		/* It is possible TX completion already happened
		 * before we set TSQ_THROTTLED, so we must
		 * test again the condition.
		 */
		smp_mb__after_atomic();
		if (refcount_read(&sk->sk_wmem_alloc) > limit)
			return true;
	}

sk_wmem_alloc counts the truesize of this socket's skbs that have been transmitted but not yet freed by the driver. The limit is about 1 ms of data at the current pacing rate (sk_pacing_shift is 10 by default), at least two packets, and at most tcp_limit_output_bytes (4 MB). Once over the limit, the socket stops transmitting. The skb destructor tcp_wfree() runs at TX completion. If the socket is throttled, it queues the socket on a per-CPU list and schedules a BH work item (tcp_tsq_workfn()) that resumes tcp_write_xmit(). This is the TX-completion clock of §7.3, applied per socket.

Pacing spreads a window's packets over the RTT instead of sending them in line-rate bursts. TCP computes sk_pacing_rate from cwnd and srtt. The rate is scaled by tcp_pacing_ss_ratio (200%) in slow start and tcp_pacing_ca_ratio (120%) in congestion avoidance, unless the congestion control sets it directly, as BBR does. Since Linux 4.20, TCP follows an earliest departure time model. tcp_update_skb_after_send() stamps each skb with the time it may leave (skb->tstamp, derived from tp->tcp_wstamp_ns). The fq qdisc holds each packet until that time. When the socket's qdisc is not fq, TCP paces itself with the pacing_timer hrtimer. The socket's sk_pacing_status records which of the two is in effect (SK_PACING_FQ or SK_PACING_NEEDED).

The pacing rate also sizes TSO bursts. tcp_tso_autosize() aims at about 1 ms of data per skb (sk_pacing_rate >> sk_pacing_shift). It then adds a bonus for flows with a small minimum RTT. The bonus is a full sk_gso_max_size packet below 512 µs and halves for each further 512 µs (net.ipv4.tcp_tso_rtt_log, 9, Linux 5.18). The result is capped by sk_gso_max_size and sk_gso_max_segs, and it is never below net.ipv4.tcp_min_tso_segs (2) or the value of the congestion control's min_tso_segs() hook, which BBR implements. A slow flow therefore sends small TSO packets that fq can interleave with other flows. A fast flow inside a data center sends 64 KB packets, or larger ones with BIG TCP.

A module registers an algorithm with tcp_register_congestion_control(). net.ipv4.tcp_congestion_control chooses the default, and the TCP_CONGESTION socket option chooses per socket. The built-in default is CONFIG_DEFAULT_TCP_CONG, which is "cubic" unless configured otherwise. CUBIC (net/ipv4/tcp_cubic.c), default since 2.6.19, grows cwnd as a cubic function of time since the last loss and uses HyStart to leave slow start early. BBR (net/ipv4/tcp_bbr.c, Linux 4.9) implements cong_control instead. It models the path's bottleneck bandwidth and minimum RTT and sets both cwnd and pacing rate from them, ignoring isolated losses. The in-tree BBR is still the first version of the algorithm. Algorithms can also be written in BPF and registered as struct_ops (net/ipv4/bpf_tcp_ca.c; see Chapter 23).

Congestion signals need not be losses. With ECN, a router marks a packet Congestion Experienced (CE) in its IP header instead of dropping it, and the receiver echoes the mark back. net.ipv4.tcp_ecn selects what TCP negotiates. The default, 2, accepts ECN on incoming connections but does not request it on outgoing ones; 1 also requests it. Classic ECN (RFC 3168) conveys at most one congestion signal per round trip, through the ECE flag. Linux 6.18 added Accurate ECN (AccECN). The receiver feeds back running counts: of CE-marked packets in a 3-bit ACE field made from the AE, CWR and ECE header bits, and of marked bytes in a new TCP option (net.ipv4.tcp_ecn_option). tcp_ecn values 3–5 negotiate it. Algorithms that react to the extent of marking need that precision; examples are DCTCP (net/ipv4/tcp_dctcp.c) and L4S designs. A congestion control states its requirements in its flags: TCP_CONG_NEEDS_ECN, and since 6.18 TCP_CONG_NEEDS_ACCECN and TCP_CONG_ECT_1_NEGOTIATION.

Loss recovery is driven by timers and ACKs. The retransmission timer (tcp_write_timer_handler() → tcp_retransmit_timer()) fires after icsk_rto. That value starts at 1 s (TCP_TIMEOUT_INIT) and doubles with each timeout. It is clamped between two limits. The lower one is net.ipv4.tcp_rto_min_us (200 ms, a sysctl since Linux 6.11), which a route attribute (rto_min) or a BPF program can override. The upper one is net.ipv4.tcp_rto_max_ms (120 s, a sysctl since 6.15), which the TCP_RTO_MAX_MS socket option can change per socket. After tcp_retries1 (3) timeouts, TCP asks the IP layer to revalidate the route. With MTU probing enabled, it also lowers the MSS. After tcp_retries2 (15) timeouts, about 15 minutes in all, it aborts the connection with ETIMEDOUT. TCP_USER_TIMEOUT can set a shorter deadline instead.

Long before the RTO fires, two mechanisms usually act. RACK (Linux 4.4, RFC 8985) marks a packet lost when a packet sent sufficiently later has been delivered (tcp_rack_mark_lost()). "Sufficiently" means a reordering window of a quarter of the minimum RTT, which widens when DSACKs reveal spurious retransmissions. The tail-loss probe (TLP, Linux 3.10; tcp_send_loss_probe()) retransmits the last segment after about two RTTs without ACKs. This provokes the SACK that lets RACK recover. Since Linux 6.17, RACK-TLP is the only loss detection for SACK connections. The RFC 3517/RFC 6675 code that counted duplicate ACKs was removed. net.ipv4.tcp_recovery now only tunes RACK: bit 0x2 makes the reordering window static, and bit 0x4 disables the duplicate-ACK threshold. Connections without SACK still use NewReno (tcp_newreno_mark_lost()).

The same timer machinery covers two idle states. When the peer advertises a zero window, tcp_probe_timer() sends window probes (tcp_send_probe0()) with the RTO's backoff, so the connection learns when the window reopens. Keepalive (SO_KEEPALIVE, tcp_keepalive_timer()) probes a connection that has been idle for net.ipv4.tcp_keepalive_time (2 hours). It then probes every tcp_keepalive_intvl (75 s) and gives up after tcp_keepalive_probes (9) unanswered probes. TCP_KEEPIDLE, TCP_KEEPINTVL and TCP_KEEPCNT override these per socket.

Receiving: tcp_v4_rcv to recvmsg

tcp_v4_rcv() runs in softirq context from ip_protocol_deliver_rcu(). After header and checksum checks, it looks up the socket in the established hash, then the listening hash (__inet_lookup_skb()). It handles the TCP_NEW_SYN_RECV and TIME_WAIT cases separately, runs the socket filter, and then applies the owned-by-user rule of §2.4:

/* net/ipv4/tcp_ipv4.c (tcp_v4_rcv, abridged) */
lookup:
	sk = __inet_lookup_skb(skb, __tcp_hdrlen(th), th->source,
			       th->dest, sdif, &refcounted);
	if (!sk)
		goto no_tcp_socket;

	if (sk->sk_state == TCP_TIME_WAIT)
		goto do_time_wait;

	if (sk->sk_state == TCP_NEW_SYN_RECV) {
		...
	}
	...
	if (sk->sk_state == TCP_LISTEN) {
		ret = tcp_v4_do_rcv(sk, skb);
		goto put_and_return;
	}

	sk_incoming_cpu_update(sk);

	bh_lock_sock_nested(sk);
	tcp_segs_in(tcp_sk(sk), skb);
	ret = 0;
	if (!sock_owned_by_user(sk)) {
		ret = tcp_v4_do_rcv(sk, skb);

		if (tcp_add_backlog(sk, skb, &drop_reason))
			goto discard_and_relse;

A listener is handled before bh_lock_sock_nested(), so SYN processing takes no socket spinlock (§8.1). Several checks run between the lookup and this point: IP_MINTTL (the RFC 5082 TTL security check), the IPsec policy check (xfrm4_policy_check()), and tcp_inbound_hash(). The last one verifies TCP-MD5 signatures or, since Linux 6.7, TCP Authentication Option (TCP-AO, RFC 5925; net/ipv4/tcp_ao.c) MACs, when keys are configured on the socket.

For an established socket, tcp_v4_do_rcv() calls tcp_rcv_established(). That function has a fast path chosen by header prediction: the segment's flags and window match tp->pred_flags, it carries the next expected sequence number, and no special state (urgent data, zero window, out-of-order data) is active. A pure ACK is processed by tcp_ack() and freed. A data segment is appended to sk_receive_queue by tcp_queue_rcv(), often merged into the previous skb by tcp_try_coalesce(). The function then updates the receive-RTT estimate, calls sk_data_ready() to wake the reader, and decides whether to ACK now or arm the delayed-ACK timer (__tcp_ack_snd_check()).

__tcp_ack_snd_check() sends an ACK at once in three cases:

  • more than one full-sized segment has arrived since the last ACK and the advertised window would advance;
  • the connection is in quickack mode;
  • the protocol state demands an immediate ACK (ICSK_ACK_NOW).

Quickack mode covers a few segments at the start of a connection and after events such as out-of-order data or a CE mark, so the sender can grow its window or start recovery without waiting. TCP_QUICKACK forces it from user space. In all other cases tcp_send_delayed_ack() arms the delayed-ACK timer for icsk_ack.ato, an estimate of the packet inter-arrival time between 40 ms (TCP_ATO_MIN) and 200 ms (TCP_DELACK_MAX), hoping to piggyback the ACK on reply data. Since Linux 6.7, ACKs for segments processed from the backlog in __release_sock() are deferred to tcp_release_cb() (net.ipv4.tcp_backlog_ack_defer, 1). A burst of backlogged segments then produces one ACK instead of one per segment.

Everything else takes the slow path. tcp_validate_incoming() does PAWS, sequence-window, RST and SYN checks. tcp_ack() then processes the acknowledgement:

  • it frees acknowledged skbs from the rtx rbtree (tcp_clean_rtx_queue()), which also produces RTT samples;
  • it processes SACK blocks;
  • it runs the loss-recovery state machine (tcp_fastretrans_alert());
  • it calls the congestion control (tcp_cong_control()).

tcp_data_queue() then places the data. An in-sequence segment goes to the receive queue, after which tcp_ofo_queue() moves any now-contiguous segments over from the out-of-order queue. An out-of-sequence segment goes to tcp_data_queue_ofo(), which inserts it into out_of_order_queue. That queue has been an rbtree keyed by sequence number since Linux 4.9; before that it was a linked list, whose linear insertion a malicious peer could exploit. The function coalesces overlaps and records the new SACK block. Both queues are charged to sk_rmem_alloc. When an incoming skb would exceed sk_rcvbuf, tcp_try_rmem_schedule() first collapses queued skbs into compact ones (tcp_prune_queue()). As a last resort it discards the out-of-order queue (tcp_prune_ofo_queue()).

While a hole persists, every arriving segment would trigger a SACK. TCP sends the first three duplicate ACKs at once, which is what the sender needs to start fast recovery, and compresses the rest (Linux 4.18). Further SACKs wait on an hrtimer for a fraction of the RTT: net.ipv4.tcp_comp_sack_rtt_percent, 33% since Linux 6.19 (previously a fixed 5%). The wait is capped at tcp_comp_sack_delay_ns (1 ms), and it ends early once tcp_comp_sack_nr (44) SACKs have been held back.

On the reading side, tcp_recvmsg() takes the socket lock and copies from sk_receive_queue, sleeping in sk_wait_data() when it is empty. When it releases the lock, the backlog is processed (§2.4). tcp_cleanup_rbuf() sends a window update if the read opened the window significantly. Receive-buffer autotuning is controlled by net.ipv4.tcp_moderate_rcvbuf and disabled for a socket that sets SO_RCVBUF. tcp_rcv_space_adjust() measures how much the application has read in each receive RTT, and tcp_rcvbuf_grow() (Linux 6.16) raises sk_rcvbuf to match, up to tcp_rmem[2]. That limit was raised from 6 MB to 32 MB in 6.16. The target is twice the data delivered in the last RTT, so the sender can double its rate in slow start, plus the span of any out-of-order data. Since Linux 6.19, flows whose RTT is below net.ipv4.tcp_rcvbuf_low_rtt (1 ms) grow more gently. In data centers, oversized buffers defeat page-pool recycling and evict data from caches that the NIC writes directly. Converting between buffer bytes and advertised window takes overhead into account. Since Linux 6.6 this uses a measured ratio of payload to truesize (tp->scaling_ratio, tcp_win_from_space()) instead of the fixed tcp_adv_win_scale, so drivers with a large truesize no longer shrink the window.

Two zero-copy paths avoid the user copy. MSG_ZEROCOPY (Linux 4.14, enabled per socket with SO_ZEROCOPY) pins the user pages with a ubuf_info (msg_zerocopy_realloc()) and attaches them to skbs as frags. The application must not modify the buffer until a completion arrives on the socket's error queue (SO_EE_ORIGIN_ZEROCOPY). This pays off only for large writes. On receive, TCP_ZEROCOPY_RECEIVE (Linux 4.18) lets an application mmap() a region on the TCP socket (tcp_mmap()) and then, via getsockopt(), have tcp_zerocopy_receive() map received page-aligned payload pages into it instead of copying. This requires a NIC that splits headers from payload. §10.2 describes the device-memory and io_uring descendants of this idea.

UDP

UDP (net/ipv4/udp.c) has no connection state, and its paths are correspondingly short. On send, udp_sendmsg() routes the packet, or reuses the route of a connected socket. In the common uncorked case it builds the whole datagram at once with ip_make_skb(), without taking the socket lock, and udp_send_skb() adds the UDP header and calls ip_send_skb(). With MSG_MORE or UDP_CORK, data accumulates on the socket through ip_append_data() until the datagram is complete.

On receive, udp_rcv() → __udp4_lib_rcv() looks up the socket. The UDP hash table has several views: a primary hash by port, a secondary hash by address and port (hash2), and since Linux 6.13 a 4-tuple hash (hash4) that makes many connected sockets on one port cheap to demultiplex. __udp4_lib_lookup() tries hash4 first, then the exact local address in hash2, then the wildcard address. If several sockets bound the same port with SO_REUSEPORT (Linux 3.9), reuseport_select_sock() (net/core/sock_reuseport.c) picks one by flow hash, or by a BPF program attached with SO_ATTACH_REUSEPORT_EBPF. This is how multi-threaded UDP and TCP servers spread load without a shared accept queue. The skb then passes through udp_unicast_rcv_skb() → udp_queue_rcv_skb() → __udp_queue_rcv_skb() to __udp_enqueue_schedule_skb(). That function drops the datagram at once if sk_rmem_alloc plus the datagram would exceed sk_rcvbuf. Since Linux 6.18 it does not take the receive-queue lock for every packet. Each NUMA node has a lockless list in the socket (udp_prod_queue), and a producing CPU adds the skb with llist_add(). Only the CPU that found the list empty takes sk_receive_queue's lock. It drains the whole list in a batch, charges the memory (udp_rmem_schedule()), and wakes readers. This replaced the earlier "busylock", which kept a flood from monopolizing the socket but left many CPUs spinning, so that the NIC dropped packets for every other flow. udp_recvmsg() reads from a private reader_queue instead, into which it splices the receive queue in bulk, so producers and the consumer rarely contend for the same lock.

Many tunnels run over UDP: VXLAN, GENEVE, WireGuard, L2TP, and ESP-in-UDP. Each installs an encap_rcv hook on a UDP socket. Kernel tunnels open their own socket and use setup_udp_tunnel_sock(). IPsec NAT traversal sets the UDP_ENCAP option on the IKE daemon's socket instead. udp_queue_rcv_one_skb() passes matching datagrams to that hook, which decapsulates them and reinjects the inner packet, instead of queuing them for a reader.

UDP gained segmentation offload late. UDP_SEGMENT (Linux 4.18) lets a sender pass a buffer of up to 128 equal-sized datagrams (64 before Linux 6.9) in one sendmsg(). The buffer travels as one GSO skb (SKB_GSO_UDP_L4) and is split by the NIC or by __udp_gso_segment(). UDP_GRO (Linux 5.0) is the receive counterpart: GRO merges datagrams of one flow, and the socket receives them as one buffer with the segment size in a control message. Together they make QUIC implementations in user space competitive with kernel TCP.

Netfilter and Netlink

Every packet-filtering, NAT and connection-tracking feature in Linux hangs off one mechanism: a small set of hook points in the IP paths, each holding a priority-sorted array of callbacks. Firewalls written for iptables and nft, Docker and Kubernetes service NAT, and the stateful “established” match all run as callbacks on those hooks. Two rule engines sit on them — the legacy x_tables behind iptables and nf_tables behind nft — together with connection tracking and NAT. All of it is configured through netlink, the socket family through which user space also configures nearly everything else in the stack. The hooks, struct nf_hook_ops, ip_tables, ip_conntrack and rtnetlink already existed in Linux 2.6.11. nf_tables, nf_conntrack and generic netlink came later.

A hook user registers a struct nf_hook_ops (include/linux/netfilter.h): the callback hook, an opaque priv, the protocol family pf (NFPROTO_IPV4, NFPROTO_IPV6, NFPROTO_ARP, NFPROTO_BRIDGE, NFPROTO_NETDEV, NFPROTO_INET), the hooknum, a dev for the netdev family, and a signed priority. Hooks are per network namespace: nf_register_net_hook(net, ops) builds a new, larger struct nf_hook_entries array with nf_hook_entries_grow(), inserting the new entry in ascending priority order, and publishes it with RCU into net->nf.hooks_ipv4[hooknum] (or the IPv6, ARP or bridge array). The standard priorities come from enum nf_ip_hook_priorities in include/uapi/linux/netfilter_ipv4.h; they are what make connection tracking run before NAT, and NAT before filtering, on the same hook.

The array is laid out for the packet path. struct nf_hook_entries holds num_hook_entries and then a packed array of struct nf_hook_entry, each just the hook function pointer and its priv argument, so the walk touches two words per callback. Behind that array is a trailer the packet path never reads: an orig_ops[] array pointing back at each registering nf_hook_ops, and an rcu_head for freeing. Registrations are serialized by nf_hook_mutex. Every change builds a fresh copy and installs it with rcu_assign_pointer(), and call_rcu() frees the old copy once every reader inside nf_hook() has left its RCU read-side section. A hook holds at most 1,024 entries (MAX_HOOK_COUNT). Unregistration must not fail, even when no memory is left for a smaller copy, so nf_remove_net_hook() first overwrites the departing entry in place with accept_all(), a stub that returns NF_ACCEPT, and only then tries to shrink the array. Netdev-family hooks are kept per device rather than per namespace, in dev->nf_hooks_ingress and dev->nf_hooks_egress, which is why an nft netdev chain names the device it attaches to.

The IP code calls a hook through the NF_HOOK() inline. It passes the packet, the input and output devices, and an okfn continuation — the next stage of the path, such as ip_rcv_finish():

static inline int
NF_HOOK(uint8_t pf, unsigned int hook, struct net *net, struct sock *sk,
	struct sk_buff *skb, struct net_device *in, struct net_device *out,
	int (*okfn)(struct net *, struct sock *, struct sk_buff *))
{
	int ret = nf_hook(pf, hook, net, sk, skb, in, out, okfn);
	if (ret == 1)
		ret = okfn(net, sk, skb);
	return ret;
}

Two costs are avoided here. When no namespace has registered anything on a hook, the nf_hooks_needed static key (net/netfilter/core.c) turns the whole call into a jump label patched into the kernel text, so a machine without a firewall pays almost nothing. And when a namespace has no entries on this hook, the RCU-protected pointer is NULL and okfn runs directly. Otherwise nf_hook_slow() walks the entries in priority order and acts on each verdict:

/* net/netfilter/core.c */
int nf_hook_slow(struct sk_buff *skb, struct nf_hook_state *state,
		 const struct nf_hook_entries *e, unsigned int s)
{
	unsigned int verdict;
	int ret;

	for (; s < e->num_hook_entries; s++) {
		verdict = nf_hook_entry_hookfn(&e->hooks[s], skb, state);
		switch (verdict & NF_VERDICT_MASK) {
		case NF_ACCEPT:
			break;
		case NF_DROP:
			kfree_skb_reason(skb,
					 SKB_DROP_REASON_NETFILTER_DROP);
			ret = NF_DROP_GETERR(verdict);
			if (ret == 0)
				ret = -EPERM;
			return ret;
		case NF_QUEUE:
			ret = nf_queue(skb, state, s, verdict);
			if (ret == 1)
				continue;
			return ret;
		case NF_STOLEN:
			return NF_DROP_GETERR(verdict);
		default:
			WARN_ON_ONCE(1);
			return 0;
		}
	}

	return 1;
}

The verdicts are small integers from the UAPI header: NF_DROP (0), NF_ACCEPT (1), NF_STOLEN (2), NF_QUEUE (3) and NF_REPEAT (4). NF_ACCEPT only means “this hook entry has no objection”; the next entry still runs, and only a return of 1 from the whole walk lets NF_HOOK() call okfn. NF_DROP frees the skb, and the caller sees -EPERM, which is why a locally generated packet dropped by an output rule makes sendmsg() fail with “Operation not permitted”. NF_STOLEN means the hook took ownership of the skb — for example to hold a fragment until reassembly completes. NF_QUEUE parks the packet in nf_queue() (net/netfilter/nf_queue.c) and hands a copy to a user-space program over nfnetlink_queue; the program's verdict later resumes the walk at the next entry, which is why nf_hook_slow() takes a starting index s. Since Linux 6.4 a BPF program of type BPF_PROG_TYPE_NETFILTER can also be attached as a hook entry through a BPF link (net/netfilter/nf_bpf_link.c), with the same verdict convention.

NF_REPEAT never reaches the switch in nf_hook_slow(); there it would trip the WARN_ON_ONCE(). It has two narrower uses. A user-space queue verdict of NF_REPEAT makes nf_reinject() call the same hook entry again instead of moving to the next one. Conntrack's TCP tracker returns -NF_REPEAT when a SYN tries to reopen a connection that is closing or was reset, and nf_conntrack_in() then kills the old entry and starts the lookup again. Queueing has its own failure rules. If no program is bound to the queue number, nf_queue() drops the packet unless the rule set NF_VERDICT_FLAG_QUEUE_BYPASS (queue ... bypass in nft), in which case the packet is accepted. A queue holds at most 1,024 packets by default (NFQNL_QMAX_DEFAULT), and when it is full packets are dropped unless the listener set NFQA_CFG_F_FAIL_OPEN. Two variants of NF_HOOK() appear in the IP code. NF_HOOK_COND() skips the hook when a condition is false; ip_output() uses it to avoid running POST_ROUTING twice for a packet that was rerouted through an IPsec transform after source NAT (IPSKB_REROUTED). NF_HOOK_LIST() runs PRE_ROUTING over each skb of the batches that ip_list_rcv() receives, and collects the survivors into a new list for ip_list_rcv_finish().

nf_tables and x_tables

The hooks are mechanism; the policy comes from a rule engine. Linux 7.0.12 has two. The legacy engine, x_tables (net/netfilter/x_tables.c, net/ipv4/netfilter/ip_tables.c), is what 2.6-era iptables programmed. Each table (filter, nat, mangle, raw, security) registers fixed hook ops at fixed priorities, and ipt_do_table() walks a binary blob of struct ipt_entry records that user space replaces wholesale with setsockopt(IPT_SO_SET_REPLACE). Matches and targets are kernel modules registered with xt_register_match() and xt_register_target(). Replacing a large ruleset means copying all of it, and every rule is tested linearly. Since Linux 6.17 the legacy tables sit behind CONFIG_NETFILTER_XTABLES_LEGACY, which cannot be enabled on PREEMPT_RT kernels; the iptables command found on current distributions is usually iptables-nft, which translates the old syntax into nf_tables rules and, where needed, runs the old match and target modules through nft_compat.

nf_tables (Linux 3.13, net/netfilter/nf_tables_api.c, net/netfilter/nf_tables_core.c) inverts that design. The kernel knows nothing about tables, chains or protocols in advance. User space (nft) creates tables and chains through netlink messages; a base chain declares its family, hook and priority, and nf_tables_register_hook() registers ordinary nf_hook_ops for it. Rules are sequences of small expressions — load a payload field into a register, compare, look up a set, set a verdict — that run on a tiny register machine. Changes arrive as a netlink batch and are committed as one transaction: the rules of each chain are compiled into two blobs (blob_gen_0, blob_gen_1), and a commit flips the per-namespace gencursor, so packets see either the old ruleset or the new one, never a mixture. Sets and maps (nft_set_hash.c, nft_set_rbtree.c, nft_set_pipapo.c with an AVX2 version for x86-64) turn “match any of 10,000 addresses” into one lookup instead of 10,000 rules. The interpreter is nft_do_chain():

The commonest expressions — fast compare, bitwise and payload load — are evaluated inline instead of through a function pointer. When an x86-64 kernel uses retpolines against Spectre, every indirect call is expensive, so expr_call_ops_eval() also compares the eval pointer against a list of frequent expressions and calls the match directly. A static key turns that list off on CPUs that do not need retpolines. Jumps to user chains use a small fixed-size stack (NFT_JUMP_STACK_SIZE). The per-family entry points such as nft_do_chain_ipv4() (net/netfilter/nft_chain_filter.c) fill a struct nft_pktinfo with the transport protocol and header offset first, so expressions do not reparse the packet.

The register machine is small. struct nft_regs is a union of the verdict and u32 data[NFT_REG32_NUM], twenty 32-bit words (80 bytes) on the stack of nft_do_chain(). The verdict overlays the first 16 bytes, and the other 64 bytes are the general registers. User space addresses them either as sixteen 32-bit registers (NFT_REG32_00 to NFT_REG32_15) or as four 128-bit registers (NFT_REG_1 to NFT_REG_4), wide enough for an IPv6 address. No protocol knowledge is built in. ip saddr 10.0.0.1 compiles to a payload expression that copies four bytes at offset 12 of the network header into a register, followed by a compare expression. Because rules are data rather than native code, the kernel checks them before they go live. During a commit, nf_tables_validate() rejects a ruleset whose jumps form a loop (-ELOOP), whose jumps nest deeper than the 16-entry jump stack (-EMLINK), or whose expressions are used on a hook that does not allow them. Every base chain also has a type. A filter chain only returns verdicts. A nat chain is attached to the conntrack NAT hooks described below, and is consulted only for the first packet of a connection. A route chain on LOCAL_OUT (net/netfilter/nft_chain_route.c) calls ip_route_me_harder() again if a rule changed the packet's mark, addresses or TOS; it replaces the rerouting done by the old mangle table.

A set is not tied to one data structure. When nft creates a set, nft_select_set_ops() asks each backend in nft_set_types[] to estimate its memory use and lookup cost for the declared key length, flags (intervals, timeouts, concatenated keys) and expected size. It then picks the cheapest lookup or the smallest footprint, depending on the set's NFT_SET_POL_PERFORMANCE or NFT_SET_POL_MEMORY policy. Keys of at most two bytes, such as ports, can become a bitmap with O(1) lookup. Exact-match keys go to a hash, plain intervals to the rbtree, and concatenations of ranges to pipapo; the AVX2 version of pipapo arrived in Linux 5.7.

Transactions carry most of nf_tables' complexity. A batch is a run of netlink messages framed by NFNL_MSG_BATCH_BEGIN and NFNL_MSG_BATCH_END. nfnetlink_rcv_batch() (net/netfilter/nfnetlink.c) takes the per-namespace commit_mutex and hands each message to its handler, which leaves the live ruleset unchanged and only records a struct nft_trans describing the change. If every message succeeds, nf_tables_commit() validates, builds the next-generation blobs and flips the generation. Otherwise nf_tables_abort() unwinds every recorded change, and the errors are reported once the whole batch has been processed. One kind of failure leads to a retry rather than an error. When a rule needs an expression or chain type whose module is not loaded, the handler returns -EAGAIN. The batch is then aborted, the module is loaded with the mutex dropped, and the whole batch is replayed from the original buffer.

Tables have flags. NFT_TABLE_F_DORMANT unregisters a table's hooks without deleting the table. NFT_TABLE_F_OWNER (Linux 5.12) ties a table to the netlink socket that created it. Other sockets get -EPERM when they try to change it, and the table is deleted when the socket closes, so a firewall daemon's rules go away when the daemon exits. NFT_TABLE_F_PERSIST (Linux 6.9) keeps an owned table after its owner exits, as an orphan that a restarted daemon can adopt. For debugging, a rule that sets meta nftrace enables the nft_trace_enabled static key. From then on nft_do_chain() reports every rule a marked packet passes, and its final verdict, to the NFNLGRP_NFTRACE multicast group, which nft monitor trace prints.

For forwarded traffic, nf_tables also offers a flowtable (Linux 4.16, net/netfilter/nf_flow_table_core.c). Once a connection is established, a rule can add it to a flowtable, and from then on nf_flow_offload_ip_hook() on the netdev ingress hook forwards its packets directly to the output device — rewriting addresses for NAT and decrementing the TTL — skipping routing, the FORWARD hook and the rest of the IP layer. The rule is flow add @ft in a forward chain. It creates a struct flow_offload with one tuple per direction in the flowtable's rhashtable, and sets IPS_OFFLOAD on the conntrack entry so that conntrack does not expire the entry while the flowtable is handling the flow. The fast path handles VLAN- and PPPoE-encapsulated packets as well. A packet returns to the normal path when it is larger than the cached MTU or its cached route has become stale, and the second case tears the flow down. A TCP FIN or RST marks the flow as closing. A flow that sees no packets for 30 seconds (NF_FLOW_TIMEOUT) is removed, and the connection goes back to ordinary conntrack handling. With the NFT_FLOWTABLE_HW_OFFLOAD flag (Linux 5.5), each entry is also pushed through ndo_setup_tc(TC_SETUP_FT) into NICs and switches that can forward the flow in hardware, and the counters read back from the hardware keep the software entry alive.

Connection tracking and NAT

Connection tracking (net/netfilter/nf_conntrack_core.c) gives netfilter memory. It replaced the IPv4-only ip_conntrack of Linux 2.6.11: nf_conntrack was merged in Linux 2.6.15 and the old code removed in 2.6.22. Conntrack registers hook ops of its own in net/netfilter/nf_conntrack_proto.c: ipv4_conntrack_in() at NF_IP_PRI_CONNTRACK (−200) on PRE_ROUTING, ipv4_conntrack_local() at the same priority on LOCAL_OUT, and nf_confirm() at NF_IP_PRI_CONNTRACK_CONFIRM (INT_MAX, last) on POST_ROUTING and LOCAL_IN. They are registered only while something in the namespace needs conntrack, such as a stateful rule or NAT.

A tracked connection is a struct nf_conn (include/net/netfilter/nf_conntrack.h). Its core is tuplehash[IP_CT_DIR_MAX]: two struct nf_conntrack_tuple_hash entries, one for the original direction and one for the reply. Each holds the addresses, ports (or ICMP id) and protocol of that direction and an hlist_nulls_node linking it into the global nf_conntrack_hash table. Because both directions are hashed, a reply packet finds the same nf_conn as the original. The structure also carries a status bit set (IPS_SEEN_REPLY, IPS_ASSURED, IPS_CONFIRMED, NAT bits), a timeout, an optional zone that lets overlapping address spaces be tracked separately, a mark, a master pointer for expected related connections (FTP data, SIP media), per-protocol state in proto (the TCP window tracker lives there), and ext, a variable-size area for optional extensions such as NAT, helpers, accounting and timestamps (nf_ct_ext_add()).

nf_conntrack_in() handles each packet in three steps. It computes the tuple and looks it up in resolve_normal_ct(). If nothing matches, init_conntrack() allocates a new, unconfirmed entry, which is not yet in the hash table. The connection and the packet's role — IP_CT_NEW, IP_CT_ESTABLISHED, IP_CT_RELATED or IP_CT_ESTABLISHED_REPLY — are stored in the skb's _nfct word, which nf_ct_get() decodes. Finally nf_conntrack_handle_packet() runs the per-protocol state machine. The entry is inserted into the hash only when the first packet survives every hook and reaches nf_confirm() → __nf_conntrack_confirm(), so packets dropped by the firewall never create table entries. When the table is full, early_drop() evicts a connection that has not been marked IPS_ASSURED. The table size is set by net.netfilter.nf_conntrack_max and nf_conntrack_buckets, and conntrack -L reads it through ctnetlink (net/netfilter/nf_conntrack_netlink.c).

nf_conntrack_init_start() sizes the table at boot. Unless the hashsize module parameter overrides it, the bucket count follows memory: one bucket per 16 KB of RAM divided by the size of a bucket head, at least 1,024, and fixed at 65,536 above 1 GB of RAM or 262,144 on a 64-bit machine with more than 4 GB. nf_conntrack_max defaults to the same number of entries. A bucket is chosen by siphash with a random boot-time key, so a remote sender cannot steer connections into one chain. The limit is global, but each namespace's own count is compared against it. Inside a child namespace nf_conntrack_max and nf_conntrack_buckets are read-only, and a namespace that hits the limit logs nf_conntrack: table full in netns %u, dropping packet. Entries are allocated from a SLAB_TYPESAFE_BY_RCU cache, so lookups run under RCU without locks. The cost is that an entry can be freed and reused for another connection while a reader is still looking at it, so __nf_conntrack_find_get() takes a reference with refcount_inc_not_zero() and then checks the tuple again with nf_ct_key_equal(). Since Linux 4.9 connections have no per-entry timer. timeout is a jiffies deadline that lookups check lazily, and gc_worker() sweeps the table from a workqueue, spending at most 10 ms per pass. It schedules the next pass from the average remaining lifetime of the entries it saw, clamped between 1 and 60 seconds. The deadlines come from per-protocol sysctls such as nf_conntrack_tcp_timeout_established (five days) and nf_conntrack_udp_timeout (30 seconds; 120 seconds, nf_conntrack_udp_timeout_stream, once the flow has seen traffic in both directions).

Because an entry is inserted only at confirmation, two CPUs can each create an unconfirmed entry for the same tuple. This is common with UDP, for example when a resolver sends its A and AAAA queries from one socket at once. Dropping the second packet would cost the application a retransmission timeout, so __nf_conntrack_confirm() calls nf_ct_resolve_clash() for protocols that allow it. If both entries have the same tuples in both directions, including any NAT result, the packet is attached to the entry already in the table. Otherwise nf_ct_resolve_clash_harder() inserts the losing entry in its reply direction only, marked IPS_NAT_CLASH and given a fixed one-second timeout. The clash_resolve counter of conntrack -S counts these.

Some protocols carry addresses and ports in their payload, such as FTP's PORT command or SIP's SDP bodies. Conntrack helpers (net/netfilter/nf_conntrack_ftp.c, nf_conntrack_sip.c and others) parse that control traffic and register expectations (struct nf_conntrack_expect, nf_ct_expect_related()) for connections about to arrive. When a new connection's first packet matches an expectation, init_conntrack() links the entry to its master, sets IPS_EXPECTED, and the packet is classified IP_CT_RELATED. The number of pending expectations is capped by nf_conntrack_expect_max. Helpers used to attach themselves to any connection on their well-known port. That default was turned off in Linux 4.7, and Linux 6.0 removed the nf_conntrack_helper toggle altogether. A helper now runs only when a rule assigns it, with ct helper set in nft or the CT target in iptables. Zones (nf_conntrack_zone) separate otherwise identical tuples, for example when one host routes for several VRFs or tenants with overlapping addresses; the zone id is part of every hash and comparison.

NAT (net/netfilter/nf_nat_core.c, nf_nat_proto.c) is built on conntrack and consults the ruleset only for the first packet of a connection. Its hook ops (nf_nat_ipv4_ops) sit at NF_IP_PRI_NAT_DST (−100) on PRE_ROUTING and LOCAL_OUT for destination NAT, and at NF_IP_PRI_NAT_SRC (100) on POST_ROUTING and LOCAL_IN for source NAT. For a new connection, nf_nat_inet_fn() runs the NAT chains registered by nf_tables or iptables; a dnat, snat or masquerade rule calls nf_nat_setup_info(), which picks a free tuple and rewrites the reply tuple in the conntrack entry. If no rule matched, nf_nat_alloc_null_binding() records an identity mapping. From then on every packet, in either direction, is rewritten by nf_nat_packet() → nf_nat_manip_pkt() from the stored tuples, with checksums fixed up incrementally. Because the reply tuple was rewritten, replies to a masqueraded connection find the entry and are translated back without any rule lookup.

get_unique_tuple() chooses the new tuple in a fixed order. For source NAT without full randomization, it first tries to keep the connection's own tuple if that lies inside the rule's range and no other connection uses it. Failing that, it looks in the nf_nat_bysource hash for an existing mapping of the same inside address, so that one host's connections leave from the same outside address. Next, find_best_ips_proto() picks an address from the range by hashing the source and destination addresses. A given client-server pair therefore gets the same address on every connection, and with NF_NAT_RANGE_PERSISTENT the choice depends on the source alone. Last, nf_nat_l4proto_unique_tuple() searches for a free port. Unless the rule gives an explicit port range, it keeps the port in its original class: below 512, 600–1023, or 1024 and above. Source NAT starts at a random offset in the range, and destination NAT does so only with NF_NAT_RANGE_PROTO_RANDOM_ALL. The search tries at most 128 candidates (NF_NAT_MAX_ATTEMPTS), then halves the window and restarts at another random offset, so a nearly exhausted range cannot keep softirq busy. Masquerade is source NAT to whatever address the output device has when the connection starts. Its netdevice and inetaddr notifiers in net/netfilter/nf_nat_masquerade.c delete the affected conntrack entries when that address or device goes away, so connections over a DHCP or PPP link do not go on using a dead source address.

Netlink: the configuration channel

Everything above is configured from user space, and almost none of it through ioctl(). The channel is netlink (net/netlink/af_netlink.c): an address family, AF_NETLINK, whose sockets exchange messages with the kernel rather than with a remote host. A message is a struct nlmsghdr (length, type, flags, sequence number, sender port id) followed by type-length-value attributes (struct nlattr), which lets old tools ignore attributes they do not know and new attributes be added without breaking the ABI. The protocol number given to socket(AF_NETLINK, SOCK_RAW, proto) selects the kernel subsystem (include/uapi/linux/netlink.h, at most MAX_LINKS = 32): NETLINK_ROUTE (0) for links, addresses, routes, neighbours, rules and qdiscs, NETLINK_AUDIT (9), NETLINK_NETFILTER (12) for nf_tables, ctnetlink and nfqueue, and NETLINK_GENERIC (16). Chapter 13 described the uevent netlink socket that udev listens on (devtmpfs and udev), and Chapter 19 the netlink notification of POSIX message queues (Message Queues).

The header's flags give a request its meaning. NLM_F_REQUEST marks a message to the kernel. NLM_F_ACK asks for an acknowledgement, an NLMSG_ERROR message whose error code is zero on success. NLM_F_DUMP asks for a whole table. A reply that spans several messages carries NLM_F_MULTI and ends with NLMSG_DONE. On “new” requests, NLM_F_CREATE, NLM_F_EXCL and NLM_F_REPLACE choose between create-only, create-or-replace and modify: ip route add sends CREATE|EXCL, and ip route replace sends CREATE|REPLACE. Errors became more informative in Linux 4.12. A socket that sets NETLINK_EXT_ACK receives, along with the error code, attributes carrying a text message and the offset of the offending attribute (NLMSGERR_ATTR_MSG, NLMSGERR_ATTR_OFFS). Handlers fill these in with NL_SET_ERR_MSG() on the struct netlink_ext_ack passed to every request handler, and they are where iproute2's “Error: ...” messages come from. Attributes are checked against a struct nla_policy array that declares the type, length and allowed range of each one. Old families parse liberally and ignore unknown or trailing data for compatibility. Since Linux 5.2, new code and new attributes are parsed strictly (nla_parse() as opposed to nla_parse_deprecated()). Since Linux 4.20, a socket can ask for strict checking of its dump requests with NETLINK_GET_STRICT_CHK. And since Linux 5.8, generic netlink families export their policies (CTRL_CMD_GETPOLICY), so a tool can find out which attributes the running kernel accepts.

A kernel subsystem creates its end with netlink_kernel_create(), passing an input callback. Messages a process sends with sendmsg() are delivered synchronously, in the sender's context, to that callback; for rtnetlink it is rtnetlink_rcv() → netlink_rcv_skb(skb, &rtnetlink_rcv_msg), which splits the buffer into messages, dispatches each by type to a handler registered with rtnl_register_many() — rtnl_newlink() for RTM_NEWLINK, for example — and sends an acknowledgement or error. Replies and events go back through netlink_unicast() to one socket or netlink_broadcast() to every socket subscribed to a multicast group, which is how ip monitor sees route and link changes. Requests for large tables (ip link, ss, conntrack -L) are dumps: netlink_dump() calls the subsystem's dump function, such as rtnl_dump_ifinfo(), once per receive buffer, with a struct netlink_callback holding the position, so a table of any size streams out in bounded chunks as the reader calls recvmsg().

Each user socket is identified by a 32-bit port id. On first use, netlink_autobind() gives a process's first socket the process's thread-group id. A later socket that would collide gets a negative number counted down from a random starting point. The kernel end of every protocol has port id 0. Sockets are kept per protocol in an rhashtable keyed by port id and namespace, which is how netlink_unicast() finds its destination. Permission checks are made per message by the handlers, not when the socket is opened. rtnetlink lets anyone send a GET, but every change requires CAP_NET_ADMIN in the user namespace that owns the network namespace. The check is netlink_net_capable(), which requires the capability both of the process that opened the socket and of the process that sent the message, so passing an open socket to an unprivileged process grants nothing. Generic netlink operations declare the same requirement with GENL_ADMIN_PERM or GENL_UNS_ADMIN_PERM. Dump buffers are sized to avoid high-order allocations. netlink_dump() allocates NLMSG_GOODSIZE (about one page) by default, and up to 32 KB once the reader has shown, by calling recvmsg() with a large buffer, that it can take more. A dump of a large routing table therefore takes many round trips.

Most rtnetlink handlers still run under the global rtnl_lock() mutex, which serializes configuration changes across all namespaces. It is a well-known scalability limit on hosts with thousands of containers. Handlers flagged RTNL_FLAG_DOIT_UNLOCKED avoid it, and since Linux 6.9 so do dumps flagged RTNL_FLAG_DUMP_UNLOCKED; the IPv4 address and route dumps, for example, walk RCU-protected lists without the RTNL. Since Linux 6.12, rtnl_register_many() registers a subsystem's whole handler table in one call and unwinds it on failure. Since Linux 6.13 the kernel has been moving toward per-namespace locking with rtnl_net_lock(), which for now still takes the global RTNL and adds a per-namespace mutex only under CONFIG_DEBUG_NET_SMALL_RTNL. Since Linux 6.14, netdev_lock() adds a per-device instance lock, which drivers that opt in use for their operations.

Rather than allocate a new protocol number for each subsystem, newer interfaces use generic netlink (net/netlink/genetlink.c). A subsystem registers a struct genl_family with genl_register_family(), gets a dynamically assigned family id that user space resolves by name through the nlctrl family, and declares its operations and multicast groups. genl_rcv_msg() dispatches incoming messages to them. Since Linux 6.2 a family can declare split operations (struct genl_split_ops), which give the doit and dumpit forms of one command separate attribute policies and their own pre_doit/post_doit hooks, such as taking a lock on the target object and releasing it afterwards; the code generated from YAML specs uses them. ethtool moved to generic netlink in Linux 5.6 (net/ethtool/netlink.c), and the netdev family (Linux 6.3, net/core/netdev-genl.c) exposes NAPI instances, queues, page pools and XDP features — the interface behind the per-NAPI controls of §5.2 and the devmem binding of §10.2. Newer families are described by YAML specifications in Documentation/netlink/specs/, from which both kernel policy code and user-space libraries in tools/net/ynl/ are generated.

Modern Data Paths

The receive path of §5 allocates a buffer, maps it for DMA, wraps it in an skb, copies the payload to user space and frees everything, once per packet. At 100 to 400 Gbit/s each of those steps becomes a bottleneck. The newest parts of the stack attack them one at a time. page_pool recycles DMA-mapped pages so the allocator and IOMMU drop out of the loop. Memory providers let a receive queue fill buffers from GPU memory or from an io_uring application's own memory, so the copy disappears. AF_XDP skips the stack entirely for applications that want raw frames. And offloads, including kernel TLS and PSP encryption, move whole stages into the NIC. Apart from the classic checksum and segmentation offloads, all of these date from Linux 4.13 or later.

page_pool and netmem

A page_pool (Linux 4.18, net/core/page_pool.c) is a per-RX-queue cache of pages that stay DMA-mapped while they circulate between the driver and the stack. A driver creates one per receive ring with page_pool_create(), passing a struct page_pool_params: the page order, the pool_size, the NUMA node nid, the DMA dev and dma_dir, the owning napi, and flags. With PP_FLAG_DMA_MAP the pool maps each page once, when it is first allocated, and unmaps it only when it finally leaves the pool. With PP_FLAG_DMA_SYNC_DEV the pool also performs the for-device cache sync when a page is recycled, limited to max_len bytes starting at offset — the region the NIC can actually have written. On a non-coherent ARM64 controller this is what keeps the per-packet cache maintenance of §4.3 proportional to the frame rather than to the page. Figure 22-9 shows how pages circulate.

page_pool_alloc_netmems() is the allocation entry point. Its fast path, __page_pool_get_cached(), pops from pool->alloc, an array of PP_ALLOC_CACHE_SIZE (128) entries that only the pool's NAPI context touches, so it needs no lock or atomic. When that array is empty, page_pool_refill_alloc_cache() moves up to PP_ALLOC_CACHE_REFILL (64) entries from pool->ring, a ptr_ring that any CPU can produce into. Only when both are empty does the slow path run: with a memory provider installed, pool->mp_ops->alloc_netmems(); otherwise __page_pool_alloc_netmems_slow(), which allocates a batch with alloc_pages_bulk_node() and DMA-maps each page with page_pool_dma_map(). Drivers that need less than a page per frame use page_pool_dev_alloc_frag(), which hands out pieces of one page and counts the users in the page's pp_ref_count.

Recycling closes the loop. The driver calls skb_mark_for_recycle() on each skb it builds, setting skb->pp_recycle. When the stack frees that skb, skb_pp_recycle() and napi_pp_put_page() recognize the page as a page_pool page — the page itself records its pool — and call page_pool_put_unrefed_netmem(). If page_pool_napi_local() says the free is running in softirq context on the CPU that owns the pool's NAPI instance, the page goes straight back into the alloc cache (page_pool_recycle_in_cache()). Otherwise it goes into the ptr_ring (page_pool_recycle_in_ring()). If the ring is full, page_pool_return_netmem() unmaps the page and frees it to the page allocator. A TCP stream consumed on the CPU that received it therefore recycles nearly every page without touching the allocator or the IOMMU. Under PREEMPT_RT, softirq processing can be preempted, so page_pool_napi_local() always returns false and every return goes through the ring. XDP uses the same pools: a driver registers its RX queue's memory model as MEM_TYPE_PAGE_POOL with xdp_rxq_info_reg_mem_model(), so frames dropped or redirected by XDP are recycled the same way. Because skbs can outlive the driver, page_pool_destroy() does not free a pool while pages are still in flight. It retries from a workqueue (page_pool_release_retry()) until they have all come home. Since Linux 6.8 each pool and its recycling statistics are visible through the netdev netlink family (net/core/page_pool_user.c).

The stack finds a pool page's owner through fields of struct page itself. While a page belongs to a pool, page->pp points at the pool and page->pp_magic holds PP_SIGNATURE, a poison-style constant that no other user of the page stores there. napi_pp_put_page() tests it (netmem_is_pp()) on every skb free, and the page allocator tests it too (page_pool_page_is_pp() in include/linux/mm.h), reporting a bad page if a pool page is freed behind the pool's back. Since Linux 6.16 the spare bits of pp_magic above the signature also hold an index into pool->dma_mapped, an xarray of every page the pool currently has DMA-mapped. That closes a hole in the destroy path just described: a page still held by a socket when the driver unbound used to keep a DMA mapping for a device that might already be gone. Now page_pool_destroy() calls page_pool_scrub(), which walks the xarray and unmaps every outstanding page at once, after a synchronize_net() if a concurrent return might still be syncing one. Pages that come home later are simply freed. Only the struct page_pool itself waits: page_pool_release_retry() runs every second (DEFER_TIME) and logs a "stalled pool shutdown" warning every 60 seconds while pages remain out. The index needs free bits between the signature and the poison offset; on x86-64 and ARM64 CONFIG_ILLEGAL_POINTER_VALUE is 0xdead000000000000, which leaves room, and architectures without room compile the tracking out.

Not every pool belongs to a driver queue. Since Linux 6.9 each CPU also has a system_page_pool (net/core/dev.c, created with PP_FLAG_SYSTEM_POOL and guarded by a nested-BH local lock) for software paths that need pool pages of their own. Generic XDP uses it when the program supports multi-buffer frames: netif_skb_check_for_xdp() calls skb_cow_data_for_xdp() for an skb that is cloned, nonlinear or short of the 256-byte XDP headroom, copying it into fresh pool pages instead of linearizing it. Since Linux 6.14 xdp_build_skb_from_zc() uses the same pool when an AF_XDP zero-copy driver passes a frame up to the stack, because the UMEM frame must go back to user space.

Pages are not the only memory a receive queue can now use. Since Linux 6.9 the network stack passes buffers around as netmem_ref (include/net/netmem.h), an unsigned long that holds either a struct page pointer or, with the low NET_IOV bit set, a pointer to a struct net_iov. A net_iov describes a chunk of memory that has no struct page — a slice of a GPU's dma-buf or of an io_uring area — but carries the same page_pool fields (pp, dma_addr, pp_ref_count), so page_pool and skb frags handle both alike. Since Linux 6.17 those fields are declared once, as struct netmem_desc. A static assertion pins each field to the same offset as its counterpart in struct page, below _refcount, and a net_iov embeds the same descriptor. This is a step toward the memory-management plan of giving each page user its own descriptor instead of overlaying fields on struct page. A driver must opt in to such memory by creating its page_pool with PP_FLAG_ALLOW_UNREADABLE_NETMEM and the queue index, promising that it never touches a buffer through netmem_address(), which returns NULL for a net_iov. Header pools must not set the flag. Since Linux 6.15 such memory comes from a memory provider, a struct memory_provider_ops (include/net/page_pool/memory_provider.h) with alloc_netmems, release_netmem, init, destroy, nl_fill and uninstall. A provider is attached to one RX queue's mp_params (§4.3), and the driver's page_pool for that queue picks it up. The queue must be restarted for that to happen, so drivers that support providers implement the queue-management operations (ndo_queue_mem_alloc, ndo_queue_start, ndo_queue_stop in include/net/netdev_queues.h), which let netdev_rx_queue_restart() rebuild one queue without taking the whole interface down. Since Linux 7.0 the restart goes through netdev_rx_queue_reconfig(), which also applies a changed queue configuration such as the buffer size of §4.3.

Devmem TCP and io_uring zero-copy receive

Both providers depend on header split: the NIC writes each packet's headers into one buffer and its payload into another. Headers land in ordinary host pages that the stack parses as usual; payload lands in provider memory and is attached to the skb as net_iov frags. __net_mp_open_rxq() (net/core/netdev_rx_queue.c) therefore refuses to install a provider unless the driver implements the queue-management operations, header split is on (hds_config is ETHTOOL_TCP_DATA_SPLIT_ENABLED), and the header-split threshold hds_thresh is zero. A non-zero threshold would let the NIC copy a small packet's payload into the header buffer. It also fails with -EEXIST if an XDP program is attached to the device, because XDP expects to read the whole frame, or if the queue already has a provider. It fails with -EBUSY if an AF_XDP socket owns the queue. A requested buffer size (rx_page_size) needs a driver that advertises QCFG_RX_PAGE_SIZE (§4.3). The function then stores the provider in the queue's mp_params and restarts the queue with it. The checks also run in reverse. While any queue has a provider, the kernel refuses to install an XDP program (dev_xdp_install()), turn header split off or raise hds_thresh through ethtool, bind an AF_XDP zero-copy socket, or shrink the channel count below the highest provider queue. The flow must be steered to the provider's queue, typically with an ntuple filter set through ethtool.

Devmem TCP (Linux 6.12, net/core/devmem.c) receives TCP payload straight into device memory, typically a GPU buffer exported as a dma-buf. User space binds the dma-buf to an RX queue with the netdev netlink bind-rx command. netdev_nl_bind_rx_doit() maps the dma-buf for the NIC (net_devmem_bind_dmabuf()), carves it into net_iov chunks managed by a gen_pool, and installs dmabuf_devmem_ops on the queue with net_devmem_bind_dmabuf_to_queue(). The CPU cannot read those payload bytes, so an skb that carries them has skb->unreadable set. Helpers that would touch the payload check skb_frags_readable() and fail with -EFAULT. Software checksum verification therefore fails, so the NIC must verify checksums. Loopback cannot work, and tcpdump and BPF see only the headers. The application calls recvmsg() with MSG_SOCK_DEVMEM. tcp_recvmsg_dmabuf() returns, instead of data, control messages: SCM_DEVMEM_DMABUF for each fragment (offset in the dma-buf, length and a token), or SCM_DEVMEM_LINEAR for bytes that landed in host memory. When the GPU has consumed the data, the application hands the tokens back with setsockopt(SO_DEVMEM_DONTNEED) and the chunks return to the page_pool. The socket keeps the outstanding tokens in its sk_user_frags xarray. One SO_DEVMEM_DONTNEED call takes at most 128 struct dmabuf_token ranges, covering at most 1024 frags. When the socket is destroyed, tcp_release_user_frags() returns whatever the application never released. A binding lives as long as the netlink socket that created it. When that socket closes, netdev_nl_sock_priv_destroy() unbinds the dma-buf and restarts the queues without the provider. Since Linux 6.16 a bind-tx command lets a dma-buf be the source of MSG_ZEROCOPY sends. The application passes the binding's id in an SCM_DEVMEM_DMABUF control message and puts offsets into the dma-buf, not pointers, in its iov_base fields. tcp_sendmsg_locked() looks the binding up with net_devmem_get_binding(), which fails with -ENODEV unless the socket's route leaves through the bound device, and builds the skb from the binding's net_iovs. Because those addresses are valid only on that device, validate_xmit_skb() drops such an skb if a route change sends it elsewhere (§7.4).

io_uring zero-copy receive (zcrx, Linux 6.15, io_uring/zcrx.c) applies the same mechanism to ordinary user memory, which the CPU can read. Chapter 24 places it among io_uring's zero-copy features; the networking side works like this. The application registers an interface queue with IORING_REGISTER_ZCRX_IFQ (io_register_zcrx_ifq()), giving a device, an RX queue index, a memory area (user pages, or a dma-buf with IORING_ZCRX_AREA_DMABUF) and a refill ring shared with the kernel. The kernel installs io_uring_pp_zc_ops as the queue's memory provider. An IORING_OP_RECV_ZC request on a TCP socket (io_zcrx_recv()) then posts completions that carry an io_uring_zcrx_cqe holding the offset of the data in the area, which is why the ring must use 32-byte or mixed-size CQEs. When the application is done with a buffer, it writes a struct io_uring_zcrx_rqe (offset and length) to the refill ring. io_pp_zc_alloc_netmems() drains that ring, through io_zcrx_ring_refill(), when the page_pool needs buffers. Data moves from NIC to application without a copy and without a system call per buffer. Registration requires CAP_NET_ADMIN and a ring created with IORING_SETUP_DEFER_TASKRUN, so completions are posted only in the application's own task. Not every byte arrives in the area. Payload left in the skb's linear part, or in frags from ordinary pages (for example, packets that reached the queue before header split or steering took effect), is copied into a free area buffer by io_zcrx_copy_chunk(), so the application always finds its data in the area. Frags from another queue's provider fail with -EFAULT. Since Linux 6.19 IORING_REGISTER_ZCRX_CTRL adds two operations. ZCRX_CTRL_EXPORT wraps an interface queue in a file descriptor that another ring attaches with ZCRX_REG_IMPORT, so several rings, typically one per worker thread, can share one hardware queue. ZCRX_CTRL_FLUSH_RQ drains the refill ring from process context when the page_pool is not asking for buffers. Since Linux 7.0 the registration can ask for buffers larger than a page (rx_buf_len, a power of two, advertised by ZCRX_FEATURE_RX_PAGE_SIZE). The value reaches the driver as the queue's rx_page_size (§4.3).

AF_XDP sockets

XDP (Chapter 23) runs a BPF program on the raw frame before any skb exists (§5.4). Its XDP_REDIRECT action can send the frame to another device, to another CPU, or — through an XSKMAP — to an AF_XDP socket (Linux 4.18, net/xdp/xsk.c). AF_XDP gives user space raw frames with the kernel stack bypassed entirely, for packet processors that would otherwise use a user-space driver such as DPDK while keeping the NIC under the kernel's control.

The application creates a socket with socket(AF_XDP, SOCK_RAW, 0) (xsk_create()) and registers a UMEM with setsockopt(XDP_UMEM_REG): a user memory area divided into equal frames. Four single-producer, single-consumer rings, sized with setsockopt() and mapped with mmap(), carry frame addresses between the two sides. The fill ring (XDP_UMEM_FILL_RING) gives the kernel empty frames to receive into, and the RX ring (XDP_RX_RING) returns filled ones. The TX ring (XDP_TX_RING) submits frames to send, and the completion ring (XDP_UMEM_COMPLETION_RING) returns them once sent. bind() (xsk_bind()) attaches the socket to one queue of one device, in XDP_ZEROCOPY or XDP_COPY mode. An XDP program on that device then redirects chosen frames into the socket's XSKMAP slot, and __xsk_map_redirect() → xsk_rcv() delivers them.

In zero-copy mode the driver has filled its RX ring with UMEM frames taken from the fill ring, through an xsk_buff_pool (registered as MEM_TYPE_XSK_BUFF_POOL). The packet is therefore already in user memory, and xsk_rcv_zc() only posts a descriptor on the RX ring. On transmit the driver pulls descriptors directly with xsk_tx_peek_desc(), and ndo_xsk_wakeup kicks it when user space has queued work. In copy mode, which works with any driver, __xsk_rcv() copies the frame into a UMEM frame, and xsk_generic_xmit() builds an skb for each TX descriptor. With XDP_USE_NEED_WAKEUP the kernel tells the application, through a ring flag, whether a system call is needed to make progress at all, so a busy application can run without system calls.

The basic model has grown several extensions. With XDP_SHARED_UMEM a second socket binds to an existing socket's UMEM. On the same queue the two share the fill and completion rings; on another queue or device the new socket brings fill and completion rings of its own. With XDP_UMEM_UNALIGNED_CHUNK_FLAG (Linux 5.4) a frame need not start on a chunk boundary. A descriptor address then carries an offset in its top 16 bits (XSK_UNALIGNED_BUF_OFFSET_SHIFT is 48), so an application can place packets anywhere in huge-page-backed memory. Since Linux 6.6 a socket bound with XDP_USE_SG handles frames larger than one chunk. Each piece takes its own descriptor, and every descriptor but the last carries XDP_PKT_CONTD, in both directions. Since Linux 6.8 the application can reserve tx_metadata_len bytes in front of each TX frame for a struct xsk_tx_metadata and set XDP_TX_METADATA in the descriptor. Since 6.11 it must also set XDP_UMEM_TX_METADATA_LEN at UMEM registration. The metadata can request:

  • a hardware TX timestamp (XDP_TXMD_FLAGS_TIMESTAMP), returned through the completion;
  • a checksum offload (XDP_TXMD_FLAGS_CHECKSUM). In copy mode this becomes a CHECKSUM_PARTIAL skb, or a software checksum with XDP_UMEM_TX_SW_CSUM, which exists mainly for testing;
  • since 6.15, a launch time against the NIC's PTP clock (XDP_TXMD_FLAGS_LAUNCH_TIME).

The receive-side counterpart, hardware hints that the XDP program reads through kfuncs, belongs to Chapter 23. In copy mode, XDP_MAX_TX_SKB_BUDGET (Linux 6.17) changes how many descriptors one sendmsg() turns into skbs, from the default of 32 up to the TX ring size. getsockopt(XDP_STATISTICS) reports packets dropped because the RX ring was full or the fill ring empty, and invalid descriptors. The sockets also support the busy polling of §5.2. AF_XDP zero-copy and memory providers exclude each other: neither can claim a queue that the other is using.

The older AF_PACKET mmap interface (PACKET_RX_RING, TPACKET_V3, with PACKET_FANOUT to spread a capture across sockets) remains the tool for capture: its tpacket_rcv() runs as a tap (§5.4) on an existing skb, sees every packet including transmitted ones, and does not take packets away from the stack.

Offloads and kernel TLS

Each device advertises what its hardware can do in dev->hw_features. The user's requests (ethtool -K) are kept in wanted_features, and what is currently enabled is dev->features. netdev_update_features() recomputes the enabled set through the driver's ndo_fix_features and applies it with ndo_set_features. The NETIF_F_* bits (include/linux/netdev_features.h) fall into a few groups, most of which earlier sections have already met:

  • Checksums — NETIF_F_HW_CSUM, NETIF_F_IP_CSUM and NETIF_F_IPV6_CSUM on transmit (CHECKSUM_PARTIAL), NETIF_F_RXCSUM on receive (§3.3).
  • Segmentation and coalescing — NETIF_F_TSO and friends and GSO on transmit (§7.4), and on receive NETIF_F_GRO_HW (hardware GRO that preserves segment boundaries) and the older NETIF_F_LRO. LRO merges packets lossily, so netif_disable_lro() turns it off when a device forwards or is bridged.
  • Steering and filtering — NETIF_F_RXHASH supplies skb->hash for RPS and RFS, and NETIF_F_NTUPLE enables exact-match filters (ethtool -N) and accelerated RFS (ndo_rx_flow_steer, §5.3), which devmem and zcrx rely on to steer flows.
  • Crypto — NETIF_F_HW_TLS_TX and NETIF_F_HW_TLS_RX for kernel TLS, below. NETIF_F_HW_ESP covers IPsec, either as crypto offload, where the NIC only encrypts and decrypts ESP, or, since Linux 6.2, as packet offload (XFRM_DEV_OFFLOAD_PACKET), where it also performs encapsulation and policy and state lookup. NETIF_F_HW_MACSEC covers MACsec. PSP, below, has no feature bit; a capable device registers a struct psp_dev in dev->psp_dev.

Checksums are also where the two architectures diverge in software. On x86-64, csum_partial() (arch/x86/lib/csum-partial_64.c) adds 64-bit words with carry through inline adc assembly, in two 40-byte streams in parallel for instruction-level parallelism. The copy-and-checksum used when copying from user space is arch/x86/lib/csum-copy_64.S, and ip_fast_csum() for the IP header is inline assembly in arch/x86/include/asm/checksum_64.h. x86 falls back to the generic C code (CONFIG_GENERIC_CSUM) only under KASAN or KMSAN. ARM64 always selects GENERIC_CSUM, so csum_partial() is the C version in lib/checksum.c. That version calls an architecture do_csum(), which ARM64 overrides in arch/arm64/lib/csum.c with a loop that loads 64 bytes per iteration as 128-bit quantities and folds the carries by adding each value to its rotated halves, so the compiler need not move the carry flag into a register. The same file provides csum_ipv6_magic(), and ip_fast_csum() is in arch/arm64/include/asm/checksum.h. With NETIF_F_RXCSUM and CHECKSUM_PARTIAL offload, both architectures run these routines mainly for headers and for devices without offload.

Kernel TLS (kTLS, net/tls/) moves TLS record encryption under the socket API: transmit since Linux 4.13, receive since 4.17. The handshake stays in user space, for example in OpenSSL. Afterwards the application calls setsockopt(TCP_ULP, "tls"). tls_init() attaches a struct tls_context as the socket's upper-layer protocol (§2.3). Then setsockopt(SOL_TLS, TLS_TX, ...) and TLS_RX hand over the negotiated keys and sequence numbers, and update_sk_prot() points sk->sk_prot at the matching entry of tls_prots[][][]. From then on write() and sendfile() produce TLS records. tls_sw_sendmsg() encrypts with the kernel crypto API. tls_device_sendmsg() (Linux 4.18) leaves the records in plaintext and lets a NETIF_F_HW_TLS_TX NIC encrypt them inline as it segments, keeping sendfile() zero-copy. On receive, tls_sw_recvmsg() uses a stream parser (net/tls/tls_strp.c) to find record boundaries in the TCP stream, and decrypts each record unless the NIC already did (tls_device_decrypted()). Each direction's configuration is one of TLS_BASE (no keys yet), TLS_SW, TLS_HW (device offload) or TLS_HW_RECORD (a NIC that terminates TCP and TLS itself, net/tls/tls_toe.c). Device transmit offload keeps a software safety net. The socket's sk_validate_xmit_skb hook (§7.4) is tls_validate_xmit_skb(), and when a route change sends a record out of a device other than the one holding the crypto state, it encrypts the skb in software (tls_sw_fallback(), net/tls/tls_device_fallback.c). When that device goes down, the hook switches to software for every packet. Since Linux 6.14 a TLS 1.3 socket can change keys. A second setsockopt(TLS_TX) or TLS_RX with the same version and cipher installs new keys; on TLS 1.2 it fails with -EBUSY. When a KeyUpdate handshake message arrives, the receive side stops behind it, and recvmsg() returns -EKEYEXPIRED until the application has installed the new receive key. Rekeying is implemented in the software path. Two further options trade safety for speed. TLS_TX_ZEROCOPY_RO (Linux 5.19) lets device offload send file pages without copying, if the application promises not to modify the file meanwhile. TLS_RX_EXPECT_NO_PAD (Linux 6.0) lets TLS 1.3 decrypt straight into the user buffer by assuming the peer adds no record padding, and decrypts again if it did. In-kernel TLS users such as NFS over TLS obtain their handshake from a user-space agent through the handshake netlink family (net/handshake/, Linux 6.4).

PSP (Linux 6.18, net/psp/), a transport encryption protocol defined at Google, takes the opposite approach. It exists only as a device offload, with no software implementation, and only for TCP. Each packet is encapsulated in UDP (port 1000 by default, PSP_DEFAULT_UDP_PORT) behind a PSP header carrying a 32-bit security parameter index (SPI). It is either encrypted with AES-GCM or only authenticated with AES-GMAC, at 128 or 256 bits (enum psp_version). The design suits servers with very many connections. The NIC never stores per-connection receive keys; it derives each one from the SPI and a device key that cannot be read out of the hardware, so its receive state is O(1). A management daemon rotates the device key, usually daily, with the key-rotate command. The previous key stays in the NIC, and a phase bit in the header says which generation encrypted a packet, so connections must be re-established before the next rotation. Configuration goes through the psp generic netlink family (net/psp/psp_nl.c). A driver registers its struct psp_dev and operations with psp_dev_create(); mlx5 is the first, and netdevsim implements PSP for testing. Key exchange is left to a higher layer, for example a TLS handshake that announces PSP support. For a connected TCP socket, user space first issues rx-assoc, which allocates an SPI and receive key from the NIC to send to the peer, then tx-assoc with the peer's key. After tx-assoc the socket accepts only authenticated data. Plaintext ACKs, FINs and RSTs are still let through until the first PSP-authenticated packet arrives, and after that everything unauthenticated is dropped. On receive the driver decrypts and calls psp_dev_rcv(). It strips the UDP and PSP headers, fixes up the IP header, and records the SPI, device and key generation in an SKB_EXT_PSP skb extension (§3), which TCP's receive path compares against the socket's association (psp_sk_rx_policy_check(), called from tcp_v4_do_rcv()). On transmit the socket's sk_validate_xmit_skb hook is psp_validate_xmit(). Unlike the kTLS hook, it drops a packet routed through any device other than the one holding the association (SKB_DROP_REASON_PSP_OUTPUT), because nothing else could encrypt it. Otherwise the driver inserts the UDP and PSP headers with psp_dev_encapsulate(), passes the key's identifier to the NIC in the TX descriptor, and the NIC encrypts.

Summary

This chapter followed data between an application and the wire. On the way down, a system call enters the socket layer through sockfs and struct proto_ops, and the protocol (struct proto) copies the data into sk_buffs, charging them to the socket's send buffer. TCP decides when each segment may leave: the congestion window, the receiver's window, pacing by earliest departure time and TCP Small Queues all gate tcp_write_xmit(). IP routes the segment through the dst_entry cached in the socket, netfilter inspects it at LOCAL_OUT and POST_ROUTING, and the neighbour layer prepends a link-layer header from its cached hardware header. The core device layer then picks a TX queue with XPS, passes the packet through a qdisc and BQL, and hands it to the driver's ndo_start_xmit, usually as one large GSO packet that the NIC segments. TX completion frees the buffers and, through TSQ and BQL, clocks the next burst out of the socket.

On the way up, an interrupt schedules NAPI, and net_rx_action() polls the driver in softirq context under a budget, or a NAPI thread or a busy-polling application does so instead. An XDP program can drop, redirect or return a frame before any sk_buff exists. GRO merges consecutive segments of a flow, and RPS and RFS move the rest of the work to the CPU that will consume the data. __netif_receive_skb_core() runs the taps, tc ingress and any rx_handler, such as a bridge or bond, and dispatches on the protocol. ip_rcv() validates the header and runs PRE_ROUTING, early demux or a FIB lookup attaches a dst_entry, and local delivery passes LOCAL_IN to the inet protocol table. An RCU lookup in the socket hash tables finds one struct sock. There the segment joins the receive queue, or the backlog if a task owns the socket, and sk_data_ready() wakes the reader.

Beside both paths runs the control plane. User space configures the stack over netlink: rtnetlink for links, addresses, routes and neighbours, and generic netlink families such as ethtool and netdev, whose YNL specifications generate both kernel and user-space code. Writers are serialized by the RTNL mutex, now complemented by per-device instance locks, and publish new objects with RCU so that packets in flight never wait for them. Routes live in the fib_trie behind policy rules and point to nexthop objects. The neighbour table resolves next hops through its state machine, and netfilter hooks carry nf_tables, connection tracking, NAT and the flowtables that let established flows bypass most of the rule set.

A few design principles explain most of the code. Batch everything: NAPI polls many packets per interrupt, GRO and GSO turn many packets into one trip through the stack, netif_receive_skb_list() and ip_list_rcv() pass lists, qdiscs dequeue in bursts, and xmit_more lets drivers ring the doorbell once per batch. Keep a flow on one CPU: multiqueue NICs, RSS, RPS, RFS, XPS and the page_pool's direct recycling all aim to keep a flow's packets, socket and buffers in one CPU's caches. Bound every queue: socket buffer limits, the NAPI budget, the backlog limit, qdisc limits, BQL and TSQ each stop one layer from hiding latency in a buffer that another layer cannot see. Make the common case free: static keys remove netfilter, RPS and the egress hooks when they are not configured, the TCP fast path handles in-order data with a header prediction test, and the route lookup is cached in the socket.

The stack has also become programmable and pluggable at nearly every layer. Address families, protocols, qdiscs, congestion-control algorithms, netfilter rule engines and memory providers are all registered operation tables. BPF programs attach at XDP, tc, socket, cgroup and congestion-control hooks (Chapter 23), and every object above belongs to a network namespace (Chapter 25). The newest work removes copies and moves whole stages into the NIC: page_pool keeps buffers mapped and abstracts them as netmem, memory providers let payload land in GPU or application memory, AF_XDP hands raw frames to user space, and kernel TLS, IPsec packet offload and PSP let the NIC encrypt and decrypt. When something goes wrong, per-CPU softnet_stat, the MIB counters, sock_diag and the drop reasons reported by the skb:kfree_skb tracepoint say where.
