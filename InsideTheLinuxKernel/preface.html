Preface

A book about Linux 7.0.12, with x86_64 and ARM64 as its reference architectures — what it covers, how it is organized, and the conventions it follows.

This book describes the Linux kernel as it is today: Linux 7.0.12, traced through its source on the two architectures that dominate contemporary computing, x86_64 (AMD64) and ARM64 (AArch64). Since the 2.6 series the kernel has been transformed. Whole subsystems have been rewritten, security has become a pervasive design constraint, and the target hardware has moved from 32-bit PCs to 64-bit, many-core, NUMA servers, phones, and embedded SoCs.

About This Book

The book explains how the Linux kernel works from the inside. It is not a manual for configuring a system, nor a reference to the system-call API. It is an explanation of the mechanisms—the data structures, algorithms, locking rules, and design decisions—by which the kernel manages memory, schedules processes, handles interrupts, serves files, and turns programs into running tasks. Each mechanism is traced through the 7.0.12 source on both architectures at once, so that the reader can see which parts of the kernel are generic and which are shaped by the machine beneath them.

Much of the material covers mechanisms that did not exist in the 2.6 series: five-level page tables, folios, control groups and namespaces, the EEVDF fair scheduler and sched_ext, pervasive RCU, extent-based and copy-on-write filesystems, the block multi-queue layer, io_uring, address-space layout randomization, stacked Linux Security Modules, seccomp, Landlock, module signing, eBPF and BTF, and livepatching. The book presents them on their own terms, building from memory addressing and processes up through the subsystems that make a running system.

Where a mechanism replaced an older one, a short Version history note or a comparison table records what Linux 2.6 did and which release introduced the change. That history has practical value: it explains identifiers that survive in older drivers, out-of-tree code, documentation, and mailing-list discussions, and it shows how far back a backport has to reach.

The Audience for This Book

This book is written for anyone who wants to understand how a real, production operating-system kernel is built. Its readers include systems programmers who must reason about how their code interacts with the kernel; students of operating systems who want to see the concepts of their courses embodied in a kernel that runs on billions of machines; kernel and driver developers who need a map of the territory before diving into the source; and simply the curious, who want to know what happens between pressing the power button and reaching a shell prompt.

The book assumes that its reader is comfortable reading C, since the kernel is written in C (with a modest amount of architecture-specific assembly), and that they have met the basic vocabulary of operating systems—processes, files, virtual memory, interrupts—at the level of an undergraduate course or equivalent experience. It does not assume prior knowledge of the Linux kernel itself, nor deep expertise in either of the reference architectures; the hardware background each topic needs is introduced where it is first required. What the book cannot do is teach C or the fundamentals of computer architecture from scratch; readers who want to strengthen that foundation will find suggestions in the §6 (“Background Information”) section below.

Organization of the Material

The book is organized as a sequence of chapters that build upon one another, grouped into broad thematic parts, followed by two appendices. It begins with the foundations: the way the processor and kernel handle memory addresses, the representation of processes, the handling of interrupts and exceptions, kernel synchronization, and timing. It then turns to memory management—the page allocator, the slab allocator, non-contiguous memory, the process address space, and the page cache—which is the heart of the kernel and the substrate on which everything else rests. From there it covers the virtual filesystem and the concrete filesystem and block I/O layers that give processes durable storage, and then the several forms of interprocess communication. It reaches program execution—how an executable file becomes a running, secured process—which draws on nearly every subsystem that came before. Part III ends with two subsystems that cut across the whole machine: power management, from system suspend and runtime PM to CPU frequency and idle states, and networking, from the socket layer through sk_buff and the protocol stack to the device queues. The book then closes with a group of advanced topics that show where the modern kernel is going: the eBPF in-kernel virtual machine, the io_uring asynchronous-I/O interface, the namespaces and control groups that underpin containers, the new support for writing kernel code in Rust, the security infrastructure of cryptography, keys, integrity, and audit, KVM virtualization, and the tracing and diagnostic facilities through which the kernel reports on itself.

Two appendices stand slightly apart from this progression because they describe the kernel from its edges rather than its interior. Appendix A follows the system from power-on to the first user process—firmware, boot loaders, decompression, and the architecture startup code that reaches start_kernel. Appendix B describes loadable kernel modules—how code is linked into a running kernel and, increasingly, how modules carry far more than device drivers. The chapters are meant to be read in order on a first pass, since later ones freely use concepts established earlier, but each is also written to serve as a reference to its subsystem once the whole has been absorbed.

Level of Description

This book describes the kernel at the level of its data structures and algorithms. For each subsystem it explains what problem the kernel is solving, the structures it uses to represent the problem, the algorithms that operate on those structures, and—crucially—the reasoning behind the design, including the trade-offs that led the kernel's developers to one approach rather than another. It names the real functions, structures, and macros of the Linux 7.0.12 source and points to the files that contain them, so that a reader can move from the book's explanation to the code itself. It is not, however, a line-by-line commentary on the source: the kernel is far too large for that, and a faithful transcription would obscure the very structure the book aims to reveal. The goal is understanding that outlives any single release, anchored in—but not drowned by—the details of one.

Because this book targets two architectures, it takes care to separate the architecture-independent core of each subsystem from its architecture-specific realization. Where the kernel's generic code is what matters, the book describes that; where a mechanism is inescapably tied to the hardware—page-table formats, exception entry, memory barriers, the boot sequence—it shows how both x86_64 and ARM64 implement it, and what the differences reveal. Seeing the same idea expressed twice, in two processor idioms, is one of the most instructive things about studying a portable kernel, and this book uses that comparison deliberately throughout.

Overview of the Book

The chapters and appendices, in order, are as follows.

  • Chapter 1, Introduction, sets the scene: the history and philosophy of Linux, the architecture of the kernel, the operating-system concepts the book assumes, and an overview of the subsystems and how they fit together.
  • Chapter 2, Memory Addressing, explains how the processor and kernel translate addresses—segmentation's vestigial role, multi-level paging up to five levels, the TLB, and the kernel's own address space—on x86_64 and ARM64.
  • Chapter 3, Processes, describes the process descriptor, how processes and threads are created and destroyed, context switching, and the namespaces that virtualize a process's view of the system.
  • Chapter 4, Interrupts and Exceptions, covers how the kernel responds to asynchronous events from hardware and synchronous faults from software, and the deferred-work mechanisms that keep interrupt handling short.
  • Chapter 5, Kernel Synchronization, examines the primitives—atomic operations, spinlocks, mutexes, RCU, and memory barriers—by which the kernel coordinates concurrent access on multiprocessor systems.
  • Chapter 6, Timing Measurements, describes how the kernel keeps time, schedules deferred work, and maintains the system clock across a range of timer hardware.
  • Chapter 7, Process Scheduling, explains how the kernel decides which task runs next, the scheduling classes, and how load is balanced across processors.
  • Chapter 8, Memory Management, presents the page allocator, the slab allocator, and the machinery that manages the kernel's own use of physical memory.
  • Chapter 9, Process Address Space, describes how each process's virtual memory is represented, how regions are mapped, and how page faults are resolved.
  • Chapter 10, System Calls, traces the boundary between user space and the kernel and the mechanics of entering and leaving it.
  • Chapter 11, Signals, covers the kernel's oldest interprocess notification mechanism and how signals are generated, delivered, and handled.
  • Chapter 12, The Virtual Filesystem, explains the abstraction layer that lets a single set of system calls operate on many different filesystems.
  • Chapter 13, I/O Architecture and Device Drivers, describes how the kernel talks to hardware devices and the driver model that organizes them.
  • Chapter 14, Block Device Drivers, covers the path from a filesystem request to a physical disk, including the multi-queue block layer.
  • Chapter 15, The Page Cache, explains how the kernel caches file data in memory to make I/O fast.
  • Chapter 16, Accessing Files, follows read and write operations through the kernel, from the system call to the storage device.
  • Chapter 17, Page Frame Reclaiming, describes how the kernel reclaims memory under pressure and the policies that decide what to evict.
  • Chapter 18, The Ext4 Filesystem, examines one concrete on-disk filesystem in depth and how it realizes the VFS abstractions.
  • Chapter 19, Process Communication, surveys pipes, System V and POSIX IPC, futexes, and the file-descriptor-based notification mechanisms.
  • Chapter 20, Program Execution, explains how an executable file becomes a running process—formats, the exec pipeline, memory layout, dynamic linking, credentials, and the security frameworks that constrain it.
  • Chapter 21, Power Management, explains how the kernel saves energy at every scale—suspending and hibernating the whole system, powering devices and power domains down at runtime, and scaling CPU frequency and idle states under the guidance of the Energy Model and thermal management.
  • Chapter 22, Networking, explains how Linux carries data between applications and network hardware: the socket layer and its proto_ops/proto split, the sk_buff, network devices and NAPI, GRO and receive steering, the IP layer, qdiscs and the transmit path, TCP and UDP, netfilter and netlink, and the page_pool, devmem and AF_XDP data paths.
  • Chapter 23, The eBPF Subsystem, describes the in-kernel virtual machine that lets user-supplied programs run safely at kernel hooks—the verifier, maps, program types, and the JIT—turning the kernel into a programmable platform.
  • Chapter 24, io_uring, presents the shared-memory ring interface for asynchronous I/O, how submission and completion queues eliminate per-operation system calls, and the registration and polling features that make it fast.
  • Chapter 25, Containers, Namespaces, and Cgroups, explains the two kernel mechanisms—namespaces for isolation and control groups for resource limits—that together let a single kernel present many isolated views of the system.
  • Chapter 26, Rust in the Kernel, covers the ability to write kernel code in Rust—the build integration, the safe/unsafe boundary and the kernel crate, the ownership and locking abstractions, and the real drivers already merged.
  • Chapter 27, Kernel Security Infrastructure, describes the layers beyond credentials and the LSM framework: the major security modules, the crypto API, keys and keyrings, integrity measurement and verity, audit, kernel lockdown, and the hardening that protects the kernel from its own bugs on x86_64 and ARM64.
  • Chapter 28, Virtualization: KVM, explains how Linux becomes a hypervisor: the /dev/kvm file-descriptor API, the vCPU run loops on x86 (VMX, SVM) and ARM64 (VHE, nVHE, pKVM), memslots and second-stage page tables, guest_memfd and confidential computing, interrupt and timer virtualization, and the virtio, vhost, and VFIO device paths.
  • Chapter 29, Tracing, Debugging, and Kernel Diagnostics, explains how the kernel reports on itself, from printk, oops and panic handling and the lockup detectors to ftrace's live code patching, tracepoints, kprobes and uprobes, perf_events, the latency tracers, runtime verification and kgdb, on both x86_64 and ARM64.
  • Appendix A, System Startup, follows the machine from power-on through firmware, boot loader, and kernel initialization to the first user process.
  • Appendix B, Kernel Modules, describes how loadable modules extend a running kernel, from linking and signing to their modern roles carrying BTF and livepatches.
  • Source Trails closes the book with a chapter-by-chapter guide to the Linux 7.0.12 source files worth reading alongside the text.

Background Information

To get the most from this book, a reader should be fluent in the C programming language, since every structure and function discussed is written in it, and should recognize a little assembly language, which appears at the boundaries where the kernel meets the hardware. A grounding in operating-system concepts—what a process is, what virtual memory does, how a filesystem presents files, why concurrency requires synchronization—will make the discussion far easier to follow; readers new to these ideas will find Chapter 1 a useful orientation but may wish to supplement it with an introductory operating-systems text.

Some familiarity with computer architecture is also valuable, particularly the notions of privilege levels, memory-management units, caches, and interrupts. The book introduces the architecture-specific details of x86_64 and ARM64 as they become relevant, but readers who want the full picture of either processor will find the vendors' architecture manuals—Intel's and AMD's for x86_64, Arm's Architecture Reference Manual for AArch64—to be the authoritative references. Above all, the ultimate companion to this book is the Linux source code itself, which is freely available and which the book everywhere invites the reader to consult.

Conventions in This Book

The book follows a small set of typographic conventions. Italic is used for emphasis and to introduce new terms; important terms also appear as key terms where they are first defined. A constant-width font marks the names of functions, variables, structures, and macros drawn from the source—for example task_struct, kmalloc, or MODULE_LICENSE—as well as literal command lines and code. File and directory paths appear in a distinct style, such as kernel/sched/core.c or include/linux/mm.h, always relative to the root of the kernel source tree.

Figures and tables are numbered per chapter (Figure 2-1, Table 8-3, and so on), and each is referred to from the surrounding text. Set-off notes call attention to subtleties, cross-architecture differences, and points that are easy to misunderstand. One convention deserves particular emphasis, because the whole book depends on it: every reference to the source code names a specific, fixed version of the kernel.

All source paths and macro names in this book refer to the Linux 7.0.12 tree at https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git/tree/?h=v7.0.12. Where the kernel uses runtime variables instead of preprocessor constants, the text calls that out explicitly.

Pinning every citation to Linux 7.0.12 means that a reader can always follow a reference from the page to the exact line of code it describes, in a tree that will not shift underneath them. The kernel moves quickly, and details will change in later releases; but the structures and algorithms this book explains, and the reasoning behind them, are stable enough that understanding them for 7.0.12 is understanding them for the kernels that follow. With the conventions established, we can begin—Chapter 1 opens with the question of what, exactly, the Linux kernel is.
